## 口径修正（由复算与评审实证得出，属立锚时写错、执行中改正）

**修正一：锚点不丢做不到字面口径。**立锚时写的是「改后锚点集合 ⊇ 改前集合」。实测发现
**Docusaurus 不为 H1 生成锚点**（`build` 出来的页面里 `<h1>` 没有 `id` 属性）。原文里有 6 个锚点挂在**章节**标题上
（`#background`、`#core`、`#actions`、`#plan`、`#review`、`#pitfalls`），拆章后这些「章节」变成了**整页**，
锚点没有可挂载的 H2 —— 故这 6 个 ID 退役，其余（原 H2 / H3 / H4）一个不丢。

至此口径应表述为「**除 6 个章节级锚点外，其余锚点一个不丢**」，而不是原文的「所有小节级锚点一个不丢」——
退役的 6 个本身就是 H2，原措辞自相矛盾（评审 P1）。

**修正二：宽表口径与「不改表格判据」冲突。** `DIAGNOSIS` R5 要求「不能拆的压到 3 列以内」，
验收 8 只要求「≤4 列」。复评时按「非目标第 3 条：不改任何一张表的判据」恢复了两张复盘表的原文列数
（判断准确率表 6 列、季度热力图 5 列），因此最宽表回到 6 列、与原文持平。**真正的口径是**：
消除的是「把整段说明塞进单元格」的宽表（八个误用表 5 列密文 → 8 个小节）；
**给读者填写的空表，列数必须与原文一致，不参与压缩**。这两类表的用途不同，不能套同一条规则。

**修正三：引用密度的分母。**密度 = 《书名》数 ÷ 正文字符数 × 1000，其中「正文」**排除**各篇「本篇出处」小节
与 `appendix.md`（后者的本职就是列书）。不排除时 `appendix.md` 单篇 49 处《》会把读数抬到 2.1‰。
该口径写死在 `an-metrics.js` 头部注释里。

## 风险与回滚

- 最坏会怎样：一是站内锚点 ID 在迁移中丢失或改名，导致文内跳转与跨文件引用集体失效；
  二是**旧 URL 的章节级深链失效**。URL 本身不变（`index.md` 顶在原路径上），但
  `.../critical-thinking-playbook#actions` 这类深链会落到导览页，而导览页已不含他要找的内容——
  **不是「打不开」，是「内容已经搬走了」**（评审 P1 指出的原措辞错误，此处更正）。
  这 6 个旧深链的正确新地址，其中 5 个与新建子页同名，可直接改写：
  `#background`→`.../critical-thinking-playbook/background`、`#actions`→`/actions`、`#plan`→`/plan`、
  `#review`→`/review`、`#pitfalls`→`/pitfalls`；`#core` 的内容落在 `.../foundations`。
  指向**小节**的深链（如 `.../critical-thinking-playbook#tool-info`）正确新地址是
  `.../critical-thinking-playbook/checks#tool-info`。
- **站内已核对干净**：新目录内 106 条链接（其中带锚点 44 条）全部命中；站内其他文件指向本目录的 2 条
  （`thinking/index.md`、`thinking/criticalthinking.md`）均已改到新索引页；直接指向 6 个退役 ID 的链接为 **0 条**。
- **站外深链无法统计——这是本次已声明并接受的代价。**
- 怎么退回去：删除新目录并 `git checkout -- docs/selfdevelop/cognition/thinking/`
  （原单篇文件在 git 历史里完整可取，`d8f6d4c2`），`PROJECT.md` 与 `DECISIONS.md` 的改动各回退一行即可。

### 构建终轮的记录（连续四轮欠账，本次还清）

第一次重跑失败，报 `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] count=891 target=build/__server`。
定位到 `@docusaurus/core/lib/commands/build/buildLocale.js:94`，执行顺序是
`clearPath(outDir)` → 编译 → `executeSSG` → **`cleanupServerBundle`（删 `build/__server`）** → `postBuild()` → 断链检查。
**`sitemap.xml` 由 sitemap 插件在 `postBuild` 阶段写**，所以 `cleanupServerBundle` 被拦下的产物**没有 sitemap**，
静态页却已齐全——**产物看着成功，`exit 0` 也拿不到**。这是本次最容易误判的一处。

对策是用 Docusaurus 官方开关 `DOCUSAURUS_KEEP_SERVER_BUNDLE=true` 跳过该步
（**不是绕守卫，是让这次删除不必发生**），构建输出 `[SUCCESS] Generated static files in "build"`；
随后把 `build/__server` 用**移动**（`fs.renameSync`）挪进 `.workbuddy/build__server_bundle`，
`build/` 于是与上一次成功构建**顶层逐项零差异**（16 项 / 401 个 html / 有 sitemap）。

**构建成功的判据是两条**：日志出现 `[SUCCESS] Generated static files`，**且** `build/sitemap.xml` 存在。
只看退出码会被上面那条骗过。该判据已写入 `PROJECT.md` §6.2。
