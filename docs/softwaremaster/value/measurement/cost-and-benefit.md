# 成本与收益

成本与收益分析的目的不是算出精确数字，而是**暴露假设**：把「我觉得值得」拆成可以让别人质疑的具体条目。

## 成本项要全

只算开发工时是最常见的漏项。完整的成本清单至少包含：

| 类别 | 内容 |
| --- | --- |
| 建设成本 | 设计、开发、测试、上线 |
| 运行成本 | 服务器、第三方服务、许可证 |
| 维护成本 | 缺陷修复、环境适配、技术债偿还 |
| 学习成本 | 用户上手时间、团队培训、文档维护 |
| 机会成本 | 用掉的人力本可以做的事 |
| 退出成本 | 迁移、下线、数据清理 |

其中**学习成本**最容易被工程视角忽略：把配置项从 3 个增加到 30 个，开发成本几乎不增加，但用户的学习成本会成倍上升。

## 收益要分近远

- 近期收益：收入、成本节约、告警减少——可直接测量。
- 远期收益：可维护性、扩展能力、团队信心——只能间接推断，但不应因此被记为 0。

对远期收益的处理建议是**单独列项、明确标注为估计**，而不是偷偷折成近期数字。

## 实践建议

- 用「不做的代价」做对照：如果这个项目不做，当前的损耗是多少？这往往比收益估计更可靠。
- 对成本给出区间而非点估计，区间宽度本身就是不确定性的一种表达。
