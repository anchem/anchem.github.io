# 价值度量

无法度量的价值主张只是愿望。本分组解决「怎么证明价值真的发生了」。

## 包含内容

- [成本与收益](./cost-and-benefit.md)：投入与产出的对照方法
- [度量指标](./metrics.md)：可落地的指标体系与常见陷阱

## 三条原则

1. **先定义再动手**：指标在项目开始前确定。事后补的指标几乎一定会被挑成对自己有利的那个。
2. **区分过程指标与结果指标**：提交次数、功能数量是过程；留存、转化、故障恢复时间是结果。过程指标可以改善，但只有结果指标能证明价值。
3. **接受度量成本**：埋点、实验、数据链路都要花钱。度量的精细程度应当与决策的重要性匹配——为一个小改动搭全套实验平台并不划算。

## 与后续板块的衔接

价值度量定义出来的目标，会直接变成[需求](../../requirement/index.md)中的非功能性指标，以及[运维](../../maintenance/index.md)中的服务级别目标。这条链路必须保持一致：度量里没写的，运维就没有理由去保障。
