# 商业模式

商业模式 = **价值创造 + 价值传递 + 价值捕获** 三件事的完整闭环。只讲前两件的是愿景，不是商业模式。

## 三个必备要素

### 价值创造

为谁、解决什么问题、比现有方案好在哪。对应[价值主张](../user/value-proposition.md)。

### 价值传递

如何触达用户、如何让用户用起来。渠道、交付方式、上手成本都属于这里。软件行业的重要变化是：传递成本被互联网压到极低，但**认知成本没有被压下去**——让用户知道并相信你，仍然很贵。

### 价值捕获

如何把创造出来的价值收回一部分。常见机制：

| 机制 | 说明 | 软件中的例子 |
| --- | --- | --- |
| 直接售卖 | 一次性买断 | 桌面软件授权 |
| 订阅 | 按时长持续收费 | SaaS |
| 用量计费 | 按消耗收费 | 云服务 |
| 广告 / 注意力 | 用免费换流量再变现 | 内容平台 |
| 平台抽成 | 撮合双方后抽佣 | 应用市场 |

## 软件行业的结构性特征

- **边际成本趋零**：多服务一个用户的增量成本极低，规模效应显著，容易形成赢家通吃。
- **转换成本决定定价权**：数据迁移成本、团队习惯、生态依赖，往往比功能强弱更能留住用户。
- **免费不等于零成本**：免费产品的成本由广告主或投资方承担，工程师需要清楚谁在为自己的服务器付钱。

## 实践建议

- 设计技术方案时问一句：这个改动影响的是价值创造、传递，还是捕获？三者优先级不同，技术选型也不同。
- 转换成本是产品设计的一部分，不是技术债。刻意保留一些摩擦以留存用户，与降低上手成本之间需要显式权衡。
