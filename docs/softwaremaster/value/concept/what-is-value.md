# 什么是价值

价值 = **某主体愿意为某个结果付出的代价**。这句话里有两个不可缺少的要素：主体（谁认可）和结果（解决了什么问题）。缺掉任何一个，「有价值」这个判断就不成立。

## 价值的三重属性

### 主体性

价值从不抽象存在，它一定相对于某个主体。同一款软件，对使用者是效率，对采购方是合规，对厂商是收入——三者是三种不同的价值，不能用同一个数字概括。

### 相对性

价值是「比较」出来的，不是「测量」出来的。用户判断要不要用你的软件，比的不是你的功能列表，而是**他当前的替代方案**：可能是竞品，可能是一张 Excel，也可能是什么都不做。

### 时效性

同一份价值在不同时间点不等价。抢占窗口期的功能价值高，窗口关上后同样的功能会迅速贬值。这是为什么「什么时候做」和「做什么」同等重要。

## 使用价值与交换价值

| 类型 | 含义 | 软件中的对应 |
| --- | --- | --- |
| 使用价值 | 使用者实际获得的效用 | 效率提升、风险降低、体验改善 |
| 交换价值 | 市场愿意支付的代价 | 售价、订阅费、用户注意力 |

软件产品最常见的失败模式，是**只创造使用价值却无法捕获交换价值**：用户很满意，公司不赚钱。反过来只有交换价值没有使用价值的，通常活不长。

## 实践建议

- 写需求文档前，先为每条价值主张写下「主体 + 结果 + 替代方案」三要素，写不出来就先别往下走。
- 区分「我认为有价值」和「有人已经为它付过代价」——后者才是证据。
