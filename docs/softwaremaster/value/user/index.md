# 用户价值

用户价值回答：这件事对**使用者**意味着什么。它是商业价值的必要条件，也是工程决策中最容易被口头承认、实际上被忽略的一项。

## 包含内容

- [用户需求洞察](./user-need.md)：如何识别用户真正的问题，而不是他嘴上说的方案
- [价值主张](./value-proposition.md)：如何把用户价值表达成一句可验证的话

## 两个基本判断

### 用户不为功能付费，为结果付费

用户购买的是「不再加班对账」「不会被审计追责」「十分钟就能上手」，不是「支持多维度筛选」。功能只是达成结果的手段。

### 用户价值是被感知出来的

客观改善必须被用户感知，才构成价值。把响应时间从 3 秒降到 0.5 秒是客观改善；如果界面上没有任何反馈，用户可能只觉得「点了没反应」。**可感知性**应当作为需求的一部分被设计，而不是上线后再补。
