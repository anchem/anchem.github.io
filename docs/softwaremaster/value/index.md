# 价值：为什么做

价值回答的是**最上游的问题**：这件事到底值不值得做、为谁创造价值、凭什么由我们来做。

在「价值 → 需求 → 开发 → 运维」这条链路上，价值是唯一的输入端。需求可以写得再漂亮、代码可以写得再优雅，如果一开始要解决的问题本身不成立，后面所有环节的投入都会成倍浪费。软件史上大量失败项目，死因都不是技术，而是做了一个没有人真正需要的东西。

## 与其他板块的关系

- 价值是**需求的源头**：一个需求如果说不清它服务于哪条价值，就应当被质疑。
- 价值是**取舍的标尺**：开发阶段的每一次架构选择、运维阶段的每一次资源投入，最终都要回到「哪条路创造的价值更大」。
- 价值是**可证伪的**：无法被度量的价值主张，通常只是愿望。这决定了本板块必须包含度量方法。

## 建议阅读顺序

1. 先读「价值认知」，建立对价值的定义；
2. 再读「商业价值」与「用户价值」，理解两类价值主体及其冲突；
3. 最后读「价值度量」，把前两步的结论变成可验证的指标。
