# Linux 服务器维护

> 面向生产环境中的 Linux 服务器，围绕「看得见 → 判断得出 → 处置得了」组织运维实践。

上一级[软件维护](../index.md)回答的是「维护有哪些类型」，本框架落到一个具体对象上：**一台正在对外提供服务的 Linux 服务器**。

## 本框架管什么

| 文档 | 内容 |
| --- | --- |
| [CPU 运维指南](./cpu.md) | CPU 使用率的观测、判读与高负载处置 |

后续可按资源维度继续扩展（内存、磁盘、网络、进程等）。

## 与相邻内容的边界

- [操作系统 / Linux](../../../develop/foundation/operating-system/linux/index.md)：讲内核机制与原理，回答「为什么是这样」。本框架讲生产环境下的观测与处置，回答「出了状况怎么办」。
- [运营](../../operation/index.md)：讲通用的运营体系（监控、告警、服务级别）。本框架是那套体系在 Linux 服务器上的具体落地。

三者互补而非重复：原理决定你能否解释现象，运营体系决定你是否知道该关注什么，本框架决定你手上怎么做。

## 一条原则

服务器运维的价值不在于「会背命令」，而在于**能把现象收敛到原因**。

CPU 使用率高本身不是故障，多数时候它只是别处问题的表征——可能是内存不足导致的频繁回收，也可能是磁盘 I/O 阻塞引发的排队。因此本框架下的每一篇都按同一结构组织：

**怎么观测 → 怎么判读 → 怎么处置**

判读是其中最容易被跳过、也最值钱的一环。
