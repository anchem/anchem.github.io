服务级别

服务级别是运营的契约与度量基准。没有它，「系统是否正常」就只是一个主观判断。

三个概念的区别​

概念含义性质
SLI服务级别指标：实际测量的值事实
SLO服务级别目标：内部设定的目标值承诺给自己
SLA服务级别协议：对外的承诺与后果承诺给客户，含赔偿

三者的关系是：用 SLI 衡量，按 SLO 管理，把一部分 SLO 写进 SLA。

SLA 通常严于 SLO 才安全：如果内部目标与对外承诺一致，就没有缓冲空间，任何轻微波动都会触发违约。

SLI 的选择​

SLI 必须从用户体验出发，而不是从实现出发：

服务类型合适的 SLI
请求型成功率、延迟分位数
数据管道端到端时延、数据新鲜度、完整性
存储型持久性、读取可用性
批处理按时完成率

「成功率」需要明确定义：哪些错误计入、哪些不计入（例如用户参数错误不应算作服务不可用）。定义不清会导致同一次故障得出不同结论。

SLO 的设定​

原则：

  1. 不要设 100%。100% 意味着没有任何变更与维护空间，也不现实。
  2. 目标的严格程度应当与业务损失匹配。每提升一个 9，成本上升一个量级，收益可能很有限。
  3. 先测量，再设定。基于当前实际水平设定，而不是基于愿望。
  4. 用户旅程对齐。多个服务组合成一条用户路径时，链路上的 SLO 应当按路径对齐，避免出现「每个服务都达标但整体体验很差」。

错误预算​

错误预算 = 100% − SLO。它是服务级别中最有实践价值的概念：

  • 预算未用完：可以继续快速迭代与尝试；
  • 预算消耗过快：说明稳定性有问题，应当冻结变更、优先修复；
  • 预算长期剩余：说明目标过松，可以考虑提高标准或加快交付。

错误预算把「要稳定性还是要速度」这个反复争论的问题变成了一个可计算的判断——这是它最大的价值。

与需求的关系​

SLO 应当直接来源于可用性与性能需求。若两者不一致，说明需求描述与运营实践脱节，应当以实际承诺的一方为准并修正另一方。

实践建议​

  • 为每条 SLO 明确：SLI 定义、统计窗口、目标值、数据来源。
  • 把 SLO 做成仪表盘常态化展示，而不是季度报表。
  • 为错误预算消耗设定明确的响应规则（何时告警、何时冻结变更）。
  • 定期审视 SLO 是否仍与业务匹配——业务重要性变化后，旧目标可能已经不合适。
  • 对外承诺（SLA）保留足够缓冲，避免轻微波动就触发违约。
