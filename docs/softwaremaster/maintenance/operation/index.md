# 运营

> 运营指确保软件系统在生产环境中持续、稳定、高效、安全地运行，以满足服务级别协议和服务级别目标的日常活动。

运营与交付的区别在于**持续性**：交付是一次事件，运营是常态。它的目标不是「把事情做完」，而是「让系统保持在可接受的状态」。

## 运营的三条基本假设

### 1. 系统一定会出问题

分布式系统的组件会失效、网络会抖动、依赖会变慢。**运营的目标不是避免所有故障，而是让故障可被发现、可被控制、可被恢复**。

### 2. 没有度量就没有运营

「系统运行良好」这种判断毫无价值。运营必须建立在可观测的数据上：指标、日志、追踪、以及面向用户的服务级别指标。

### 3. 人的注意力是稀缺资源

告警疲劳会摧毁整套监控体系的价值：当告警多到可以忽略时，真正的故障也会被忽略。

**每一条告警都必须是可行动的**——收到告警的人应当知道要做什么。做不到，就不该发这条告警。

## 运营的核心指标

| 类别 | 关注 |
| --- | --- |
| 可用性 | 服务是否可访问、关键功能是否可用 |
| 延迟 | 请求耗时分布，尤其是长尾 |
| 错误率 | 各类错误的占比与趋势 |
| 饱和度 | CPU、内存、连接、队列、磁盘等资源的紧张程度 |
| 变更 | 近期变更与故障的相关性 |

其中**变更与故障的相关性**最常被忽略：相当比例的线上故障由变更直接或间接引起，把变更信息与监控关联能显著缩短定位时间。
