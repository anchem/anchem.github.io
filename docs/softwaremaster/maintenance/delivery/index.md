# 交付

> 交付指的是将新开发或更新后的软件产品（包括其环境、配置、数据、文档等）正式移交给最终用户或生产环境的过程。

交付的本质是**可控的风险释放**。它不是一个「完成」的时刻，而是一次「把新的不确定性引入生产」的动作。

## 发布与部署是两件事

| 动作 | 性质 | 决策者 |
| --- | --- | --- |
| 部署 | 技术动作：把代码放到环境里 | 工程团队 |
| 发布 | 业务决策：让用户看到新功能 | 业务方 |

把两者解耦（通过特性开关、灰度、流量切分）能带来两个好处：

1. **随时可部署**，不必等业务窗口，减少积压与冲突；
2. **随时可撤销**，出现问题时关闭开关即可，无需重新部署。

这是交付能力成熟度最重要的分界线。

## 交付要一并移交的东西

软件不是孤立的可执行文件。一次完整交付至少包含：

| 内容 | 缺失后果 |
| --- | --- |
| 可执行产物 | 无法运行 |
| 配置与依赖清单 | 环境不一致导致故障 |
| 数据库变更与回滚脚本 | 版本不兼容，无法回退 |
| 运行手册与告警说明 | 出问题时无人知道如何处置 |
| 变更记录与影响范围 | 故障定位缺少线索 |
| 兼容性承诺 | 调用方被动中断 |

**回滚脚本与变更记录最常被遗漏**，而它们恰恰是出问题时的救命稻草。

## 交付的检验标准

一次交付是否成功，不看「有没有按计划上线」，而看：

- 服务是否在承诺的指标内运行；
- 出现问题时能否在可接受的时间内恢复或回退；
- 运维团队是否具备独立处置该版本问题的能力。
