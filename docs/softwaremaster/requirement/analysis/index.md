# 需求分析

需求分析要弄清三件事：**谁在提要求、要求具体是什么、哪个先做**。

## 包含内容

- [利益相关者](./stakeholders.md)：识别所有对系统有诉求的角色
- [需求来源](./sources.md)：需求从哪些渠道来、各自的可靠性如何
- [功能性需求](./functional.md)：系统做什么
- [非功能性需求](./nonfunctional/index.md)：系统要做得多好
- [需求优先级](./prioritization.md)：在资源有限时先做哪个

## 分析的动作序列

1. **圈定相关方**：漏掉一个角色，就会在验收时冒出一批「必须满足」的需求。
2. **收集原始诉求**：先要原话与场景，不要急于归纳。
3. **归一化**：把不同相关方用不同说法表达的同一件事合并。
4. **分类**：区分功能性需求与非功能性需求——**两者的处理方式完全不同**。
5. **排优先级**：明确第一版必须做到哪里。

## 分析阶段最贵的两个错误

- **把方案当需求**：「需要加一个导出按钮」是方案，「月度对账要交给财务」才是需求。锁死在方案上，会错掉更简单的解法。
- **忘记非功能性需求**：性能、安全、容量这类约束事后补救的成本远高于事前约束，且很多是**不可逆**的（例如数据模型选错导致无法水平扩展）。
