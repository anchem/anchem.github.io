# 需求优先级

资源永远不够，优先级不是「排序技巧」，而是**明确放弃什么**的决策过程。

## 常用方法

| 方法 | 维度 | 适用场景 |
| --- | --- | --- |
| 四象限（重要 / 紧急） | 2 | 快速粗筛 |
| MoSCoW | 必须 / 应该 / 可以 / 不做 | 版本范围谈判 |
| Kano 模型 | 基本型 / 期望型 / 兴奋型 | 判断功能对满意度的作用机制 |
| 价值 - 成本矩阵 | 收益 / 投入 | 资源分配 |

方法的差别不大，关键在**判定标准是否公开**。标准不公开，优先级就会退化成声量博弈。

## Kano 模型的实用价值

它区分了三类功能的边际效用：

- **基本型**：不满足会强烈不满，满足了也不加分（如登录不报错）。必须最先做满。
- **期望型**：做得越好满意度越高（如搜索准确率）。持续投入的主战场。
- **兴奋型**：没有也不被期待，有了则显著加分（如意外的好用细节）。用来制造差异。

随着时间推移，兴奋型会退化为期望型，最终变成基本型。这解释了为什么靠单一亮点无法长期立足。

## 一个实用的排序判据

依次问四个问题，任一为「否」就降级：

1. 不做它，业务是否真的受损失？
2. 它是否阻碍其他需求实现（是否为前置依赖）？
3. 它的证据是否来自**已付出代价**的行为？
4. 它的成本估算是否包含维护成本？

## 实践建议

- 优先级是**排序**而不是**打分**。给每条需求一个数字，最后仍然要靠人排序；不如直接排出顺序，效率更高。
- 明确写出「本版本不做」的清单。不写不做的范围，范围就一定会膨胀。
- 优先级需要定期重排。环境变化后，旧排序可能已经失效。
