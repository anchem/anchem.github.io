# 兼容性

兼容性约束系统**与外部环境、既有版本、上下游系统共存的能力**。它是唯一一类「不满足会立刻造成用户损失」的需求。

## 需要覆盖的兼容维度

| 维度 | 内容 |
| --- | --- |
| 向后兼容 | 新版本不破坏旧客户端 / 旧调用方的行为 |
| 向前兼容 | 旧版本能容忍新版本产生的数据 |
| 数据兼容 | 表结构、序列化格式、编码的兼容与迁移 |
| 接口兼容 | 新增可选字段可接受，删改字段造成破坏 |
| 平台兼容 | 操作系统、浏览器、运行时版本 |
| 依赖兼容 | 第三方库版本、协议版本 |
| 国际化 | 多语言、时区、字符集、数字与日期格式 |

## 兼容性破坏的典型来源

- 直接删除或重命名字段；
- 把可选字段改为必填；
- 修改枚举取值却未做未知值兜底；
- 改变默认行为或排序规则；
- 修改时间与时区的解释方式；
- 修改数值精度与舍入策略。

这些改动在开发环境通常毫无异样，只有在真实客户端版本混杂时才暴露。

## 需求的写法

兼容性必须写明**承诺范围与期限**：

> 对外接口保证向后兼容至少两个大版本；字段只增不删，废弃字段保留标记不少于 6 个月。

没有期限的兼容承诺会变成永久负担；没有承诺的兼容则会让客户端随时被打断。

## 实践建议

- 把「字段只增不删、枚举留未知分支」写进接口设计规范，作为默认约束。
- 客户端与服务端解耦部署时，必须假定**任意新旧组合都可能同时存在**。
- 数据迁移方案要与发布方案一起评审，包含回滚路径。
- 兼容性检查应当纳入自动化测试，例如基于契约的兼容性验证。
