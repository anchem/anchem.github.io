# 需求管理

需求管理要解决一个不可回避的事实：**需求一定会变**。管理的目的不是阻止变化，而是让变化**可见、可控、可回溯**。

## 包含内容

- [需求生命周期](./lifecycle.md)：一条需求从提出到退场的完整过程
- [变更控制](./change-control.md)：变化进入系统时的评估与决策机制
- [需求追踪](./traceability.md)：需求与设计、代码、测试之间的对应关系

## 为什么不能靠「自然演进」

没有管理机制时，需求变化会以三种方式失控：

1. **隐性变更**：口头变更没有记录，实现与文档脱节，验收时才发现理解不一致。
2. **范围蠕变**：每一条变更单独看都合理，累加起来交付日期不断推后。
3. **影响不可见**：改一条需求牵动多少设计、代码、测试，没人说得清。

这三种失控都会在[运维](../../maintenance/index.md)阶段以缺陷形式暴露，且修复成本远高于当时决策的成本。

## 管理的产出

需求管理的产物不是流程文档，而是三样具体的东西：

- 一份**当前有效的需求基线**；
- 一条条**变更记录及其决策理由**；
- 一张**需求到实现的追踪关系**。

## 一条纪律

变更本身不可怕，**未记录的变更**才可怕。任何口头承诺都应立刻落到需求池里，哪怕只写一行。
