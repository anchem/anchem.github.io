# 算法与数据结构

这一学科回答三个问题：**数据怎么组织**、**问题怎么求解**、**代价怎么衡量**。三者是一个整体——脱离代价谈算法没有意义。

## 包含内容

- [数据结构](./data-structure.md)：把数据组织成什么形状
- [算法范式](./algorithm-paradigm.md)：用什么样的思路求解问题
- [复杂度分析](./complexity.md)：如何衡量并比较代价

## 核心认识

### 数据结构决定算法空间

同一个问题，换一种数据组织方式，可行解会完全不同。「在十亿条记录里找重复」用数组做不到，用哈希表是线性的。因此**选数据结构常常比选算法更关键**。

### 没有最好的结构，只有匹配场景的结构

| 结构 | 强项 | 代价 |
| --- | --- | --- |
| 数组 | 随机访问、缓存友好 | 插入删除昂贵 |
| 链表 | 任意位置插入删除 | 随机访问线性、缓存不友好 |
| 哈希表 | 常数期望查找 | 无序、扩容抖动、哈希攻击面 |
| 平衡树 | 有序 + 对数操作 | 常数因子大、实现复杂 |
| 堆 | 极值操作 | 只关心极值时最优 |
| 跳表 | 有序 + 并发友好 | 空间换实现简化 |

### 复杂度是共同语言

复杂度让「这个方案行不行」在写代码之前就有答案。它是[架构决策](../../development/architecture/index.md)中最常被引用的量化依据。
