# 算法范式

范式是求解问题的**思路模板**。识别出问题属于哪种范式，往往直接给出可行方向。

## 主要范式

| 范式 | 思路 | 适用条件 | 典型问题 |
| --- | --- | --- | --- |
| 分治 | 拆成同构子问题，合并结果 | 子问题独立 | 归并排序、快速排序 |
| 动态规划 | 记录子问题结果，避免重复计算 | 有最优子结构 + 重叠子问题 | 最短路、背包、编辑距离 |
| 贪心 | 每步取局部最优 | 需证明贪心选择性质 | 区间调度、霍夫曼编码 |
| 回溯 | 枚举 + 剪枝 | 解空间可剪枝 | 排列组合、约束满足 |
| 分支限界 | 在回溯基础上用界函数优先搜索 | 需要最优解 | 调度、规划 |
| 随机化 | 引入随机性换取简单或更快 | 允许小概率失败 | 快速选择、采样 |
| 近似 | 放弃最优，换多项式时间 | 问题本身难解 | 旅行商、装箱 |
| 在线 / 流式 | 数据一次到达，内存受限 | 无法回看全部数据 | 基数估计、滑动窗口 |

## 动态规划是分水岭

它出现的标志是：**同一个子问题会被反复遇到**。此时的要点是设计状态定义与转移方程——状态定义得好，转移自然简单；状态定义错了，转移会变成一堆特例。

代价是空间。实践中常用滚动数组等手段把空间压到常数级。

## 什么情况该停止找精确解

遇到 NP 难问题（如旅行商、图着色、大规模装箱），继续优化精确算法通常没有意义。此时要转为：

1. **放松问题**：约束是否可以放宽？
2. **近似算法**：接受一个可证明的近似比。
3. **局部搜索 / 启发式**：工程上够用即可。
4. **改用求解器**：把问题交给成熟的约束求解或整数规划工具。

**识别「这个问题没有高效精确解」，本身就是关键能力**——它能避免数周的无效投入。

## 实践建议

- 遇到新问题先归类范式，再动手；归类错了，实现再快也要返工。
- 对动态规划，先写朴素递归再看能否记忆化——这比直接设计状态更不容易出错。
- 规模是决定策略的关键参数：小规模暴力，中等规模动态规划或剪枝，大规模只能近似或分布式。
