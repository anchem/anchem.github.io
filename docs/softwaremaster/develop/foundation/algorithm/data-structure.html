数据结构

数据结构是数据的组织形状，它决定了哪些操作便宜、哪些操作昂贵。

按访问模式选择​

核心需求首选结构说明
按下标随机访问数组连续内存，缓存命中率高
频繁在两端增删双端队列 / 栈O(1) 操作
按 key 快速查找哈希表期望 O(1)，最坏 O(n)
需有序遍历 + 查找平衡树 / 跳表O(log n)
只取最大 / 最小堆O(1) 取极值，O(log n) 更新
前缀匹配Trie / 前缀树按字符共享前缀
去重 + 集合运算位图 / 布隆过滤器空间极小，可能误判
关系与依赖图表达多对多与方向

内存布局比复杂度更重要​

两个都是 O(log n) 的结构，实际性能可能相差数倍——差别来自缓存局部性：

  • 数组与 B 树把相关数据放在连续内存，CPU 缓存命中率高；
  • 链表与二叉树节点分散，每次跳转都可能触发缓存未命中。

因此现实中「复杂度略差但内存连续」的结构常常胜出。数据库索引普遍采用 B+ 树而非二叉搜索树，正是这个原因。

概率型结构​

布隆过滤器用极小的空间回答「一定不存在 / 可能存在」：

  • 判断「不存在」是确定的；
  • 判断「存在」可能是误判。

它适合做前置过滤：先用布隆过滤器挡掉绝大多数不存在的查询，再回落到真正的存储。代价是可控的误判率与不可删除。

实践建议​

  • 先明确操作的比例（读多还是写多、是否需要有序），再选结构。
  • 大对象集合优先考虑内存连续性与分块，它对真实性能的影响常超过算法复杂度。
  • 对哈希表要预留扩容策略；扩容瞬间的延迟抖动常是线上毛刺的来源。
