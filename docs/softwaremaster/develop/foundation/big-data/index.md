# 大数据

大数据的核心问题是：**当数据量或写入速率超出单机能力时，如何组织计算与存储**。它不是一个技术栈，而是一组权衡。

## 包含内容

- [批处理](./batch-processing.md)：面向全量数据的离线计算
- [流处理](./stream-processing.md)：面向持续到达数据的增量计算

## 根本约束

### 数据搬运比计算昂贵

分布式计算的大部分时间花在**网络传输与磁盘 IO** 上，而不是 CPU 计算。因此优化的核心方向是**减少数据移动**：把计算推到数据所在的位置，而不是把数据拉到计算所在的位置。

### 分而治之需要可切分性

能并行的前提是数据与计算可以被切分，且切分后能合并结果。这对数据格式提出了要求：**按行切分容易，任意随机切分代价高**。这就是列式存储、分区与分桶存在的原因。

### 一致性代价随规模放大

数据分散后，跨分片的事务与连接成本急剧上升，因此大数据系统普遍放弃通用事务，转而依赖幂等、可重算与数据血缘。

## 一条实用的技术选择路径

| 需求 | 方向 |
| --- | --- |
| 全量历史分析、允许小时级延迟 | 批处理 |
| 秒级到分钟级指标、持续到达 | 流处理 |
| 交互式探索、要求秒级响应 | 预聚合 + 列式存储 + OLAP 引擎 |
| 单条记录的精确读写 | 回到关系数据库或键值存储 |

## 常见误区

- **为了「大数据」而引入大数据栈**：数据量在单机能力范围内时，引入分布式系统只会增加运维与一致性负担。
- **只关注吞吐不关注数据质量**：缺少血缘、口径与校验的数据平台，最终会失去信任。
- **忽略时效性**：离线与实时的口径不一致，会导致同一指标出现两个数字，直接摧毁数据可信度。
