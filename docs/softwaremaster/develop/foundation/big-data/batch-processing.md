# 批处理

批处理对**一批已经落地的数据**做全量或增量计算，特点是高吞吐、可重算、延迟较高。

## 基本模型

```
读取 → 切分 → 并行处理 → 洗牌聚合 → 写出
```

其中**洗牌**（shuffle）是性能关键点：它需要把数据按 key 重新分布到不同节点，涉及网络传输与磁盘落盘，通常是整个作业中最慢的阶段。

## 关键设计问题

| 问题 | 影响 |
| --- | --- |
| 分区键选择 | 决定数据倾斜程度与并行度 |
| 数据倾斜 | 少数 key 数据量过大，拖慢整个作业 |
| 小文件 | 元数据开销主导，调度开销上升 |
| 文件格式 | 列式 + 压缩显著降低 IO |
| 重算能力 | 作业必须可重复执行且结果一致 |

### 数据倾斜的应对

倾斜是批处理中最常见的性能问题。常见手段：

1. **加盐打散**：给热点 key 加随机后缀，先局部聚合再全局合并。
2. **广播小表**：把小维表广播到各节点，避免 shuffle。
3. **拆分热点单独处理**：对大 key 走单独路径，其余走常规路径。

### 幂等与可重算

批处理作业必须满足：**同一批数据重跑结果一致，且重复写出不产生重复数据**。做法通常是按日期或批次分区覆盖写，而非追加写。

## 实践建议

- 优先减少 shuffle 次数与数据量，这比调优算子实现收益大得多。
- 使用列式存储并按常用过滤字段分区，能大幅降低扫描量。
- 为作业建立数据质量校验（行数、主键唯一性、值域），失败即告警。
- 保证作业可重跑，这是数据修复能力的唯一来源。
- 关注存储层的小文件问题，定期合并。
