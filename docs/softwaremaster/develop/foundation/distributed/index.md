# 分布式及并行开发

分布式的价值是**突破单机上限**：更高的吞吐、更大的容量、更强的容错。代价是引入了单机编程中不存在的根本难题。

## 包含内容

- [并发与并行](./concurrency.md)：共享状态下的正确性问题
- [一致性](./consistency.md)：多副本之间的数据正确性取舍
- [共识](./consensus.md)：多节点如何就一件事达成一致

## 为什么分布式难以一劳永逸

### 网络是不可靠的

延迟不确定、消息可能丢失、可能重复、可能乱序。这直接导致一个基础难题：**无法区分「节点挂了」和「节点慢」**。

### 部分失败

单机程序要么活着要么崩了；分布式系统中总有一部分在正常工作、一部分在失败。系统必须为「部分可用」定义明确行为。

### 没有全局时钟

各节点的本地时钟无法可靠对齐，因此**事件顺序不能依赖时间戳**，只能依赖逻辑因果。

```mermaid
flowchart LR
  A[客户端请求] --> B[节点 A]
  B -->|"发送（可能丢失/重复/乱序）"| C[节点 B]
  B --> D[节点 C]
  D -->|"网络分区"| C
```

## 三条工程纪律

1. **无法绕过的取舍要显式做出**：一致性、可用性、分区容忍之间的取舍必须写进设计文档，由业务确认。
2. **幂等是基本功**：在必须重试的世界里，重复执行的正确性是底线。
3. **不依赖时间的顺序**：用逻辑时钟、序列号或版本向量表达因果关系。

## 与单机并发的连续性

单机的[进程与线程](../operating-system/process-and-thread.md)问题是分布式的缩小版：共享状态、竞态、死锁。分布式只是把这些问题的粒度放大到了网络层。
