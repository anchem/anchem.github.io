# 数据库及存储

数据库解决的是**数据的持久化、并发访问与高效检索**。它的设计决策比其他环节更难撤回——表结构一旦承载数据，改动成本就随数据量增长。

## 包含内容

- [关系模型](./relational.md)：表、约束、范式与索引
- [事务](./transaction.md)：并发访问下的正确性保证
- [非关系型数据库](./nosql.md)：不同数据模型与它们各自的取舍
- [存储引擎](./storage.md)：数据在磁盘上如何组织

## 三个必须想清楚的问题

1. **数据模型**：用关系表、文档、键值，还是图？选错的代价是长期的查询复杂度。
2. **一致性要求**：哪些操作必须原子、哪些可以最终一致？这决定了能否使用分布式与缓存。
3. **访问模式**：读多还是写多、按什么条件查、数据量级多大？索引与分片策略由此决定。

**先想访问模式，再定数据结构**。反过来做，几乎一定会出现「表设计得很规范但查询全表扫描」的局面。
