# 网络安全

网络安全要解决的是：**在不可信的信道上建立可信的通信**。默认假设应当是——所有经过网络的数据都可能被窃听、篡改或重放。

## 三个基本目标

| 目标 | 手段 |
| --- | --- |
| 机密性 | 传输加密（TLS） |
| 完整性 | 消息认证码、签名 |
| 身份认证 | 证书、密钥对、令牌 |

## 常见攻击与防护

| 攻击 | 原理 | 防护 |
| --- | --- | --- |
| 中间人 | 截获并转发通信 | 证书校验、严格传输安全 |
| 重放 | 重复发送合法请求 | 时间戳、随机数、幂等设计 |
| 注入 | 数据被当作指令执行 | 参数化查询、输入校验 |
| 跨站脚本 | 脚本被注入页面 | 输出转义、内容安全策略 |
| 跨站请求伪造 | 借用已认证会话 | 令牌校验、同站策略 |
| DDoS | 耗尽资源 | 限流、清洗、容量冗余 |

## 网络层的防护边界

纵深防御是这里的核心思路——**任何单一层级的防护都可能失效**，需要多层重叠：

1. **边界**：防火墙、安全组、只开放必要端口。
2. **传输**：全链路 TLS，包括服务间的内部通信。
3. **应用**：认证、鉴权、输入校验、限流。
4. **数据**：敏感字段加密、最小权限访问。
5. **监测**：审计日志、异常流量告警。

## 两个高频误区

- **信任内网**：内网一旦被突破，横向移动几乎不受阻。现代实践是**零信任**：不因位置授予信任，每次访问都校验。
- **加密即安全**：加密只解决信道问题。加密流量中依然可以有注入、越权与业务逻辑漏洞。

## 实践建议

- 强制使用 TLS 并校验证书链，禁止降级到明文。
- 内部服务间通信同样加密并鉴权，不要依赖网络边界的假设。
- 对入站数据一律视为不可信，包括来自其他内部服务的字段。
- 所有对外接口设置限流与配额，防止资源被单点耗尽。
- 日志中不得记录密钥、令牌与敏感个人信息。
