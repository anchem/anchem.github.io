# 进程与线程

进程是**资源分配与隔离的单位**，线程是**调度的单位**。区分这两件事，是理解并发问题的起点。

## 核心区别

| 维度 | 进程 | 线程 |
| --- | --- | --- |
| 地址空间 | 独立 | 共享 |
| 开销 | 创建、切换成本高 | 轻量 |
| 通信 | 需要显式 IPC | 直接读写共享内存 |
| 隔离性 | 强，一个崩溃不影响另一个 | 弱，一个出错全挂 |
| 故障半径 | 小 | 大 |

**共享内存是线程效率的来源，也是线程 bug 的来源**。所有竞态、死锁、可见性问题都源自这里。

## 进程状态与调度

```
新建 → 就绪 → 运行 → 阻塞 → 就绪
                ↓
              终止
```

关键认识：

- **阻塞不等于占用 CPU**：等待 IO 的进程被移出运行队列，这正是 IO 密集任务可以高并发的原因。
- **就绪队列长度决定延迟**：当可运行线程数远多于 CPU 核数时，调度延迟会显著上升。这是「线程池开太大反而更慢」的原因。
- **上下文切换有成本**：包括寄存器保存与缓存失效。高并发系统更偏好异步 IO 与协程，本质是减少切换。

## 进程间通信

| 方式 | 特点 | 适用 |
| --- | --- | --- |
| 管道 | 单向、简单 | 父子进程流式数据 |
| 共享内存 | 最快 | 大数据量、需自行同步 |
| 消息队列 | 解耦、有序 | 异步任务 |
| Socket | 可跨机器 | 通用 |
| 信号 | 轻量、语义弱 | 通知与终止 |

## 实践建议

- 线程数按「CPU 核数 × (1 + 等待时间 / 计算时间)」估算，并根据实测调整；不要凭感觉设大。
- CPU 密集任务用「核数」量级的线程池，IO 密集任务可以更高，但都要有上限。
- 进程隔离是故障隔离最有效的手段之一，在关键模块间保留进程边界是值得的。
- 线上排查时先看上下文切换次数与运行队列长度，它们比 CPU 使用率更能解释延迟。
