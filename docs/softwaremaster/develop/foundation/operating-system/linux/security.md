# Linux 安全

Linux 安全的核心是**权限模型 + 隔离机制 + 审计能力**三者的组合。

## 权限模型

| 层面 | 机制 |
| --- | --- |
| 用户与组 | 属主 / 属组 / 其他，读写执行三类权限 |
| 特殊位 | setuid / setgid / sticky，权限提升的关键风险点 |
| 能力（capabilities） | 把 root 权限细分成可单独授予的能力 |
| 访问控制 | SELinux / AppArmor 提供强制访问控制（MAC） |

**最小权限**是这里唯一重要的原则：进程只应拥有完成其职责所必需的权限。以 root 运行应用、给脚本加 setuid 位、把目录权限设为 777，都是在用便利换风险。

## 隔离机制

| 机制 | 作用 |
| --- | --- |
| namespace | 隔离视图：PID、网络、挂载、用户、UTS、IPC |
| cgroup | 限制资源：CPU、内存、IO、进程数 |
| chroot / pivot_root | 改变根目录，限制文件系统视图 |
| seccomp | 限制系统调用集合 |

这些机制正是[容器](../../container/introduction.md)的实现基础。理解它们才能判断容器的隔离强度——**容器共享宿主机内核，因此内核漏洞是容器逃逸的主要路径**。

## 常见风险清单

- 以 root 运行服务；容器内不需要的特权（`--privileged`）被开启。
- 把敏感信息写在环境变量或镜像层里，随镜像分发泄露。
- 开放不必要的端口与服务，暴露面过大。
- 依赖与镜像未做漏洞扫描与版本更新。
- SSH 允许口令登录、允许 root 直连。
- 审计日志缺失，事后无法追溯。

## 实践建议

- 服务以非特权用户运行，只授予必需的能力。
- 容器镜像使用最小基础镜像，构建过程不携带凭据。
- 敏感配置通过挂载或密钥管理服务注入，不写入镜像。
- 开启审计并集中收集内核与应用日志，日志本身要防篡改。
- 定期做漏洞扫描与基线核查，将其纳入自动化流水线。
