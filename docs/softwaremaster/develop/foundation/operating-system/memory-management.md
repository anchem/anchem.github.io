# 内存管理

内存管理提供了**虚拟内存**这一抽象：每个进程都以为自己独占一片连续地址空间，而实际物理内存由内核统一调度。

## 虚拟内存解决的三件事

1. **隔离**：进程无法访问他人的地址空间。
2. **简化**：程序不必关心物理内存碎片与布局。
3. **复用**：不常用的页可以换出到磁盘，使程序可用空间超过物理内存。

代价是**地址翻译**：每次访问都要经过页表，因此需要 TLB 缓存。TLB 未命中会显著影响性能，这是「随机访问大数组比顺序访问慢很多」的根本原因。

## 内存层级与局部性

```
寄存器 → L1/L2/L3 缓存 → 物理内存 → SSD/磁盘
```

速度每降一级往往差一个数量级以上。因此**程序性能主要由访问模式决定，而不是由指令数决定**：

- 顺序访问数据比随机访问快数倍到数十倍；
- 同样的算法，数据布局不同可以有量级差异。

## 常见问题

| 现象 | 原因 |
| --- | --- |
| 进程被 OOM Killer 终止 | 内存超限，内核选择代价最低的进程杀掉 |
| 内存持续增长不释放 | 内存泄漏、缓存无上限、对象生命周期过长 |
| 延迟周期性抖动 | 页回收、脏页写回、GC 与内存分配竞争 |
| 容器内存到限但进程没涨 | 页缓存计入 cgroup 内存 |

其中最后一条在容器环境中最容易踩：**页缓存被计入容器的内存用量**，所以频繁读写文件的应用会看到内存「无故」上涨。

## 实践建议

- 为进程与容器设置显式内存上限，并配置合理的回收行为——没有上限的进程最终会拖垮整台机器。
- 关注**常驻内存**（RSS）与虚拟内存的区别，两者含义完全不同。
- 大对象集合优先考虑连续内存与分块处理，利用局部性。
- 排查内存问题时先区分「真的在用」和「被缓存占用」。
