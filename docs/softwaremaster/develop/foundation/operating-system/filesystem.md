# 文件系统

文件系统把块设备抽象成**目录与文件**，并为上层提供统一的读写接口。理解它的 IO 特性，是排查性能问题的必要前提。

## 关键机制

### 页缓存

读写文件默认先经过内核的页缓存，而不是直接落盘：

- **读**：命中缓存则不访问磁盘。
- **写**：写入缓存即返回（写回模式），由内核异步刷盘。

这解释了为什么「写完就断电」会丢数据，也解释了为什么顺序写文件很快——写的是内存。

### 一切皆文件

磁盘文件、管道、socket、设备在接口层被统一。这让 IO 多路复用与统一抽象成为可能，也意味着**文件描述符是稀缺资源**，需要管理。

### 索引节点与目录

文件内容与元数据（inode）分离，目录本质是「名字 → inode」的映射。这解释了：

- 同一文件可以有多个硬链接（共享 inode）；
- 重命名在同一文件系统内是瞬时的；
- 文件大小与占用磁盘空间可能不一致（稀疏文件）。

## 影响性能的几个点

| 行为 | 后果 |
| --- | --- |
| 大量小文件 | 元数据操作成为瓶颈 |
| 随机读写 | 需要真实寻址，远慢于顺序 |
| 同步写（fsync） | 每次都要等待落盘，延迟高 |
| 未清理的临时文件 | 占用 inode，可能耗尽 |

## 实践建议

- 日志类写入优先选择**追加写**模式，利用顺序写优势。
- 对数据安全性有要求时明确 fsync 语义与代价：不 fsync 可能丢数据，每次 fsync 则吞吐骤降。常见折中是批量提交。
- 监控 inode 使用率，它比磁盘容量更容易先被耗尽。
- 大量小文件场景考虑打包或合并存储，避免元数据开销主导。
