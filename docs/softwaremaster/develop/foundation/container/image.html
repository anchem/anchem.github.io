容器镜像

镜像是一个只读的、分层的、内容可寻址的文件系统快照，也是容器运行时的起点。

分层机制​

镜像由若干只读层叠加而成，容器启动时在最上面加一个可写层：

可写层（容器运行时创建）
─────────────────────
应用层         ← 应用与依赖
基础运行环境层  ← 语言运行时
基础镜像层     ← 最小操作系统文件

分层带来的三个关键性质：

  1. 复用：相同基础层在多个镜像间共享，节省存储与传输。
  2. 缓存：构建时未变化的层可复用，加速构建。
  3. 可追溯：每一层都对应构建历史中的一个步骤。

层的顺序决定构建效率：把变化频繁的步骤（如拷贝源码）放在后面，不常变的步骤（如安装依赖）放在前面，才能最大化缓存命中。

镜像与容器的关系​

概念性质
镜像只读模板
容器镜像的一个运行实例，带可写层
仓库镜像的存储与分发地

同一个镜像可以启动任意多个容器，它们共享只读层，各自持有可写层——这也是容器启动快的原因。

构建实践​

  • 使用最小基础镜像：减小体积、缩小攻击面、加快分发。
  • 多阶段构建：构建工具与产物分离，运行镜像只保留产物。
  • 一次一个关注点：一个容器只跑一个主进程，便于扩缩与排查。
  • 不在镜像中放密钥：镜像层可被解包，任何写入层的内容都会随分发泄露。
  • 固定基础镜像版本：使用固定标签或摘要，避免上游更新引入不可控变化。
  • 以非 root 用户运行：降低容器内进程被利用后的影响面。

与可复现性的关系​

镜像的摘要（digest）是内容哈希，因此同一摘要必然对应同一内容。这让「构建产物可复现」成为可能——这是容器相比传统安装包最本质的优势。
