# 容器技术

容器把**应用及其依赖环境打包成一个整体**，解决了「本地能跑、换台机器就报错」的根本问题。它是云原生交付方式的基础。

## 核心认识

### 容器是一种特殊的进程

容器不是轻量虚拟机。它通过以下三者约束一个普通进程的视图与资源：

| 技术 | 作用 |
| --- | --- |
| namespace | 隔离视图：让进程只看到自己相关的资源 |
| cgroups | 限制资源：CPU、内存、IO、进程数 |
| rootfs | 提供隔离的文件系统 |

因此容器**共享宿主机内核**——这是它轻量的原因，也是它隔离强度弱于虚拟机的根本原因。

### 镜像解决的是交付一致性

镜像把「程序 + 运行环境」固化为不可变产物，使交付物从「一堆安装说明」变成「一个可校验的哈希」。这是容器真正的价值来源。

### 编排解决的是规模问题

单机容器只解决打包；一旦涉及多节点、扩缩容、滚动升级、故障自愈，就需要编排系统统一管理期望状态。
