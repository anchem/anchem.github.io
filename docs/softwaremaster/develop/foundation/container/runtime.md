# 容器运行时

运行时负责**创建并管理容器的生命周期**：准备文件系统、建立隔离、限制资源、启动进程、回收资源。

## 职责分解

| 阶段 | 动作 |
| --- | --- |
| 拉取 | 获取镜像层并校验完整性 |
| 解包 | 叠加只读层，创建可写层 |
| 隔离 | 建立 namespace，设置 cgroups |
| 启动 | 以指定用户、权限、能力启动主进程 |
| 监控 | 跟踪进程状态、转发信号、收集退出状态 |
| 回收 | 清理文件系统与网络资源 |

## 隔离的强度边界

容器隔离依赖内核机制，因此它的安全边界**等于宿主机内核的安全边界**。这带来几个必须清楚的事实：

- 内核漏洞是容器逃逸的主要路径；
- 以特权模式运行会让隔离大幅弱化；
- 敏感场景应当在虚拟机内运行容器（沙箱容器），用更强的边界换取安全。

**知道边界的强度，才能决定哪些负载可以放在一起。**

## 容器的生命周期

```
创建 → 运行 → （暂停 / 恢复） → 停止 → 删除
```

几个工程要点：

- **主进程是 PID 1**：它需要处理信号与孤儿子进程回收。若应用不处理，就需要一个初始化进程来代劳，否则会出现僵尸进程与信号不响应。
- **可写层随容器销毁**：容器内产生的数据默认会丢失。需要持久化的数据必须挂载外部卷。
- **停止是分阶段的**：先发终止信号给应用优雅退出，超时后强制杀死。超时时间应当大于应用的清理时间。

## 资源限制

cgroups 限制 CPU、内存、IO 与进程数。两个高频问题：

1. **内存超限被终止**：容器内存达到上限时会被直接杀掉，而不是缓慢降级。上限设置必须基于实测的峰值，而不是估计值。
2. **CPU 配额与调度延迟**：CPU 限制会让容器在配额耗尽时被节流，表现为延迟尖刺而非吞吐下降。

## 实践建议

- 显式设置内存上限，并为应用留出足够的堆外空间（缓存、线程栈、元数据）。
- 优先使用 CPU 请求值而非硬上限，避免节流带来的延迟抖动。
- 应用要正确处理终止信号，实现优雅关闭。
- 以非 root、最小能力集运行容器；按敏感级别划分运行边界。
- 监控容器的重启次数与终止原因，它是发现配置问题的第一手信号。
