# 机器学习基础

机器学习用**数据拟合规律**，替代人工编写规则。它的适用前提是：规律存在、数据可获取、且允许一定错误率。

## 三类任务

| 类型 | 目标 | 例子 |
| --- | --- | --- |
| 监督学习 | 从标注数据学映射 | 分类、回归 |
| 无监督学习 | 发现数据结构 | 聚类、降维、异常检测 |
| 强化学习 | 通过反馈优化策略 | 控制、调度、博弈 |

## 核心问题：泛化

模型的价值不在于记住训练数据，而在于**在未见过的数据上表现良好**。

| 现象 | 含义 | 应对 |
| --- | --- | --- |
| 欠拟合 | 模型太简单，规律没学到 | 增加容量、增加特征 |
| 过拟合 | 记住了噪声，泛化差 | 正则化、更多数据、降低容量 |
| 数据泄漏 | 训练时用到了预测时不可能获得的信息 | 严格按时间与实体切分数据 |

**数据泄漏是最危险的问题**：它会让离线指标非常漂亮，上线后急剧崩塌。典型来源是特征计算时用了未来信息，或切分数据时把同一实体的样本分散到了训练集与验证集两侧。

## 评估的三条原则

1. **划分要符合真实场景**：时序数据必须按时间切分，不能随机划分。
2. **指标要与业务目标一致**：准确率在不平衡数据上会严重误导，需要看精确率、召回率或面向业务的组合指标。
3. **保留独立测试集**：反复用同一份数据调参，会让它事实上变成训练集。

## 从模型到系统

一个可用的 ML 系统包含的远不止模型：

```
数据采集 → 特征工程 → 训练 → 评估 → 部署 → 监控 → 再训练
```

其中**特征一致性**是工程上最常见的故障源：训练时的特征计算方式与线上推理不一致，会导致线上表现与离线差距巨大。实践中的应对是把特征计算统一为同一份代码或同一个服务。

## 实践建议

- 先确认「这个问题是否真的需要机器学习」。规则能覆盖 95% 场景时，规则更可控。
- 建立基线（简单规则或简单模型），没有基线的复杂模型无法证明其价值。
- 上线后持续监控输入数据分布，**数据漂移**会让模型静默失效。
- 记录模型版本与训练数据版本，保证结果可追溯。
