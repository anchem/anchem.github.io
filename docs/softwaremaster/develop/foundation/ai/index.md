# 人工智能

人工智能在本站语境下不是研究课题，而是**一种需要被正确集成与约束的系统组件**。工程师需要理解它能做什么、不能做什么、成本在哪里。

## 包含内容

- [机器学习基础](./machine-learning.md)：从数据中学习规律的方法与评估原则
- [大语言模型](./llm.md)：能力边界与工程集成的关键约束

## 与软件工程的关系

引入 AI 改变了系统的几个基本假设：

| 传统软件 | 含 AI 组件的软件 |
| --- | --- |
| 行为确定、可复现 | 输出有概率性，可能不唯一 |
| 正确性可判定 | 质量需用指标评估，且难以完全判定 |
| 输入校验即可保证边界 | 需要额外的输入输出防护与复核 |
| 性能与延迟可预测 | 延迟与成本随输入长度变化，波动大 |
| 逻辑写在代码里 | 逻辑部分藏在数据与权重中 |

**最关键的差异是不可解释性**：当系统给出错误结果时，无法像排查代码 bug 那样定位到具体一行。因此风险评估与兜底机制必须前置设计。

## 三个工程纪律

1. **明确失败模式**：模型一定会有出错的比例，必须定义出错时的行为（拒答、回落、人工介入）。
2. **保留证据链**：输入、输出、模型版本、参数都要可追溯，否则无法复盘。
3. **成本可预测**：调用费用与延迟随规模增长，必须设置配额与降级策略。
