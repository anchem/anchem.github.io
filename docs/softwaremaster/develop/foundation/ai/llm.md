# 大语言模型

大语言模型（LLM）以**自回归生成**的方式工作：根据已有文本预测下一个词元，逐字生成完整回答。理解这一点，就能推出它的大部分能力边界。

## 由生成机制推出的固有性质

| 性质 | 原因 |
| --- | --- |
| 输出不确定 | 采样过程引入随机性 |
| 会编造内容 | 目标是生成「合理的」文本，而非「真实的」文本 |
| 对输入措辞敏感 | 上下文不同会改变概率分布 |
| 长上下文能力有限 | 注意力成本随长度增长，中间内容易被忽略 |
| 知识有时效上限 | 知识来自训练数据的时间窗口 |

**幻觉不是 bug，而是机制的副产物**。因此不能把 LLM 输出直接当作事实，必须设计验证环节。

## 工程集成的关键手段

### 检索增强生成

把外部知识检索后放进上下文，让模型基于给定材料作答，而不是依赖参数中的记忆。这是提升准确性与可追溯性的主要方法。

要点：检索质量决定上限。检索错了，模型再强也只能给出错误答案。

### 工具调用

让模型调用外部函数来获取事实、执行动作。原则是：**需要精确结果的事情交给工具，需要语言理解的事情交给模型**。数值计算、时间查询、数据检索都不应当由模型「心算」。

### 结构化输出

要求模型按规定格式输出并做严格校验，校验失败则重试或降级。这是把概率性输出接入确定性系统的必要手段。

### 提示设计

- 明确角色与目标，给出输出格式约束；
- 提供示例（少样本）通常比长篇说明有效；
- 把指令与待处理内容清晰分隔，防止内容被当作指令执行（提示注入）。

## 成本与延迟

- 成本与延迟随输入与输出长度增长，长上下文显著更贵；
- 流式输出改善的是感知延迟，不改变总时长；
- 缓存（相同前缀复用）能显著降低成本，值得在提示设计时考虑。

## 实践建议

- 为每次调用设置超时与重试上限，并把 LLM 视为**不可靠的外部依赖**。
- 对输出做校验与兜底：格式校验、事实核验、必要时人工复核。
- 记录输入、输出、模型版本与参数，形成可回放的审计日志。
- 严禁把未脱敏的敏感数据送入外部模型，这属于[隐私保护](../../../requirement/analysis/nonfunctional/privacy.md)的硬约束。
- 评估要建立一套固定测试集，而不是靠零散试用来判断效果。
