# 汇编与机器模型

汇编是机器指令的**可读形式**。理解它不是为了写汇编，而是为了理解程序的真实执行成本。

## 现代 CPU 的基本模型

| 组成部分 | 作用 |
| --- | --- |
| 寄存器 | 最快存储，指令操作数的主要来源 |
| 指令流水线 | 多条指令重叠执行以提高吞吐 |
| 分支预测 | 预测跳转方向，预测失败代价高 |
| 多级缓存 | 弥合 CPU 与内存的速度差 |
| 乱序执行 | 在不改变语义的前提下重排指令 |

关键推论：**性能不只取决于指令数量，更取决于流水线是否被打断**。一次缓存未命中或分支预测失败，代价可能等于数百条普通指令。

## 调用约定

函数调用涉及参数传递、栈帧建立、返回地址保存与寄存器恢复。这套约定解释了：

- 为什么**深递归**会栈溢出；
- 为什么**函数调用有开销**，内联能消除它；
- 为什么**闭包与回调**可能带来额外分配。

## 汇编里最值得看懂的部分

| 内容 | 用途 |
| --- | --- |
| 函数序言 / 尾声 | 理解栈帧与局部变量布局 |
| 循环体 | 判断是否被向量化、有无冗余内存访问 |
| 分支指令 | 判断分支预测是否友好 |
| 内存访问指令 | 判断访问是否连续、是否走缓存 |
| 锁相关指令 | 理解原子操作与内存屏障的代价 |

## 实践建议

- 用性能剖析工具定位热点后，再看热点函数的汇编，不要全局通读。
- 优化时优先调整**数据布局与访问顺序**，而不是微调指令——前者收益通常大一个量级。
- 明白原子操作与内存屏障是硬件级同步手段，其成本远高于普通读写。
