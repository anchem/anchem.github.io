# 软件工程

软件工程要解决的是**规模问题**：当参与者从一人变成多人、寿命从一周变成数年，靠个人技艺无法维持质量。工程化管理的是**过程与协作**。

## 三个不可回避的目标

1. **可重复**：同样的输入应当得到同样的结果。手工步骤越多，可重复性越差。
2. **可观测**：任何一次变更都应能被追溯——谁改的、为什么改、改了什么、影响什么。
3. **可持续**：流程必须能在长期高压下维持。依赖英雄主义的流程一定会崩。

## 判断工程实践是否有效的标准

一项实践值得保留，当且仅当它**缩短了反馈周期**或**降低了变更风险**。做不到这两点的实践（无论看起来多规范）都是纯成本。

这也是为什么评审意见的格式、提交信息的规范、流水线的速度都值得花时间优化——它们直接作用于反馈周期的长度。
