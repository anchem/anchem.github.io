# 重构手法

重构手法是**小步、可验证、行为不变的结构调整**。掌握手法比掌握坏味道更重要——识别问题只是第一步，能安全地改才是关键。

以下 7 类按改动对象划分。

## 1. 重新组织函数

| 手法 | 用途 |
| --- | --- |
| 提炼函数 | 把一段可命名的逻辑抽成函数 |
| 内联函数 | 消除无价值的间接层 |
| 提炼变量 | 为复杂表达式命名 |
| 内联临时变量 | 消除只用于一次赋值的中间变量 |
| 以查询取代临时变量 | 用函数替代需重复计算的变量 |
| 分解临时变量 | 一个变量承担多种含义时拆分 |
| 移除对参数的赋值 | 避免参数被改写导致的理解困难 |

**提炼函数是最重要的一条**。命名本身就是设计行为：能起出好名字，说明这段逻辑的职责清晰；起不出名字，往往说明它混杂了多件事。

## 2. 在对象之间搬移特性

| 手法 | 用途 |
| --- | --- |
| 搬移函数 | 把方法移到真正依恋的类 |
| 搬移字段 | 把字段移到更常使用它的类 |
| 提炼类 / 内联类 | 拆分过大类 / 合并冗赘类 |
| 隐藏委托关系 | 封装链式导航 |
| 移除中间人 | 消除只做转发的类 |

搬移的目标是**让变化集中在同一个地方**。

## 3. 重新组织数据

| 手法 | 用途 |
| --- | --- |
| 以对象取代基本类型 | 引入值对象承载语义与校验 |
| 以对象取代数据值 | 为成组数据提供行为 |
| 将引用对象改为值对象 / 反之 | 按是否需要共享身份选择 |
| 以查询取代派生变量 | 避免冗余状态不一致 |
| 封装字段 / 集合 | 保护内部状态 |
| 以字面常量取代魔法数 | 提升可读性 |

## 4. 简化条件表达式

| 手法 | 用途 |
| --- | --- |
| 分解条件表达式 | 把复杂条件抽成命名函数 |
| 合并条件表达式 | 多个同结果判断合并 |
| 以卫语句取代嵌套条件 | 提前返回，减少嵌套层级 |
| 以多态取代条件表达式 | 用类型系统替代分支 |
| 引入特例 / 空对象 | 消除重复的判空 |

**以卫语句取代嵌套条件**是收益最高、成本最低的一条：把异常与边界情况提前返回，主流程的缩进层级立刻下降。

## 5. 简化函数调用

| 手法 | 用途 |
| --- | --- |
| 改名 | 命名即文档 |
| 添加 / 移除参数 | 让调用表达更准确 |
| 以参数对象取代参数列 | 收敛成组参数 |
| 移除标志参数 | 标志参数意味着函数在做两件事 |
| 保持对象完整 | 传整个对象而非拆散的字段 |
| 以工厂函数取代构造函数 | 命名更清晰地表达意图 |

## 6. 处理概括关系

| 手法 | 用途 |
| --- | --- |
| 上移 / 下移方法 | 把方法放到合适的继承层级 |
| 上移 / 下移字段 | 同上 |
| 提炼超类 / 提炼接口 | 显式表达共性 |
| 折叠继承体系 | 合并无实际差异的层级 |
| 以委托取代继承 / 以继承取代委托 | 调整复用方式 |
| 以子类取代类型码 | 用类型系统替代枚举分支 |

## 7. 大型重构

大型重构指影响范围跨越多个模块的结构调整，通常针对[架构](../../architecture/index.md)层面的问题。常见做法：

| 重构 | 用途 |
| --- | --- |
| 拆分阶段 | 把混杂流程拆成清晰的处理阶段 |
| 提炼模块 / 类 | 从大块代码中分离出内聚单元 |
| 分离领域与基础设施 | 让业务逻辑不依赖技术细节 |
| 迁移到微服务 | 在边界稳定后拆分部署单元 |
| 引入防腐层 | 隔离外部模型，保护内部概念 |

大型重构的原则是**拆成一系列可交付的小步**，每一步系统都保持可用：

- 不要停下来重写。业务不会停，长时间不可交付的重构几乎必然被中断。
- 用并行运行与逐步切换（如新旧逻辑同时执行并比对结果）降低风险。
- 保留回退路径，每一步都要能独立回滚。

## 手法使用的通用纪律

1. **一次只做一种改变**，做完立即运行测试。
2. **先让测试通过，再继续下一步**；失败时立刻回退而不追加修复。
3. **小步提交**，让每次改动都容易被理解与回退。
4. **重构与功能改动分开提交**，避免混在一起。
