# 软件实现

实现是设计落地的过程。它不只是「把逻辑写成代码」，还包括**让代码在团队中可持续演进**：可构建、可审查、可重构。

## 实现阶段的两个目标

### 1. 正确的行为

由[验证](../verification/index.md)环节保证。实现者需要让代码**可被验证**，这直接影响结构选择。

### 2. 可持续的结构

代码会被反复阅读和修改，而**阅读时间远超书写时间**。因此实现的评价标准不是「写得有多聪明」，而是「别人多快能改对」。

判断实现质量的实用指标：

| 指标 | 说明 |
| --- | --- |
| 变更影响面 | 改一个需求要动几个文件 |
| 回归信心 | 改动后能否靠自动化测试确认没坏 |
| 上手时间 | 新成员多久能独立完成一次改动 |
| 重复度 | 同一条知识写了几处 |

## 一条纪律

**实现方案由写代码的人决定，但结构约束由团队约定。** 编码规范、分层规则、命名约定这类内容应当被自动化检查，而不是靠评审时的人工记忆——能被工具检查的规则，不要靠人。
