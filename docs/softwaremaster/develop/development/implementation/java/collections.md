# Java 集合框架

集合是日常使用频率最高的部分。选错集合带来的性能影响，往往比算法选择更大。

## 常用实现与代价

| 接口 | 常用实现 | 底层结构 | 关键特性 |
| --- | --- | --- | --- |
| List | ArrayList | 动态数组 | 随机访问 O(1)，中间插入 O(n) |
| List | LinkedList | 双向链表 | 两端操作 O(1)，随机访问 O(n) |
| Map | HashMap | 数组 + 链表 / 红黑树 | 期望 O(1)，扩容有抖动 |
| Map | LinkedHashMap | 哈希 + 双向链表 | 保持插入或访问顺序 |
| Map | TreeMap | 红黑树 | 有序，O(log n) |
| Set | HashSet / TreeSet | 基于对应 Map | 去重，不保证顺序 |
| Queue | ArrayDeque | 循环数组 | 双端操作高效 |
| Queue | PriorityQueue | 二叉堆 | 优先出队 O(log n) |

**实践中最常见的失误是被 LinkedList 的「插入快」误导**：真实场景下按索引查找、遍历操作远多于中间插入，而链表的内存不连续导致缓存命中率低，实际性能普遍不如 ArrayList。

## 需要特别注意的三点

### 1. 初始容量

HashMap 与 ArrayList 扩容时需要重建结构。可预估规模时**预先指定容量**能显著减少扩容开销。HashMap 还有负载因子问题，扩容会触发一次全量重哈希，在高并发下可能表现为延迟尖刺。

### 2. 不可变集合

对外返回集合时应当返回不可变视图或副本，否则调用方可以修改内部状态，破坏了封装。这一点在并发环境下尤其重要。

### 3. 遍历中修改

遍历时修改集合会抛出并发修改异常。需要删除元素时使用迭代器的删除方法，或先收集再统一处理。

## 并发场景

普通集合不是线程安全的。并发场景应当使用并发集合，而不是给普通集合加锁：

| 需求 | 推荐 |
| --- | --- |
| 高并发读、少量写 | 写时复制的列表 / 并发映射 |
| 高并发读写映射 | 分段或 CAS 实现的并发映射 |
| 无界 / 有界的生产者消费者 | 阻塞队列（区别在于满时是否阻塞） |

## 实践建议

- 默认用 ArrayList、HashMap、ArrayDeque；只有明确需要有序、优先队列等特性时才换实现。
- 预估规模时显式指定初始容量，避免扩容抖动。
- 对外暴露集合时使用不可变封装。
- 有界队列优先于无界队列：无界队列会把过载转化为内存耗尽。
- 缓存场景要为条目设置过期与容量上限，否则会退化为内存泄漏。
