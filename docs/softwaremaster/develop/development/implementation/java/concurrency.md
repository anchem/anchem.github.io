# Java 并发编程

Java 的并发能力建立在**内存模型**之上。不理解内存模型，同步代码就只能是「照着抄」。

## Java 内存模型要解决的问题

多线程环境下存在三个问题：**原子性、可见性、有序性**。内存模型定义了：

| 概念 | 含义 |
| --- | --- |
| 主内存与工作内存 | 线程可能使用本地副本，因此写入未必立刻可见 |
| happens-before | 定义操作之间的可见性与顺序关系 |
| volatile | 保证可见性与禁止部分重排，**不保证复合操作的原子性** |
| synchronized | 同时提供互斥与可见性 |
| final | 正确构造后保证对其他线程可见 |

**一个高频错误是把 volatile 当作锁使用**：它能保证单次读写的可见性，但无法保证「读 - 改 - 写」的原子性。计数器场景必须使用原子类或锁。

## 主要工具

| 工具 | 用途 | 注意 |
| --- | --- | --- |
| synchronized | 互斥 | 避免锁粒度过大；注意锁对象与锁升级 |
| volatile | 可见性 | 仅适用于单次读写或状态标志 |
| 原子类 | 无锁计数、CAS | 高竞争下自旋开销大 |
| 显式锁 | 可中断、可超时、可读写分离 | 必须在 finally 中释放 |
| 并发集合 | 线程安全容器 | 复合操作仍需自行保证原子性 |
| 线程池 | 任务执行管理 | 必须有界、必须显式拒绝策略 |
| 同步工具 | 门闩、屏障、信号量 | 用于协作而非互斥 |

## 线程池的关键决策

| 参数 | 影响 |
| --- | --- |
| 核心与最大线程数 | 并发能力与资源占用 |
| 队列类型与容量 | 过载时的行为：排队、拒绝还是阻塞 |
| 拒绝策略 | 超载时是丢弃、抛出还是由调用方执行 |
| 线程命名 | 排查问题时的基本要求 |

**无界队列是最常见的配置事故**：任务会无限堆积直到内存耗尽。所有生产环境线程池都应当有界，并配置明确的拒绝策略。

## 实践建议

- 先设计无共享结构，再用同步工具。共享可变状态是并发 bug 的根源。
- 临界区尽可能小，绝不在持锁期间做网络调用或磁盘操作。
- 为所有线程与线程池命名，这是排查并发问题的最低成本手段。
- 使用工具检测潜在的死锁与竞态，不要依赖「本地跑不出来」。
- 并发正确性需要测试与审查双重保障，因为竞态难以稳定复现。
