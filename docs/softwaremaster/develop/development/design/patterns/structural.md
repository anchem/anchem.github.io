# 结构型模式

结构型模式处理**对象如何组合成更大的结构**，核心手段是「在调用链中间插入一层」。

## 主要模式

| 模式 | 目的 | 使用信号 |
| --- | --- | --- |
| 适配器 | 转换接口以兼容既有代码 | 需要集成第三方或遗留组件 |
| 装饰器 | 在不改原类的前提下叠加行为 | 需要动态组合功能（如缓存、日志、重试） |
| 代理 | 控制对对象的访问 | 延迟加载、权限控制、远程调用 |
| 外观 | 为复杂子系统提供简化入口 | 需要降低外部对内部的依赖 |
| 组合 | 统一处理单个对象与组合对象 | 树形结构（菜单、组织架构、表达式） |
| 享元 | 共享细粒度对象以节省内存 | 大量重复的不可变小对象 |
| 桥接 | 分离抽象与实现，各自独立变化 | 两个维度同时扩展 |

## 最容易混淆的一对：装饰器与代理

两者都在调用链中插入一层，区别在于**意图**：

- **装饰器**关注「增加功能」，可以任意叠加，客户端通常知道自己在装饰；
- **代理**关注「控制访问」，通常由框架透明插入，客户端不感知。

区分意图很重要，因为二者对**顺序与数量的假设不同**：装饰器可叠加任意层，代理通常只有一层且位置固定。

## 组合与树形结构

组合模式的价值在于让调用方**不需要区分「单个」与「一组」**。凡是结构本身是树形的场景（组织架构、文件系统、表达式求值、权限继承），它都能显著简化调用方代码。

## 实践建议

- 适配器的边界应当是系统中最稳定的一层，把它隔离在基础设施层，不要让领域逻辑感知到被适配的对象。
- 装饰器叠加顺序会影响行为（缓存加在重试外层还是内层，含义完全不同），需要显式记录。
- 享元的前提是对象**不可变**。共享可变对象会引入难以排查的并发问题。
- 外观层容易被当成垃圾场——它应当只做转发与编排，不承载业务规则。
