# 行为型模式

行为型模式处理**对象之间的职责分配与通信方式**，是数量最多、使用最广的一类。

## 主要模式

| 模式 | 目的 |
| --- | --- |
| 策略 | 封装可互换的算法 |
| 模板方法 | 在父类固定流程，子类实现步骤 |
| 观察者 | 一对多通知，发布订阅 |
| 责任链 | 请求沿链传递，逐个处理或放行 |
| 状态 | 用对象表达状态及其转移 |
| 命令 | 把请求封装成对象，支持排队、撤销、记录 |
| 迭代器 | 统一遍历方式，屏蔽内部结构 |
| 中介者 | 用中心对象协调多方交互 |
| 备忘录 | 捕获并恢复对象内部状态 |
| 访问者 | 在不改元素类的前提下新增操作 |
| 解释器 | 用对象结构表示文法并求值 |

## 使用要点

### 策略与状态的区别

结构相似但语义不同：

- **策略**：由外部选择一种算法，对象本身不改变「身份」；
- **状态**：对象的行为随内部状态改变，转移通常由对象自身驱动。

把状态机写成策略，会在转移逻辑上处处别扭。

### 责任链与中间件

责任链模式是现代 Web 框架中间件、网关过滤器、消息处理管道的基础结构。它的关键设计点是**链上节点的顺序与终止条件**，这两点必须在设计中明确，否则会出现「请求被静默丢弃」这类难查问题。

### 观察者的隐患

观察者把调用方与被调用方解耦，但引入了新问题：

- **通知顺序不确定**，不要依赖它；
- **异常传播**：一个观察者抛异常是否影响其他观察者，需要明确策略；
- **内存泄漏**：忘记取消订阅会导致对象无法回收；
- **调试困难**：调用关系在运行时才确定，静态分析看不到。

## 实践建议

- 优先考虑用语言的一等函数替代单方法策略与命令（如用函数对象代替策略类）。
- 观察者场景明确异常隔离策略，通常应当独立捕获，避免一个订阅者影响全部。
- 责任链要显式定义顺序与终止条件，并为其编写测试。
- 状态机优先使用显式建模（状态与转移表），而不是用嵌套条件散落各处。
