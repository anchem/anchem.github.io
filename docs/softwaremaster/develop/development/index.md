# 软件开发

软件开发把原理转化为可运行、可维护的系统。这里的六个模块构成一条**从约束到细节**的链条。

## 包含内容

| 模块 | 回答的问题 | 典型产出 |
| --- | --- | --- |
| [软件工程](./engineering/index.md) | 多人如何协作、过程如何组织 | 流程、规范、自动化流水线 |
| [软件架构](./architecture/index.md) | 系统由哪些部分构成、边界在哪 | 架构决策、模块划分、质量属性方案 |
| [软件设计](./design/index.md) | 模块内部如何组织 | 类与接口设计、模式应用 |
| [软件实现](./implementation/index.md) | 代码怎么写、怎么演进 | 可运行代码 |
| [软件验证](./verification/index.md) | 怎么确认它是对的 | 测试与质量证据 |
| [软件安全](./security/index.md) | 怎么保证它不被攻破 | 威胁模型、安全编码、防护措施 |

## 顺序为什么是这样

```
工程 → 架构 → 设计 → 实现 → 验证 → 安全
```

这条顺序对应**返工成本的递增**：越靠前的决策影响面越大，也越难撤回。

- **工程**决定协作方式，影响所有人的日常节奏；
- **架构**决定系统骨架，改一次要动全局；
- **设计**决定模块边界，影响局部的改动成本；
- **实现**是最容易调整的层面；
- **验证**决定可信度，缺了它就只能靠运气上线；
- **安全**贯穿始终——它不是某一阶段的补丁，而是必须在架构与设计阶段就落地的约束。

## 一条主线

六个模块服务于同一个目标：**让系统在持续变化中保持可控**。判断一次技术决策是否值得，标准不是「是否先进」，而是它让未来的改动更容易还是更难。
