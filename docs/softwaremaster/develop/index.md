# 开发：怎么做

开发把[需求](../requirement/index.md)变成**真实可运行的系统**。它回答的是：用什么原理支撑、用什么结构承载、用什么手段实现与验证。

## 本板块管什么

| 分组 | 回答的问题 |
| --- | --- |
| [ICT 理论基础](./foundation/index.md) | 底层原理：计算机怎么工作、网络怎么通信、数据怎么存储 |
| [软件开发](./development/index.md) | 工程实践：从工程化、架构、设计到实现、验证、安全 |

## 为什么先有理论基础

理论基础看似与应用开发距离很远，实际上它决定了**技术方案的天花板**：

- 不懂[并发与一致性](./foundation/distributed/consistency.md)，就无法判断一个缓存方案是不是正确；
- 不懂[索引与存储结构](./foundation/database/storage.md)，调优只能靠试；
- 不懂[网络往返的成本模型](./foundation/network/tcp-ip.md)，就分不清哪些优化有意义。

理论的价值不在于被直接使用，而在于**判断力的下限**：它让你知道哪些方案从原理上就走不通，不必等到线上验证。

## 为什么软件开发的六个模块是这个顺序

```
工程 → 架构 → 设计 → 实现 → 验证 → 安全
```

这是一条**从约束到细节**的链条：工程约束决定协作方式，架构决定系统骨架，设计决定模块内部结构，实现决定代码形态，验证决定可信度，安全贯穿始终但不是某一阶段的补丁。

这个顺序也对应了返工成本的排序：**越靠前的问题，发现得越晚代价越大**。架构选错，实现再优雅也无法挽救。
