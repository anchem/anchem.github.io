# 阶段一学习材料：认知与装备（约 1 周）

本文是《[一人公司的 AI 实战进阶计划（AI Agent 学习路线）](ai-agent-one-person-company-plan.md)》第一阶段的配套学习内容，按七天推进：**前两天读懂 Agent 与工具地图 → 第三天写任务书 → 第四至六天搭起并打磨第一位「员工」 → 第七天复盘与验收**。

:::tip 本阶段唯一的成功标准
不是“我读懂了”，而是“**我派出去一个任务，它做完了，我能说清它哪里做对、哪里跑偏**”。所有阅读、选型、对比，都是为这一个动作服务的。
:::

## 零、开始之前：三件事先确认 {#before-start}

### 0.1 前置检查 {#prereq}

- [ ] 你能写出“你是谁 + 做什么 + 要什么样”的提示词（基础篇水平）；
- [ ] 你有“AI 会犯错、重要信息要核实”的意识，不会把 AI 的回答直接当结论；
- [ ] 你准备好每周投入 5 小时以上，且能接受“某周完全没时间”；
- [ ] 你愿意在**没有回报**的情况下先做一个月——这一阶段是纯投入期，产出是文档不是收入。

**四项目前有两项不成立时**：先回到[基础篇](ai-learning-plan-for-beginner.md)补完提示词与验证习惯，再回来。这不是退步，是省时间。

### 0.2 三种时长节奏 {#rhythm}

本材料的[七天逐日清单](#daily-plan)是按**每周约 8 小时**设计的。其它两种情况这样调：

| 节奏 | 每周投入 | 怎么用这份材料 | 必须做的动作 |
| --- | --- | --- | --- |
| **保命档** | 约 5 小时 | 把七天清单合并成 2～3 天（见[5.4 最小版本](#daily-plan)） | 跑通一次调研 + 写验收记录 |
| **标准档** | 约 8 小时 | 按七天清单走 | 全部 |
| **加速档** | 12 小时以上 | 提前完成清单，多出的时间加做练习题与第二次试运行 | 全部 + 加做一次同类任务对比 |

:::warning 两条节奏纪律
1. **保命档一周最多用 2 周**，第三周必须回到标准档；
2. **不追进度，追完成度**——七天清单拖成 10 天没关系，跳过“试运行”不行。
:::

## 一、本阶段学习目标 {#goals}

| 维度 | 一周后达标线 | 对应本材料章节 |
| --- | --- | --- |
| 认知 | 不看资料，2 分钟内讲清 Agent 的“四件套”和两个典型翻车点 | [第三章 观念校准](#concepts) |
| 选型 | 能说出至少 6 个国内工具分属哪一层、各自适合什么任务 | [第二章 工具地图](#tools) |
| 表达 | 写出一份四要素齐全、可直接执行的任务书 | [第四章 任务书](#task-brief) |
| 实操 | 配好并跑通 1 个“市场调研员”Agent，产出可核查的调研成果 | [第五章 试运行](#handson) |
| 产出 | 完成《我的一人公司构想》一页纸（允许粗糙） | [第六章 产出模板](#deliverable) |

:::note 本阶段的定位
第一阶段**不追求做出产品**。它只做三件事：①把“Agent 能干什么、不能干什么”的预期校准到真实水平；②把工具箱装好，后面不再为“用哪个”反复纠结；③把**任务书**这个贯穿全程的手艺练到能用。
:::

## 二、工具地图：先看清有哪些“员工”可选 {#tools}

### 2.1 三层能力 vs 五层工具 {#three-vs-five}

规划里说过“Agent / 工作流 / 自动化”三者不同，选型表又分了五层。把这两件事叠在一起看，就是下面这张**总图**：

| 工具层 | 你要它干的事 | 2026 年国内代表 | 一句话定位 |
| --- | --- | --- | --- |
| 底层大模型 | 提供“大脑” | DeepSeek、通义千问（Qwen）、豆包（豆包大模型）、混元、GLM、Kimi | 一般不当产品用，通过上面的应用来用 |
| 对话应用 | 你问我答、写初稿 | 豆包、腾讯元宝、Kimi、通义千问（夸克入口）、文心一言 | 上手最快，适合日常问答与写作 |
| 深度检索 | 带来源的调研 | 秘塔 AI 搜索、纳米 AI 搜索、豆包“深度研究”、Kimi 探索版 | **写报告、做行业研究的主力**，信源可追溯 |
| Agent 编排平台 | 给 Agent 配工具、写工作流、发成应用 | 扣子（Coze）、Dify、腾讯云 ADP、阿里百炼、智谱清流 | 做出**能对外发布**的 Agent |
| 桌面 / 通用智能体 | 一个目标端到端跑完，直接交成品 | **WorkBuddy**（腾讯，本计划默认）、360 纳米 Work、Manus（海外，慎用） | 像“办公桌总管”，能读写你的文件 |
| 自动化工作流 | 按排好的步骤链自动跑 | 扣子工作流、n8n、影刀 RPA、简道云 | 几乎不做推理，靠触发执行 |
| AI 编程 | 帮你写代码 | Trae、通义灵码、CodeBuddy、文心快码、CodeGeeX | 阶段三主力 |
| 无代码应用生成 | 说话就生成应用 | 秒悟 Meoo、百度秒哒、腾讯微搭、简道云 | 阶段三另一条路线 |
| 图像 / 视频 | 出图、出片 | 即梦、可灵、通义万相、剪映 AI、Canva 可画 | 阶段三、四用 |

:::warning 不要把这张表当购物清单
**新手最常见的错误是同时开八个工具，结果每个都只用懂 20%。** 本计划的策略是：**每一层只留一个主力**，其余留作备选。下面的推荐就是“只留一个”的结果。
:::

### 2.2 本计划的推荐配置 {#recommended-stack}

如果你不想研究工具，直接用这一套。它覆盖了本计划六个阶段的全部场景，且**总成本可以做到 0 元**。

| 角色 | 推荐工具 | 为什么选它 | 成本 |
| --- | --- | --- | --- |
| **一号员工（总管家）** | **WorkBuddy** | 桌面端通用智能体，能直接读写你电脑上的文件、跑命令、生成文档与网页，可交付成品而不只是“给建议”；本阶段的试运行就用它 | 有免费额度，按量计费 |
| 日常对话 + 写初稿 | 豆包 | 中文语感最自然、响应快、免费额度充足 | 免费 |
| 带来源的调研 | 秘塔 AI 搜索 | 引用标注最细，能输出带大纲的研究报告，适合阶段二 | 免费 |
| 对外发布的 Agent | 扣子（Coze） | 零代码、节点编排成熟、能发布到微信/网页挂件，阶段四、五、六主力 | 免费额度够用 |
| 长文档与合同 | Kimi | 长文本总结与问答最强 | 免费 |
| 微信生态与公众号内容 | 腾讯元宝 | 可直接检索公众号、视频号内容，结论口径相对诚实 | 免费 |
| AI 编程 | Trae | 免费、中文友好，**SOLO 模式**对零基础最友好 | 免费 |
| 无代码生成应用 | 秒悟 Meoo | 一句话生成含前端、后端、数据库的完整应用并一键上线，非技术用户门槛最低 | 有免费额度，Pro 档约 9.9 元/月（活动价） |
| 图像 | 即梦 | 角色一致性最好，免费额度每日可用 | 免费额度 |
| 视频 | 即梦 / 剪映 AI | 即梦出片质量靠前，剪映负责剪辑与字幕 | 免费额度 |

:::info 工具会变，方法不变
上面每个工具的具体能力、免费额度、界面位置**都会在几个月内改变**。所以本材料在每个关键动作旁都写了**“这一步在做什么”**，而不只是“点哪个按钮”。工具换了，你照样能做。
:::

### 2.3 如果你只想用一个工具 {#one-tool-route}

完全不想装新工具的人，走这条路：

> **WorkBuddy 一个工具，跑完全部六个阶段。**

WorkBuddy 能覆盖检索、写作、编程、文件处理、数据整理这些环节。它做得不够好的地方有两个，需要补充：

1. **对外发布型 Agent**（让陌生人直接和你的机器人对话）——这一环需要扣子这类平台，或者退一步用“手动回复 + WorkBuddy 起草”替代；
2. **真实出图/出视频**——这一段需要即梦/剪映，或者退一步用文字方案 + 免费图库替代。

**这两处缺口不影响主线推进**，材料里都给了“降级方案”。

### 2.4 三层概念的辨析表 {#three-concepts}

| 概念 | 通俗解释 | 判断口诀 | 例子 |
| --- | --- | --- | --- |
| Agent | 会“想”的决策者，看情况决定下一步 | **步骤不固定** | 客服 Agent 判断“这个问题要不要转人工” |
| 工作流 | 提前排好的步骤链，顺序固定 | **步骤固定，节点可拖** | 收到表单 → 自动发欢迎信 → 记入表格 |
| 自动化 | 由时间或事件触发的执行 | **有触发条件** | 每天 8:00 自动跑一遍数据汇总 |

**一句话记住**：Agent 决定“怎么做”，工作流规定“按什么顺序做”，自动化决定“什么时候开始做”。三者常常叠在一起用——一个客服 Agent（想）调度一条工作流（顺序），由用户发消息触发（自动化）。

### 2.5 成本粗估：先会算账，再谈规模 {#cost-basics}

规划把它列为五条边界之一（“有成本”）。你不需要精确到分，但要知道**量级**，否则某天会看到意料之外的账单。

| 概念 | 通俗说法 | 粗估方式 |
| --- | --- | --- |
| token | 计费单位，中文大约 **1 个汉字 ≈ 1～2 个 token** | 一篇 1000 字中文 ≈ 1500～2500 token |
| 一次调研任务 | 多轮检索 + 输出约 2000 字 | 大约几万 token 量级 |
| 一次长文写作 | 输入资料 3000 字 + 输出 2000 字 | 大约 1 万 token 量级 |
| 一次 30 轮客服对话 | 含知识库检索 | 大约几千到几万 token，视上下文长度而定 |

:::warning 三条估算提醒
1. **上下文越长越贵**——把整个历史对话反复塞回去，成本会成倍上升。任务做完就开新对话；
2. **价格差异极大**——不同模型单价可能相差十倍以上。简单任务（分类、打标、格式转换）用小模型，**这是最有效的一招控本手段**；
3. **具体单价与免费额度随时会变**，不要在材料里记价格，而是**记在你自己的 `00-工具箱.md` 里**：每个工具的免费额度是多少、超量怎么计费、在哪看账单。

**阶段一的成本预期：基本可以做到 0 元。** 有正收益之前不要为工具付费——这条原则贯穿全计划。
:::

## 三、观念校准：Agent 的四件套与五条边界 {#concepts}

### 3.1 四件套 {#four-parts}

| 组成部分 | 通俗说法 | 缺了它会怎样 |
| --- | --- | --- |
| 大模型 | 大脑 | 它不懂你说什么，也做不了推理 |
| 规划能力 | 做计划的人 | 你给一个大目标，它只会回你一个通用答案，不会拆步 |
| 工具调用 | 手脚 | 它只能“说”，不能“做”——查不到、改不了、发不出 |
| 记忆 | 记事本 | 每轮对话都从零开始，你的偏好和项目进度全部丢失 |

**自检方法**：随便找一个你用过的 AI 应用，问自己“它这四样各是什么”。例如豆包：大脑是豆包大模型，规划体现在“深度思考”模式，工具是联网搜索与图片生成，记忆是它的对话历史与用户偏好设置。

:::info 关于“记忆”，一个常见的误解
很多工具的“长期记忆”其实只是**你的偏好设置 + 最近若干轮对话**，并不是真的记住了整个项目。**跨会话、跨工具的长期记忆，通常需要你自己维护**——这也是为什么本计划从阶段一就要求你建“我的一人公司”文件夹：**你的文件夹，就是这套系统最可靠的那份记忆。**

实践建议：每个阶段结束，把关键结论（公司构想、机会卡片、指标定义）单独存成一份**“项目事实”文档**，每次开新对话时先把它贴给 AI。这一招能显著减少“它又忘了”的挫败感。
:::

### 3.2 五条边界与它们的“现场表现” {#five-limits}

规划里给了五条现实。这一节把每条现实翻译成**你一定会遇到的具体现象**，以及**遇到时该做什么**。

| 现实 | 你会看到的现场 | 你该做的动作 |
| --- | --- | --- |
| 会出错、会幻觉 | 它给出一份“2025 年市场规模 47 亿元”，但点开来源发现是另一回事 | 要求它**逐条给链接**，你抽查 2～3 条；数据只用来定方向，不用来下结论 |
| 工具调用会失败 | 搜索超时、代码报错、接口 403，它卡住后开始“猜” | 把报错原文贴回去，明确说“先解决这个报错，不要继续往下做” |
| 会曲解指令 | 你要 800 字报告，它给你 3000 字还附了 PPT 大纲 | 验收时**对着任务书逐条核对**，多做的删掉、少做的补上 |
| 越复杂越需要人盯 | 前 3 步都对，第 7 步开始悄悄改了你的假设 | 在**关键节点设卡**：调研完成先看结论，再让它写正文 |
| 有成本 | 连续跑几小时，月底账单超出预期 | 先免费额度、后付费；长任务前先问一句“这个任务大概要消耗多少” |

:::danger 阶段一就要建立的三个肌肉记忆
1. **要来源**：任何事实性数字，都要它给链接；没有链接的数字，一律写“待核验”。
2. **设卡点**：长任务拆成 2～3 段，每段结束先验收再继续。
3. **留退路**：让它改动文件之前，先确认有备份，或者让它新建文件而不是覆盖原文件。
:::

### 3.3 你的新角色：派活的人 {#new-role}

| 旧角色（对话助手时代） | 新角色（Agent 时代） |
| --- | --- |
| 我该怎么说它才懂 | 我该怎么把这件事讲清楚 |
| 它答得对不对 | 它交的活能不能用 |
| 一次对话解决一个问题 | 一次委托推进一件任务 |
| 出错了就重问 | 出错了先定位是哪一步错的 |

**一个立刻能用的转换公式**：把“帮我看看这个”改成“**你要交付什么、给谁看、什么范围内、做到什么程度算合格**”。

## 四、任务书：把目标讲清楚的手艺 {#task-brief}

### 4.1 四要素模板 {#brief-template}

```text
【角色】你是______，服务于______。
【目标】请完成______，最终交付______（格式：______）。
【约束】只使用______；不要______；必须______；字数/时长______。
【验收标准】做到以下条件视为合格：
  1. ______
  2. ______
  3. ______
【先确认】开始之前，先用三句话复述你理解的
  任务目标、交付物和边界；我确认后你再动手。
```

最后一条【先确认】是**新手最值得加的一句提示词**。它把“跑偏了才发现”变成“动手前就发现”，性价比极高。

### 4.2 三份完整任务书示例 {#brief-examples}

**示例一：市场调研员（本阶段试运行用，可照抄）**

```text
【角色】你是一名严谨的行业研究员，为一位准备做"面向小学生的 AI 编程课"的
        独立创业者服务。
【目标】调研中国"小学生 AI 编程教育"市场现状，交付一份 800～1200 字的
        调研简报（Markdown），结构为：市场规模与增速 / 主要玩家与模式 /
        家长付费决策的关键因素 / 三条对创业者可执行的机会判断。
【约束】只使用可公开查证的来源；每一个事实性数字后面必须标注来源链接；
        查不到的数据写"未找到公开来源"，禁止推测填充；不写客套话；
        不使用"我们认为"这类无依据的表述。
【验收标准】
  1. 至少 8 个事实性数字，每个都带可点击来源；
  2. "主要玩家"一节至少覆盖 4 家，含各自模式与定价区间；
  3. 三条机会判断每条都能追溯到简报中的某组数据；
  4. 全文不超过 1200 字。
【先确认】开始之前，先用三句话复述你理解的任务目标、交付物和边界；
          我确认后你再动手。
```

**示例二：文案改写员（阶段四会用到，先熟悉结构）**

```text
【角色】你是一位小红书账号的内容编辑，账号定位"教上班族用 AI 省时间"。
【目标】把下面这段 400 字的产品介绍，改写成 3 条小红书笔记，每条
        150～250 字。交付格式：每条含标题（不超过 20 字）、正文、
        3～5 个话题标签。
【约束】口语化、第一人称、不用"赋能/闭环/抓手"这类词；不承诺效果
        （不写"保证""一定"）；不使用夸张数字；不出现联系方式。
【验收标准】
  1. 三条笔记切入角度互不重复（如：痛点场景 / 对比实测 / 清单干货）；
  2. 每条都有具体的场景细节，不空谈；
  3. 没有一条出现夸大宣传用语。
【素材】______（把产品介绍粘在这里）
```

**示例三：数据整理员（阶段五会用到）**

```text
【角色】你是一位数据分析助理。
【目标】读取 attached 的 30 条用户反馈（CSV），交付一份归纳报告：
      好评集中在哪 3 类 / 吐槽集中在哪 3 类 / 被提到但产品没做的隐藏需求 /
      建议优先处理的 2 件事及理由。
【约束】每条结论后面标注它来自哪几条反馈的编号；不得加入文件中没有的
        信息；不得把"用户客气话"（如"整体不错"）归入好评。
【验收标准】
  1. 每条结论都能指到原始反馈编号；
  2. 隐藏需求至少 2 条；
  3. 优先处理建议给出排序理由（影响人数 × 严重程度）。
```

:::tip 用【先确认】省下半数返工
把上面三份任务书都加上【先确认】，你会发现 AI 经常在复述阶段就暴露了理解偏差——这一步不花时间，省的是后面全部重做的时间。
:::

### 4.3 任务书的三个常见毛病 {#brief-antipatterns}

| 毛病 | 反面例子 | 改法 |
| --- | --- | --- |
| 目标含糊 | “帮我调研一下这个市场” | 补上：给谁看、交付什么格式、多少字、含哪几节 |
| 只有约束没有验收 | “要严谨、要专业” | 换成可数的标准：至少 8 个数字、每个带链接、不超过 1200 字 |
| 一次塞十个要求 | 一条任务书里同时要调研、写方案、做图、写代码 | 拆成 3～4 次委托，每次一个交付物 |

### 5.1 主路线：用 WorkBuddy 搭「市场调研员」{#route-workbuddy}

**目标**：让 WorkBuddy 完成一次真实的调研任务，并留下完整的验收记录。

**操作步骤（逐步照做）**

| 步骤 | 你做什么 | 这一步在做什么 |
| --- | --- | --- |
| 1 | 在本地建一个文件夹 `我的一人公司/阶段一/`，后面所有产出都放这里 | 建立产出归档，也是你的过关凭证 |
| 2 | 新建一个空白 Markdown 文件 `01-任务书-市场调研员.md`，把[示例一](#brief-examples)的任务书抄进去，按你的真实想法改掉行业 | 把“想清楚”变成“写下来”，写不下来就是还没想清楚 |
| 3 | 打开 WorkBuddy，把任务书**整段**贴进去（不要只贴一句“帮我调研 XX”） | 检验任务书是否足够自足——如果 AI 要反问很多，说明任务书不合格 |
| 4 | 观察它是否做了【先确认】这一步；如果做了，认真读它的复述，指出偏差后让它继续 | 这一步就是“设卡”，是本次学习最重要的动作 |
| 5 | 它开始检索、整理、写报告，你**不要插手**，但记录它做了哪些动作 | 观察“它怎么拆任务、怎么用工具” |
| 6 | 拿到报告后，**抽查 2～3 条来源链接**，逐条打开核对是否真实支持正文说法 | 幻觉识别训练，这是判断力的核心练习 |
| 7 | 新建 `02-验收记录.md`，按[5.3 节模板](#review-template)写下你的验收意见 | 验收本身是学习，也是产出 |
| 8 | 把报告存为 `03-调研报告.md`，保留 AI 的原始版本不要改 | 保留原始件，是对比“改前改后”的依据 |

:::warning 第 6 步不许跳过
**抽查来源是这次试运行的唯一“考题”。** 如果你只是读了报告觉得“写得挺像样”，这次试运行等于没做。真实的经验是：新手第一次抽查，十有八九能抓到至少一处 AI 张冠李戴的数据。
:::

### 5.2 备选路线：秘塔 / 豆包 / 扣子 {#route-alternatives}

| 如果你…… | 就换成 | 差异在哪里 |
| --- | --- | --- |
| 没有 WorkBuddy 使用额度 | 秘塔 AI 搜索 | 检索与来源标注是它的强项，但不会直接生成文件，需自己复制整理 |

| 想顺便体验“发布型 Agent” | 扣子（Coze） | 在扣子里新建 Bot，粘贴任务书到“人设与回复逻辑”，上传资料建知识库，调试后即可预览对话 |

**扣子版的具体操作路径**：

1. 打开扣子首页 → 用手机号登录 → 「新建 Bot」→ 填写名称（如“市场调研员”）；
2. 在「人设与回复逻辑」中粘贴你的任务书全文；
3. 在「插件」中添加“搜索”类插件（让它能查实时信息）；
4. 在「知识库」上传你认为可信的背景资料（可选）；
5. 在右侧对话框测试，重点验证三件事：**答案带来源吗 / 超纲问题会不会编 / 连续多轮会不会串台**；
6. 调整 3～5 轮后，把对话记录截图存档。

## 九、带到阶段二的资产 {#handover}

阶段一结束时，你的文件夹里应该有这样五个“可交付、可复用”的东西。**它们不是作业，是工具**——阶段二每一步都会用到。

| 资产 | 文件 | 阶段二会怎么用它 |
| --- | --- | --- |
| 工具箱清单 | `00-工具箱.md` | 选调研与分析工具时直接照表用；账单与额度也查这份 |
| 《公司构想》一页纸 | `我的公司构想.md` | **直接作为行业扫描任务的输入**（扫描哪个方向由它决定） |
| 任务书模板 | `01-任务书-市场调研员.md`（含 v1/v2 对比） | 阶段二的任务书 A/B/C 都是在它基础上改的 |
| 验收经验 | `02-验收记录.md` | 抽查来源、识别存疑的方法，阶段二全程复用 |
| 认知底稿 | 你自己的三行复盘 | 用于回看“我当时是怎么判断的” |

### 阶段收尾的两行字 {#phase-note}

在 `02-验收记录.md` 末尾补两行（这是阶段二的起点）：

```text
这个方向我最想验证的一个假设是：______
我目前最不确定的是：______
```

:::tip 一个被低估的动作
**把“我最不确定什么”写下来。** 阶段二的全部工作，本质上就是去回答这个不确定。写清楚了，你就不会在访谈时问一堆跟假设无关的问题。
:::
