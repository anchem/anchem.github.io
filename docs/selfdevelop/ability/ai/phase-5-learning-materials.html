阶段五学习材料：运营与迭代（约 3 周）

本材料是《一人公司的 AI 实战进阶计划（AI Agent 学习路线）》第五阶段的配套学习内容。

零、开始之前​

0.1 前置检查​

  • 你手上有 ≥ 3 条真实的用户反馈原话（阶段四的第一批用户）；
  • 你的 MVP 有一个能持续被访问的入口（链接 / 文档 / 微信群任一）；
  • 你愿意每周固定花 1 小时看数据并做决定（这件事本阶段叫“周会”，是最重要的习惯）；
  • 你接受一个事实：三周后你可能发现这条路不太行。能发现它，也是本阶段的合格产出。

0.2 时长节奏​

逐日清单按每周约 8 小时设计：

节奏每周投入怎么用
保命档约 5 小时用最小版本：10 天完成 2 轮闭环 + 2～3 份周报；客服降级为“手动回复 + 话术模板”
标准档约 8 小时按二十一天清单走
加速档12 小时以上加做一次完整用户声音分析 + 把客服 Bot 的边界测试做透

一、本阶段学习目标​

维度三周后达标线对应本材料章节
客服客服 Bot 上线，能答常见问题，复杂/情绪/付款问题一律转人工第三章
分析完成 1 轮用户声音分析，且做了人工复核第四章
指标定义 3 个最小指标，每个都有分子分母与统计口径第五章
迭代完成 2～3 轮迭代，每轮有完整记录与指标对比第六章
周报3 份迭代决策周报（AI 出数据与建议 + 你写三行）第七章
判断写下停损判据；如需要，真的执行过一次降级或换向第八章

二、工具选型​

环节推荐工具怎么用降级方案
客服 Bot扣子（Bot + 知识库 + 工作流）知识库放 FAQ，工作流处理“收集信息/转人工/通知我”手动回复 + 保存话术模板
微信生态客服腾讯元器 / 企业微信 + 扣子若用户主要在微信/企微里手动回复
反馈汇总飞书多维表格 / 金山表格所有反馈与线索汇总到一张表一张 Excel
反馈分析Kimi（长文本）/ WorkBuddy / DeepSeek归纳好评、吐槽、隐藏需求手动分类计数
数据看板飞书多维表格（视图/分组/统计）每周自动汇总指标手动统计并在表格里算
周报生成WorkBuddy读数据表 → 出“数据 + 建议”周报手动整理 + AI 润色
迭代记录同一张迭代表每轮一条记录，字段固定一篇 Markdown

先把“反馈表”和“迭代表”的字段定死（见10.1），后面每周只是往里填。

三、客服自动化​

3.1 FAQ 手册怎么写​

来源直接用阶段二～四收集到的真实提问，不要自己猜用户会问什么。

类别典型问题答案要求
它是什么“这是干什么用的？”一句话说明，不用技术名词
怎么用“怎么开始？”“要不要注册？”3～5 步，动词开头
价格“多少钱？”“有免费版吗？”只讲公开信息，不承诺折扣
边界“能帮我做 XX 吗？”明确说“目前不支持”，不模糊
效果“能省多少时间？”用你自己或用户的具体经历，不承诺效果
隐私“我的数据你会看到吗？”如实说明，越具体越可信
售后“不好用能退吗？”明确规则

FAQ 手册模板：

# FAQ 手册 v____     更新日期：____

## 一、它是什么
Q：______
A：______

## 二、怎么用
Q：______
A：______

## 三、价格与购买
Q：______
A：______

## 四、能力边界（重要）
Q：你们能帮我做 ______ 吗？
A：目前不支持。原因是 ______。如果你需要这个，可以先告诉我，我会记录。

## 五、数据与隐私
Q：______
A：______

## 六、不在这里的问题
统一回复："这个问题我帮您记录下来，稍后人工回复您。"
写 FAQ 的同时，一定要配一条“拒答规则”

知识库类应用最危险的行为不是答不好，而是检索不到时自己编。FAQ 写完只是第一步，还必须在人设里写死一句话：

“如果知识库中没有相关答案，直接回答‘这个问题我帮您记录下来，稍后人工回复您’，不要用你自己的想法回答。”

测试方法：问一个 FAQ 里绝对没有的问题（如“明年会涨价吗”“你们老板是谁”），确认它拒答而不是编。上线后每周抽查 5 条真实对话，这是唯一能发现“它开始编了”的办法。

顺序不能反：先保证它不会瞎答，再考虑让它答得快、答得多。答错的伤害远大于答不上来。

3.2 转人工规则​

触发情况关键词/信号示例Bot 应做的事
付款与退款付、付款、退款、发票、怎么买不给承诺，直接转人工
投诉与情绪投诉、骗子、骗人、垃圾、太差、差评先安抚，立即转人工并通知你
涉及金额与合同报价、合作、代理、签合同转人工
能力边界外提问命中“你们能帮我做 XX 吗”且答案是“不支持”明确说“不支持”，可登记需求
Bot 答不上来连续 2 轮未命中知识库（回复里出现“我帮您记录”“不确定”等字样）/ 用户重复问同一个问题第 3 次 / 用户明确说“你答非所问”转人工
涉及隐私与安全索要他人信息、上传敏感材料拒绝并转人工
“置信度低”不能作为触发条件

很多材料会写“置信度低时转人工”，但绝大多数 Agent 编排平台并不把这个数值暴露给你，你没法据此设条件。必须换成你能实际观测到的信号：

可观测信号怎么配 / 怎么判
知识库未命中在人设里要求“检索不到时必须输出固定句：我帮您记录，稍后人工回复”，然后在工作流里匹配这句话 → 触发转人工
关键词命中消息里出现“退款、投诉、骗子、合同、报价、发票”等词 → 直接转
轮次计数同一用户连续 3 轮未解决问题 → 转
用户明确要求出现“转人工”“找人”“真人”等词 → 转

在这四条里，最可靠的是“关键词 + 未命中固定句”这两条。上线前用3.3 测试清单逐条验证它们真的会触发。

转人工时对用户说什么（模板）：

“这个问题我需要人工来回答，我已经帮您记下来了，稍后会有专人联系您。抱歉让你等一下。” （如果是投诉类，前面先加一句：“非常抱歉给你带来不好的体验。”）

付款、投诉、对外承诺必须由人处理，不能交给 Bot 自行应答，这是底线清单里“人兜底”的落地。

3.3 客服 Bot 上线前的测试清单​

测试类型具体怎么测通过标准
常见问题把 FAQ 里每个问题都问一遍优先引用知识库答案，不编造
超纲问题问一个你和它都没答案的问题（如“明年会涨价吗”）明确说“不确定，转人工”，不猜
边界问题故意问“能打五折吗”“我要投诉你们”不擅自答应，走转人工
多轮连贯连续问 5 轮相关问题不串台、不丢失上下文
语气检查用挑剔的用户口吻提问不失礼、不油滑、不啰嗦
出错兜底断网/接口失败时有友好提示，不白屏

调优口诀：答非所问 → 补知识库；语气不对 → 改人设；该转向却硬答 → 补转人工规则。

四、用户声音分析​

4.1 分析任务书​

【角色】你是用户研究分析师。
【目标】阅读我提供的全部用户反馈（聊天记录、评论、问卷开放题），交付：
  1. 好评集中的 3 类（每类注明来自哪几条反馈编号）；
  2. 吐槽集中的 3 类（同样标注编号，并标注严重程度：阻断使用 / 影响体验 / 吹毛求疵）；
  3. **被提到但产品没做的需求**（≥ 2 条）；
  4. 与我的假设矛盾的证据（**这一节最重要，不许省略**）。
【约束】只使用文件里出现的原话，不得推测、不得合并语义不同的反馈；
        禁止把"挺好的""整体不错"这类客套话归入好评；
        每条结论必须能指到具体反馈编号。
【验收标准】每条结论都能回溯到原始记录；第 3、4 节不得为空。

4.2 四种常见误判​

误判AI 常犯的具体表现人工复核方法
把客气话当满意把“还不错”“挺好用的”列为正面评价只有“主动推荐给别人”“重复使用”“说了具体哪里好”才算正面
过度聚类把 5 个人说的 5 件不同的事归成“一个共同痛点”回原始记录数一遍：只出现在 1 份里的，不能叫“高频”
忽略情绪强度把“有点小问题”和“完全用不了”同等对待给每条吐槽标严重程度：阻断使用 / 影响体验 / 吹毛求疵
把需求当结论用户说“希望有导出功能”，直接当成必做需求追问“你想拿导出去做什么”——真实需求往往在目的里，而不是功能里

4.3 反馈表的字段​

字段说明
编号F001、F002……
日期收到日期
来源客服对话 / 评论区 / 问卷 / 访谈 / 熟人
用户标识代号，不用真名
原话必须原话，不改写
类别好评 / 吐槽 / 需求 / 疑问 / 咨询
严重程度阻断使用 / 影响体验 / 吹毛求疵
涉及功能哪个环节
是否已处理待处理 / 已改进 / 不处理（写明理由）

五、北极星指标：把“看数据”落到数字上​

5.1 三个最小指标与定义方法​

指标分子分母时间窗怎么数
① 落地页 → 线索转化率留下联系方式的人数打开落地页的独立访客数每周表格里“留资日期”计数 ÷ 落地页后台访问数
② 试用 → 付费转化率付费人数（或口头承诺付费人数）完成过一次完整使用的独立人数每周试用名单表 ÷ 付费名单表
③ 内容触达 → 咨询数主动来咨询的人数内容总曝光量（或阅读量）每条内容反馈表里来源=评论区的记录数

数据不足时的替代指标（阶段五早期很常见）：

替代指标定义
每周咨询数本周主动来问你的人数（去重）
每周试用人数本周实际用过一次的人数
每周留存上周用过的人里，这周又用了一次的人数

对一人公司，比转化更该盯着的是留存：用过的人里有多少会再来用（以及会不会续费）。

指标可落地定义
周留存上周用过的人里，这周又用了一次的人数 ÷ 上周用过的人数
复购 / 续费已付费的人里，下一周期又付费的人数 ÷ 已付费人数

如果你三周下来周留存接近 0，不要急着加内容、加投放，先做第八章的降级判断（换卖点 / 换形态）。把资源投在一个留不住人的东西上，是最常见的浪费。

指标定义的三个常见坑
  1. 分母不写清。“转化率提升了”，是相对于谁？独立访客还是页面浏览？两个口径能差一倍。
  2. 时间窗不一致。上周按 7 天数，这周按 5 天数，比出来没意义。
  3. 口径中途改变。表结构变了却继续对比新旧数据。改口径要在迭代记录里注明“本期起口径变更，不与上期直接比较”。

六、迭代飞轮：每周只改一个核心问题​

6.1 四步循环​

步骤谁做做什么输出
收集AI + 人汇总本周全部用户声音，归类、标严重程度本周问题清单（按 人数 × 严重程度 排序）
判断人拍板对照北极星指标，选出只改一个的问题，并写下“我预期改完哪个指标动”本周迭代决定（一句话）
执行Agent按阶段三的开发委托模板做改动新版本 + 备份
验证人看指标有没有动；没动就如实记录并分析原因迭代记录一条

一次改 5 个地方的后果是：你永远不知道是哪个改动起了作用。三周下来你会有 3 个数据点，但一个因果都说不出来。一次一个，宁可慢。

6.2 怎么判断“改哪个最值钱”​

排序维度判断方法
影响人数有多少人遇到这个问题（看反馈表计数）
严重程度是“阻断使用”还是“吹毛求疵”
与指标的关联改它能影响北极星指标吗？改一个跟指标无关的小细节，就是白忙
改动成本半天能改完的，优先做

一张简单的判断表（把候选问题填进去）

候选问题影响人数严重程度关联指标成本综合排序

6.4 三周迭代节奏​

周收集判断执行验证

七、AI 周报与人的三行​

7.1 AI 周报任务书​

【角色】你是我的运营数据助理。
【目标】读取本周数据（访客、线索、试用、付费、反馈条数）与迭代记录，
        输出一份周报，含四节：
  1. 本周数据（表格，含与上周的对比）
  2. 本周用户说了什么（归类，各附 1～2 条原话）
  3. 我的建议：下周只做哪一件事，及理由
  4. 需要我警惕的信号（指标异常、投诉上升、某个渠道失效等）
【约束】数据只来自我提供的文件，不得推测；不得把"可能""也许"写成结论；
        建议只给 1 条，不要罗列 10 条；不确定的地方明确说"数据不足，无法判断"。

7.2 人只写三行​

AI 出数据与建议，但决策必须你写。每周在周报末尾手写三行：

这周的关键决定：______
下周只做一件事：______
需要警惕的信号：______
不要让 AI 替你写这三行

这三行是你的判断，也是本阶段真正要训练的东西。如果你让 AI 写，你省下的不是时间，而是这整门课最核心的收获。AI 可以给建议，但决定必须由人做，并署名。

8.2 三种降级/换向方式​

方式保留什么换掉什么成本什么时候选
换卖点产品、人群价值主张、说辞最低有人用但没人付费；说明价值表达不对
换人群产品、能力目标用户中有人夸但没人用；说明人群选错
换形态你验证过的痛点产品形态（如从工具改成服务）最高痛点真实但形态不匹配（如用户其实想要“你帮我做”而不是“给我工具”）

规划里写得很清楚：“硬扛不是坚持，是浪费；知道何时收手，是经营能力，也是学习目标之一。”

判断“该不该换”的一个实用问题：如果再给我三周，我能说清这三周会改什么、为什么这次会不一样吗？如果答案是“继续说不上来”，就是该换的信号。

参考答案与解析​

练习 1（参考答法）

  • 定义：本周客服对话中，由 Bot 转给人工处理的对话数占全部对话数的比例；
  • 分子：本周触发转人工的对话数；分母：本周客服对话总数（去重到人会话）；
  • 时间窗：每自然周（周一 00:00 ~ 周日 24:00）；数据来源：客服平台的对话记录导出；
  • 过高（如大于 50%）说明 FAQ 与知识库覆盖不够；过低（接近 0）可能是转人工规则失效，投诉类问题被 Bot 自行应答了。

练习 2

  1. “还不错”是客套话，不能作为满意度证据 → 复核：只有主动推荐、重复使用、说出具体优点的才算正面；否则归为“中性”。
  2. “导出功能”是用户提的功能诉求，未必是核心需求 → 复核：回到原话数人数；并追问“导出后你打算做什么”找真实目的。
  3. 把严重程度差异极大的两条反馈“综合”成一句结论，等于丢掉最重要信息 → 复核：给每条吐槽标“阻断使用 / 影响体验 / 吹毛求疵”，分开统计。
  4. 把需求直接当结论，且未经追问 → 复核：追问使用场景与频率，判断是否值得做；同时写下“不做的理由”。

十二、本阶段自检清单​

  • FAQ 手册已完成（≥ 15 条，来源是真实提问）；
  • 客服 Bot 上线，或手动 SOP 已写成；
  • 转人工规则 ≥ 6 条，且测试过三类边界问题；
  • 反馈表与迭代表字段已定死，并已开始填写；
  • 北极星指标卡完成：3 个指标各有分子、分母、时间窗、数据来源与基线值；
  • 至少设 1 个反向指标；
  • 完成 ≥ 1 轮用户声音分析，且做过人工复核（剔除了伪高频项）；
  • 完成 2～3 轮迭代，每轮有完整的“收集 → 判断 → 执行 → 验证”记录；
  • 每轮迭代都有“预期指标变化”与“实际变化”的对比；
  • 有 1 个以上完整闭环可作为证据链：“因为用户说了 X，我改了 Y，指标 Z 从 A 变成 B”；
  • 3 份迭代决策周报已完成，每份含 AI 数据与建议 + 你的三行；
  • 停损判据已提前写下；
  • 已对照停损判据做出“继续 / 降级 / 换向”的明确判断（如需要，已执行一次）；
  • 阶段五文件夹整理完毕，复盘三行已写。

最常见的未达标是“没有足够多的真实用户，2 个闭环跑不起来”。处置原则是降低闭环门槛，而不是放弃闭环：

  1. 用熟人和阶段二的访谈者凑出 3～5 人的小样本，明确告诉他们“你们就是我的第一批测试用户”；
  2. 指标换成“每周试用人数”“每周咨询数”这类数得出来的量，不要硬算百分比；
  3. 把“用户提意见 → 我改 → 他再看一眼”当作一个闭环。只要出现过一次完整的“因为他说的我改了，他确认变好了”，这个闭环就成立。
