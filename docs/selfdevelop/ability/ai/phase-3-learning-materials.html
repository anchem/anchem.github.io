阶段三学习材料：创造 MVP（约 3 周）

本材料是《一人公司的 AI 实战进阶计划（AI Agent 学习路线）》第三阶段的配套学习内容。

这三周要把一张卡片变成一件真实存在、别人能自己打开使用的东西。判断标准只有一个：找一个不认识你的人，不解释，让他自己用起来。

动手前认清两件事：第一版一定丑，能用比好看重要；卡住是常态，不是你的问题，卡住时该做的是缩小范围，不是硬扛。

零、开始之前​

0.1 前置检查​

  • 你的产品机会卡片七栏已填满，其中第②栏用的是用户原话；
  • 你有 ≥ 1 个愿意深度试用的承诺者（阶段二留下的名单）；
  • 你已确定产品形态与开发路线（见决策树）；
  • 你接受"三周后交出来的东西可能只完成一半"，这正常，不算失败。

0.2 别把第一天耗在注册上​

零基础者最容易忽略的一道隐形门槛是账号与资质：

门槛你需要先确认的事
实名认证多数国内平台需要绑定手机号，部分功能需实名（身份证）
免费额度额度会变化，注册当天就记进 00-工具箱.md
企业资质涉及支付、收款、小程序发布等功能往往需要企业主体；第一版请绕开需要企业资质的路径（如用"留联系方式"代替在线支付）
域名与备案用平台自带的一键部署域名通常不需要；自己买域名指向国内服务器需要备案，第一版不建议自购域名
发布时间小程序类存在审核周期，不要把它排在最后两天做

0.3 时长节奏​

逐日清单按每周约 8 小时设计：

节奏每周投入怎么用
保命档约 5 小时用最小版本：只做"输入 → 输出"两个功能，10 天交付
标准档约 8 小时按二十一天清单走
加速档12 小时以上加做一次可用性测试 + 把视觉包装做得更完整

一、本阶段学习目标​

维度三周后达标线对应本材料章节
决策能说清自己为什么选这条开发路线（不是"随便挑的"）第二章 路线决策
拆解把想法拆成 3～5 个最小功能，并说清哪个是"没它就不能用"第三章 需求拆解
开发完成一轮完整的"拆需求 → Agent 生成 → 人验收 → 迭代"第四章 开发循环
包装有产品名、一句说明、基本视觉（Logo 或配色）第五章 包装
上线产出可分享的链接或可打开的成品第六章 上线
验收1～2 位陌生人无指导完成一个任务（一级达标）第七章 可用性测试
验证争取到"愿意付费"表态或进入付费意愿队列（尽力目标）第七章 7.3

二、开发路线：先选对路，再动手​

2.1 三种起步形态与对应工具​

形态是什么适合谁2026 年推荐工具预计上手难度
信息产品电子书、课程、模板包、付费专栏有内容/经验积累的人，最快启动腾讯文档 / WPS AI（写与排版）、Canva 可画 / 稿定（封面与版式）最低
网页小工具一个解决具体问题的网页应用想做出"可交互的东西"的人秒悟 Meoo / 百度秒哒（无代码）；Trae / 通义灵码（AI 编程）中
自动化服务用 Agent 帮客户做重复工作手上已有客户或明确需求的人扣子（Coze）工作流 + 飞书/金山表格；影刀 RPA中

怎么选：先问自己三个问题。手上已经有什么？有内容积累选信息产品，有明确客户选自动化服务，都没有但有想法选网页小工具。想不想碰代码？完全不想走无代码，愿意花时间学走 AI 编程。三周内最能交付的是什么？最诚实的答案是"最小的那一个"，宁可做小不要做大。

2.2 路线决策树​

你的 MVP 是什么？
├─ 主要是"知识/经验/模板"类内容
│   └─ → 信息产品：腾讯文档 / WPS AI 排版 + Canva 封面
│
├─ 是一个"输入 → 处理 → 输出"的小工具，逻辑简单
│   ├─ 完全不想写代码 → 秒悟 Meoo / 百度秒哒（说话生成全栈应用，一键上线）
│   └─ 愿意学一点     → Trae（SOLO 模式）/ 通义灵码
│
├─ 需要"实时对话/自动应答/编排多步流程"
│   └─ → 扣子（Coze）：Bot + 知识库 + 工作流
│
└─ 是"帮某类客户做重复劳动"的服务
    └─ → 扣子工作流 + 人工交付；或 影刀 RPA 处理固定桌面操作

2.3 三条路线的具体起步步骤​

路线 A：无代码生成（零基础优先）

步骤操作说明
1打开秒悟 Meoo 或百度秒哒，注册登录都用手机号，有免费额度
2用一段话说清你要什么：谁用、解决什么、有哪几个页面、每页放什么这段话的写法见第三章 3.3
3生成后立即预览，逐个功能点一遍生成快，但第一版一定有不合意的地方
4用逐条修改的方式提意见："登录页去掉手机号，只要邮箱"一次只说一件事，改完再看
5满意后一键部署，拿到可分享的公网链接这一步无代码平台的优势
6让 2 个朋友打开链接试一下见第七章

路线 B：AI 编程（愿意投入时间者）

先做 1 天热身，热身不通过就不要进入正式开发。

热身步骤做什么通过标志
1用 Trae（或通义灵码）打开一个空文件夹工具就绪
2说"帮我做一个网页，上面有一个按钮，点一下显示当前时间"生成代码并能在本地预览
3故意让它报错：改成"点一下显示昨天北京时间，带时区"出现报错或结果不对
4把报错原文完整贴回去，说"先解决这个报错，不要改别的地方"它修好，你看到"生成 → 报错 → 丢回去 → 跑通"的完整循环
5复盘：刚才那一轮你做了什么、它做了什么能说清这个循环

热身通过的标准：你不再害怕报错，知道"报错原文 + 一句约束"就是最好的提问。

路线 C：扣子 Bot / 工作流

步骤操作
1新建 Bot，写清人设、语气、边界（阶段二的任务书写法照样适用）
2建知识库，上传你的资料（产品说明、FAQ、模板），开启自动调用
3加插件（搜索、时间等），必要时加工作流（收集信息 → 写进表格 → 通知你）
4右侧对话测试：正常问题能答、超纲问题会拒答或转人工、多轮不串台
5发布到可用渠道，拿到可分享入口

扣子这类平台里，上下文长度与知识库切片方式会直接影响回答质量。文档排版越清晰（标题分层、一段一件事），检索命中率越高。上传前花 10 分钟整理资料来源，比上线后反复调提示词有效得多。

三、需求拆解：从想法到 3～5 个功能​

3.1 拆解四步法​

步骤做什么时长输出
1. 写全量把"想要的功能"全部写出来，不设限（通常 15～30 条）30 分钟功能清单
2. 划红线逐条问："没有它，用户是不是就完全用不了？"不是就砍掉30 分钟红线功能（通常 2～4 条）
3. 定闭环把红线功能串成一条最短可用路径：用户从进入到最后拿到结果要走哪几步30 分钟一条 3～5 步的路径
4. 排顺序按"没有它就走不通"排序，形成开发顺序15 分钟开发排期

3.2 一个完整的拆解示例​

想法：一个帮技术组长整理周报的网页工具。

步骤 1：全量清单（18 条）步骤 2：划线判断
用户注册登录✂ 砍——第一版不注册，用本地存储
粘贴零散记录✅ 红线——没有它什么都做不了
一键生成结构化周报✅ 红线——这是产品本身
可编辑生成结果✅ 红线——AI 一定会出错，必须能改
导出 Markdown / 复制✅ 红线——用户要拿去用
历史记录列表⏸ 延后——第二版
周报模板可切换⏸ 延后
团队共享⏸ 延后
数据统计图表✂ 砍——没人要求过
付费订阅⏸ 延后——先用"加微信"测意愿
...（其余 8 条同理）——

步骤 3：最短可用路径

打开网页 → 粘贴零散记录 → 点生成 → 看到结构化周报 → 复制走
       （4 步，其中 2 步是用户操作、1 步是系统、1 步是用户取用）

步骤 4：开发顺序

  1. 页面骨架 + 粘贴框（1 天）
  2. 接入模型，粘贴能出结果（1～2 天）
  3. 结果可编辑（1 天）
  4. 复制 / 导出（半天）
  5. 打磨：加载状态、错误提示、手机端能看（2～3 天）

3.3 给无代码平台的"生成提示语"模板​

帮我做一个网页应用，名字叫"______"。使用者是______。
它要解决的是：______。

页面只有 1 个，从上到下依次是：
1. 顶部标题和一句说明；
2. 一个大的多行输入框，提示文字是"把你这周的零散记录粘进来"；
3. 一个"生成周报"按钮；
4. 下方一个结果区域，生成后显示整理好的内容，可以直接编辑；
5. 一个"复制"按钮。

不需要登录、不需要数据库、不需要历史记录。
风格：干净、留白多、按钮明显、手机上也好看。

迭代时的提意见模板：

只改一处：______（具体到哪个元素、改成什么）。
其他所有部分保持不动。
改完告诉我改了哪里。
不提"再优化一下"

"优化一下""让它更好看"这类指令必然带来大面积改动，可能把你已验收的部分改坏。每一轮都要能说清"改了哪一处"。

四、Agent 化开发：小步快跑的循环​

4.1 循环的四步与每步的验收动作​

步骤你做什么验收动作用时占比
拆需求从开发顺序里取下一个最小改动用一句话说清这一轮要改什么5%
Agent 生成把这一件事写清楚给 Agent，附上"不要改别的地方"看它改了几个文件，超出范围就让它回退15%
人验收实际点一遍——不是看代码，是用一遍记录"能用/不能用/哪一步卡"20%
迭代有问题就贴报错或现象；没问题就进入下一个最小改动通过后立刻备份这一版60%

生成 15%、验收 20%、调试迭代 60%，这个比例和多数人的直觉相反，记住它你就不会在第三小时怀疑自己。

4.2 提问模板（开发专用）​

让 Agent 加一个功能

【当前状态】现在页面能做到：______（一句话）。
【只做这一件事】请增加：______。
【不要动】不要修改______和______，不要重构现有代码。
【做完告诉我】改了哪些文件、怎么验证这一处能工作。
【如果有报错】把报错原文贴回来，先解决报错，不要绕过它。

出了问题时

【现象】我点______，结果是______，我期望的是______。
【报错原文】
（完整粘贴，不要截断、不要改写）
【我的判断】我怀疑问题在______，但不确定。
【要求】先告诉我可能的原因（不超过 3 条），我确认后再改代码。

4.3 备份纪律（必需）​

做法适合谁具体操作
手工另存无代码平台用户每完成一个可用版本，在平台内"复制一份"，命名 v1-可用-日期
文件夹快照AI 编程新手每完成一个可用版本，把整个项目文件夹复制一份并改名
Git 提交愿意学一点的人用 Trae/通义灵码的对话让它帮你执行 git init 与提交；每验收通过一次就提交一次
最少做到"手工另存"

不要在没有备份的版本上让 AI 做大改动，这是初学者最常发生的灾难：让它"重新生成一遍"，结果把已经调好的部分全改坏了，而且没有退路。

五、包装：让它看起来像个东西​

5.1 包装四件套与做法​

元素做什么推荐工具注意
产品名好记、好念、能搜到让 AI 出 20 个候选，你挑 3 个，问 5 个人避开已有商标与大厂产品名
一句话说明我帮谁解决什么，怎么做让 AI 出 10 个版本，你改不超过 40 字，说人话
Logo / 视觉一个图形 + 一套配色即梦 / Canva 可画 / 稿定商用前确认授权
界面文案按钮、提示、空状态让 AI 按你的语气写，你再改提示语要告诉用户"下一步做什么"

5.2 界面文案的三个关键位（最容易被忽略，影响最大）​

位置反例正例
输入框提示"请输入内容""把你这周的零散记录粘进来，一句话一行也行"
按钮文字"提交""生成周报"
空状态（空白）"还没有内容。先用上面的框试一条，看看效果。"
出错提示"错误：500""生成失败了。可能是网络问题，请再点一次；如果一直失败，把这段话发我。"

5.3 商用版权：四条自查​

商用素材四条自查
  1. 图像：生成式平台的条款是否允许商用？免费档生成的内容授权是否不同？
  2. 字体：界面与封面用的字体是否免费商用？中文字体是重灾区，很多"免费"字体只免费个人使用；
  3. 图标/素材：图标库的授权类型（是否需署名）；
  4. 代码：AI 生成的代码可能包含开源片段，注意许可证要求。

做不到全部确认时，选最保守的方案：用平台自带字体与素材、用自己生成且标明可商用的图。第一版不需要完美，但需要干净。

六、上线：拿到可分享的链接​

你的形态上线方式具体做法
无代码生成的应用平台内一键部署秒悟 Meoo / 秒哒 生成后点击部署，得到公网链接
自己写的静态网页静态托管GitHub Pages / Vercel / Netlify；让 AI 帮你写部署步骤
需要后端的小应用云服务阿里云/腾讯云轻量服务器；或微信云开发
扣子 Bot平台内发布发布为网页挂件或对应渠道，拿到分享入口
信息产品文档或 PDF腾讯文档 / WPS 生成分享链接，设置权限
自动化服务不需要链接交付物是"跑出来的结果"，但要有演示记录（截图/录屏）
上线前的三件小事
  1. 在手机上打开一次，很多第一版在手机上完全错位；
  2. 换一个没登录你账号的浏览器打开，确认不需要你的登录态；
  3. 把链接发给一个朋友，看他能不能打开，本地预览可以、公网打不开是常见问题。

七、验收：可用性测试与付费验证​

7.1 可用性测试五步法（本阶段最重要的一小时）​

步骤做什么关键纪律
1. 找 1～2 个不认识你（或只认识但不了解这个项目）的人熟人可以，但要严格保密项目背景不要选"怕伤你面子"的人
2. 只给一句话任务："请用它完成______"不解释、不演示、不指路你一旦开口，数据就失效了
3. 全程闭嘴观察，记录三件事① 他先点了哪里；② 他在哪里停了超过 10 秒；③ 他问了什么问题他的每一个问题都是产品缺陷
4. 结束后再问三句"你觉得这是干什么用的？""哪一步最别扭？""你会再来用吗？"只听，不辩解
5. 当天把卡点整理成一张清单，按"人数 × 严重程度"排序下一个迭代就改排名第一的不改你的判断，只改产品

找不到陌生人时，按可行性顺序试这几个渠道：

渠道具体话术特点
阶段二的承诺者"上次你说愿意试试，我做出来了，能麻烦你花 15 分钟用一下吗？"最顺，但不算"陌生人"，结论要打折扣看
互测社群"我在做一个 XX，想找 3 个人互测——你出测试任务我帮你测，我出测试任务你帮我测。"有效，双方都受益，最容易约到

7.3 付费验证​

一级（可用性）通过后，再往前走一步。三种可用的轻量做法：

做法怎么做拿到什么证据
明确表态问："如果正式版收 ____ 元，你会买吗？"意愿级

拿不到付费证据时，常见原因有三类，各自对应不同处置：

卡在哪里可能的原因下一步
有人用，但都说"免费的话会用"价值不够稀缺，或人群不对换人群，或把价值做成"省下来的时间/钱"可量化
没人愿意点开链接一句话说明没讲清，或渠道不对重写说明，换渠道（阶段四解决）
用了一次就不再用没有"反复使用"的理由找"高频场景"重做功能，或改成一次性交付物

假装乐观没有价值。把这三类原因如实写下，阶段五才有依据。

三条通用纪律：

  1. 贴完整原文，不要截断，不要手动改写报错（改写常常丢掉关键的路径与行号）；
  2. 一次只解决一个错，报错常有连环，先解决第一个，再跑一次看第二个；
  3. 要求先分析再动手："先告诉我可能原因（不超过 3 条），我确认后再改代码"。这一句能防止 AI 在你的项目里乱改一通。
两个必须记住的动作
  • 改之前先备份（见 4.3）。报错不可怕，可怕的是"改着改着把能跑的部分也改坏了，而且回不去"；
  • 卡住超过 40 分钟就换策略：把问题缩小到最小可复现的例子（让 AI 单独写一个 20 行的示例），跑通再往项目里搬。不要在复杂项目里直接调一个你看不懂的错。
