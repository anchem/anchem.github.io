# 阶段二学习材料：找对方向（约 2 周）

本材料是《[一人公司的 AI 实战进阶计划（AI Agent 学习路线）](ai-agent-one-person-company-plan.md)》第二阶段的配套内容。这两周只做一件事：动手做产品前先搞清楚谁真的疼、疼到什么程度、肯不肯掏钱。最终判据不是调研了多少，而是能拿出一张填满七栏的机会卡片，每条都能指到谁说的、证据在哪。

## 零、开始之前 {#before-start}

### 0.1 前置检查 {#prereq}

- [ ] 你手上有《我的一人公司构想》一页纸（哪怕是粗糙的）；
- [ ] 你的任务书四要素能写全，且试运行过一次，知道【先确认】的作用；
- [ ] 你至少有一个带来源的检索工具已能使用（秘塔 / 元宝 / 豆包任一）；
- [ ] 你做好了一个心理准备：这两周大概率会听到“我不太需要这个”，那不是坏消息，是花钱都买不到的信息。

### 0.2 时长节奏 {#rhythm}

[逐日清单](#daily-plan)按每周约 8 小时设计。调整方式：

| 节奏 | 每周投入 | 怎么用 |
| --- | --- | --- |
| 保命档 | 约 5 小时 | 用[最小版本](#daily-plan)：扫描 + 抽查、竞品矩阵、5 场访谈、填卡片，压到 5 天 |
| 标准档 | 约 8 小时 | 按十四天清单走 |
| 加速档 | 12 小时以上 | 加做问卷（回收 ≥ 30 份）+ 多找 2 场访谈 + 多拿 1 个承诺级证据 |

## 二、工具选型：这两周用哪些 {#tools}

### 2.1 本阶段工具清单 {#tool-list}

| 环节 | 推荐工具 | 能力 | 降级方案 |
| --- | --- | --- | --- |
| 行业扫描（带来源） | 秘塔 AI 搜索 | 引用最细，学术/政策类强 | 豆包“深度研究”（引用较粗） |
| 公众号/视频号内容 | 腾讯元宝 | 可搜微信生态，结论较诚实 | Kimi 长文本总结 |
| 长文档与政策文件 | Kimi | 长文本总结与问答最强 | 元宝 |
| 多来源交叉汇总 | WorkBuddy | 把多轮检索整理成矩阵/卡片/报告 | 手动复制到表格 |
| 访谈录音转写 | 通义听悟 / 讯飞听见 / 剪映 | 转写够用，省记录时间 | 手机语音转文字 |
| 访谈整理与洞察 | WorkBuddy / Kimi / DeepSeek | 归纳、高频词、需求聚类 | Kimi |
| 问卷发布与回收 | 腾讯问卷 / 金数据 / 问卷星 | 免费额度够 20～100 份 | 微信群 + 表格手工统计 |
| 价格敏感度测算 | 让 AI 用 Van Westendorp 法分析问卷 | 把付费意愿变成区间 | 手工取中位数 |

阶段二要拿证据向别人证明这事有人需要，所以检索只选每条结论能点开核对的；快但不给来源的只做思路启发，不当证据。

### 2.2 本阶段的委托任务书 {#briefs}

任务书 A：行业扫描

```text
【角色】你是一名严谨的行业研究员。
【目标】对"______"这个方向做行业扫描，交付一份 1500 字以内的扫描报告，含四节：
      1. 行业现状（规模、增速、驱动因素）
      2. 主要玩家（至少 6 家的名称、模式、定价区间）
      3. 竞争格局（头部集中度、玩家差异化的点）
      4. 三条趋势信号（每条注明它是"确证"还是"推测"）
【约束】每一个事实性数字必须附来源链接；同一结论尽量给两个独立来源；
        查不到的写"未找到公开来源"，禁止用相近数据顶替；
        区分"公开披露"与"媒体估算"，并标明。
【验收标准】
  1. ≥ 12 个带来源的事实，来源可打开且内容支持正文；
  2. 至少 3 处标注了"两来源不一致"的地方（如果存在）；
  3. 趋势信号里明确区分确证与推测。
【先确认】动手前先用三句话复述任务目标、交付物与边界。
```

任务书 B：竞品拆解

```text
【角色】你是产品分析师。
【目标】针对以下 5 个竞品：______，交付一张竞品对比矩阵（Markdown 表格），
        维度为：目标用户 / 核心功能 / 定价 / 获客方式 / 用户主要抱怨 /
        我认为它没做好的地方。表格后附 300 字总结：这 5 家共同没解决什么。
【约束】"用户主要抱怨"必须来自可查证的公开评论或评价，并给出来源链接；
        不得凭印象填写；找不到就写"未找到公开评价"。
【验收标准】5 个竞品行齐全；抱怨栏 100% 带来源；总结里明确指出一个"空位"。
```

任务书 C：访谈提纲生成（这一步只是让 AI 出草稿）

```text
【角色】你是一位用户研究顾问。
【目标】围绕"______（我要了解的问题）"，面向"______（人群）"，
        设计一份 45 分钟的用户访谈提纲。交付：12～15 个问题，
        分成四段（背景 / 现状与替代方案 / 痛点与代价 / 付费与承诺）。
【约束】严格遵守三条访谈原则：
  1. 问过去的具体行为，不问未来的假设（禁用"如果……你会……吗"）；
  2. 问他们遇到过什么麻烦，不问"你觉得我的想法怎么样"；
  3. 不引导、不暗示答案，不给选项。
【验收标准】逐题自查：每题都能对应上面三条原则中的至少一条；
             有问题违反原则的，必须标出来并给出改写版本。
```

:::warning 关于任务书 C
AI 出的提纲只是草稿。你必须自己逐题读一遍、改成自己的话，并删掉所有“如果……你会愿意吗”式的假设题。这类题目给出的答案几乎没有信息量，人们对自己未来行为的预测能力很差。你在访谈提纲上的判断力，直接决定这两周拿到的是证据还是客套话。
:::

## 三、市场扫描与竞品分析 {#market-scan}

### 3.1 市场扫描四步法 {#scan-steps}

| 步骤 | 做什么 | 时长 | 产出 | 判断点 |
| --- | --- | --- | --- | --- |
| 1. 铺开 | 用任务书 A 跑一轮行业扫描 | 2 小时 | 扫描报告 v1 | 只看，不下结论 |
| 2. 证伪 | 抽查 ≥ 3 条来源，剔除不成立的 | 1 小时 | 扫描报告 v2 | 存疑率超 40% 就换信息源重跑 |
| 3. 追问 | 对“主要玩家”逐个补做任务书 B | 3 小时 | 竞品矩阵 | 找玩家共同没做好的地方 |
| 4. 收敛 | 写 3 条趋势信号，各标“确证/推测” | 1 小时 | 一页趋势判断 | 至少 1 条“确证”，否则深度不够 |

:::warning 抽查不是走过场
打开第一条链接、看到标题对得上就认定“核验通过”，是新手典型错误。正确做法是逐句比对：正文写“2025 年市场规模 47 亿元”，来源里必须真有一句口径、年份都一致的 47 亿元。把“整个教育科技市场”当成“少儿编程市场”，是最常见的隐蔽错误。
:::

### 3.2 竞品对比矩阵模板 {#competitor}

| 维度 | 竞品 1 | 竞品 2 | 竞品 3 | 竞品 4 | 竞品 5 |
| --- | --- | --- | --- | --- | --- |
| 名称 / 链接 | | | | | |
| 目标用户 | | | | | |
| 核心功能（一句话） | | | | | |
| 定价 | | | | | |
| 获客方式 | | | | | |
| 用户主要抱怨（附来源） | | | | | |
| 我认为它没做好的地方 | | | | | |

填完必答的三个问题：

1. 五家共同没解决的是什么？（这是最常见的空位）
2. 五家共同做对了的是什么？（这是你必须达到的及格线）
3. 如果我只能在一件事上比它们好，是哪件事？（这就是你机会卡片里的“凭什么是我们”）

用户抱怨（“太贵”“太难上手”“客服不理人”“数据导不出”）往往就是新玩家的切入口，所以这一栏必须来自真实的公开评论，不能靠 AI 推测。

## 四、用户访谈：本计划最不能省的一步 {#interview}

### 4.1 三条铁律 {#interview-rules}

| 铁律 | 反面做法 | 正确做法 |
| --- | --- | --- |
| 问过去，不问未来 | “如果有一款这样的产品，你会用吗？” | “过去三个月，你为这个问题做过什么？花了多少时间或钱？” |
| 问生活，不问想法 | “你觉得我这个点子怎么样？” | “上一次遇到这个麻烦是什么时候？当时怎么处理的？” |
| 问代价，不问态度 | “你觉得这个问题重要吗？” | “为了解决它，你试过哪些办法？哪些没用？为此花过钱吗？” |

受访者会对你客气，只有问回真实经历才编不出来。

### 4.2 访谈提纲模板（45 分钟版）{#interview-outline}

```text
# 用户访谈提纲 · 主题：______    日期：____  受访者代号：R__

## 开场（2 分钟）
- 说明目的：我在了解【某类人】在【某个场景】上的真实做法，不是推销产品。
- 声明：没有标准答案，说真话对我帮助最大；我可以记录吗？
- 征得录音同意。

## 第一段：背景（5 分钟）
1. 你现在主要在做______？做了多久？
2. 一周里，和______相关的事大概占用你多少时间？
3. 你平时用什么工具/办法处理这件事？

## 第二段：现状与替代方案（10 分钟）
4. 最近一次遇到【具体场景】是什么时候？能具体讲讲当时的过程吗？
5. 当时你是怎么解决的？用了什么？
6. 这个办法你觉得哪里还行、哪里别扭？
7. 你还试过别的方法吗？为什么没继续用？

## 第三段：痛点与代价（15 分钟）
8. 这件事最让你烦的是哪一点？
9. 上一次因为这个问题造成损失（时间/钱/情绪）是什么情况？
10. 你为解决它花过钱吗？花了多少？花在哪？
11. 如果这个问题一直不解决，会怎样？
12. 你觉得理想的解法应该是什么样？（让他描述，不要你介绍）

## 第四段：付费与承诺（10 分钟）
13. 你现在为类似的事每月大概花多少钱？
14. 如果有一个东西能解决它，你觉得合理的价格区间是______到______？
15. 什么价格你会觉得"太贵不会买"？什么价格你会觉得"这么便宜是不是有问题"？
16. 如果我这两周做出一版能用的，你愿意先付定金 / 预购 / 深度试用 30 分钟吗？
    （三选一，给出具体动作和时间）

## 收尾（3 分钟）
- 我有没有漏问什么？你觉得我还应该去问谁？
- 能否介绍 1 位有同样困扰的朋友？（转介绍是最快的样本来源）
- 告知：我会在______前给你反馈结论。
```

### 4.3 访谈记录模板 {#interview-record}

```text
# 访谈记录 · R__       日期：____  时长：__ 分钟  方式：线上 / 线下

## 基本信息（不带真实姓名，只写代号）
- 身份/职业：____   相关经验年限：____
- 是否为目标人群：是 / 否（否也要留记录，用于对照）

## 逐题要点（只记原话，不写自己的解读）
| 问题 | 受访者原话（摘录） |
| --- | --- |
| | |

## 三个最有信息量的原话（直接摘，不改写）
1. "______"
2. "______"
3. "______"

## 他当前的实际投入（时间/钱/工具）
- ______

## 付费意愿信号
- 价格锚点：他认为合理区间 ____ ～ ____；太贵 ____；太便宜 ____
- 承诺层级：无 / 口头愿意 / 加等待名单 / 愿意深度试用 / 愿意付定金
- 具体动作与时间：______

## 我这次的失误（哪一问问错了、哪次引导了对方）
- ______
```

转写工具（通义听悟/讯飞听见/剪映）省时间，但：① 转写前说明用途并征得同意；② 先脱敏成“R01”“A 公司”再传，不上传含真实姓名/公司/联系的录音。这是[底线清单](ai-agent-one-person-company-plan.md#guardrails)里“隐私与安全”的落地。

### 4.4 访谈排期与找人的四个来源 {#recruit}

| 来源 | 怎么做 | 成功率 | 注意 |
| --- | --- | --- | --- |
| 已有熟人（相关从业者） | 私聊说明目的，约 30～45 分钟 | 高 | 熟人容易客气，更要严格执行“问过去”三铁律 |
| 垂直社群 | 以“我在研究 XX，想听听真实做法”身份出现 | 中 | 先贡献价值再提请求，不要一进群就发问 |
| 转介绍 | 每场访谈结尾问“还有谁有类似困扰” | 中高 | 最优质的来源，务必每次都问 |
| 内容平台评论区 | 找在相关话题下发过真实抱怨的人，私信请教 | 低但质量高 | 话术要真诚，说明不是推销 |

两周排期建议：第 1 周完成 3 场，第 2 周完成 2～3 场，留出缓冲。约不到人时不要延后整体进度，可以用“问卷 + 3 场访谈”的组合补齐。

### 4.5 访谈后必做：AI 归纳 + 人工复核 {#synthesis}

把 5 份访谈记录一次性交给 AI（Kimi 或 WorkBuddy），用这份任务书：

```text
【角色】你是用户研究分析师。
【目标】阅读我提供的 5 份访谈记录，交付一份洞察报告：
  1. 高频出现的痛点 Top 5（每条注明出现在哪几份记录的第几题）；
  2. 用户当前使用的主要替代方案，及各自被吐槽的点；
  3. 被反复提到但市面上产品明显没满足的需求（≥ 2 条）；
  4. 付费意愿的分布情况（多少人处于哪个承诺层级）；
  5. 与我的假设相矛盾的证据（这一节最重要，不要省略）。
【约束】只使用记录中出现的内容，不得推测补充；
        每条结论必须标注来源记录编号；
        禁止把客套话（如"挺好的""有需求"）算作正面证据。
【验收标准】每条结论都能回溯到具体记录；第 5 节至少列出 1 条矛盾证据，
            如果确实没有，写"未发现矛盾证据"并说明检索方式。
```

AI 归纳最易犯两错：把客气话当证据（“挺有用”不算，花过时间/钱才算）；过度聚类，把 5 人的不同事硬归成一个“共同痛点”。复核：每条“高频”回原始记录数一遍，只出现 1 份的不算高频。

## 五、问卷：把访谈结论拿去量化（可选但推荐）{#survey}

### 5.1 什么时候做问卷 {#when-survey}

| 情况 | 建议 |
| --- | --- |
| 访谈中已发现一个清晰的痛点 | 做：验证痛点有多普遍 |
| 访谈结论分散，拿不准哪个痛点更疼 | 做：选项式提问能帮排序 |
| 访谈还没做完 | 先不做：问题没定，问卷只会问错 |
| 目标人群极小（如某类冷门职业） | 可以不做，用访谈 + 社群讨论替代 |

### 5.2 问卷设计的三个要点 {#survey-design}

1. **让 AI 出草稿，你来砍**：AI 喜欢一次给 20 题。实发只留 8～12 题，超过 15 题回收率会明显下降；
2. **前三题必须是“筛人题”**：先问“你是否做过 XX”（是/否）。答“否”的人直接结束，避免无效数据；
3. **必加三道反常识题**（用来提高数据可信度）：
   - **行为题**：过去 3 个月，你为解决这个问题做过什么？（多选，含“什么都没做”）
   - **代价题**：你为它花过钱吗？花过多少？
   - **价格题**：什么价格你觉得太贵、什么价格你觉得太便宜（用来算价格敏感度区间）

## 六、付费意愿：从口头到掏钱 {#willingness}

### 6.1 承诺升级阶梯 {#commitment-ladder}

| 层级 | 用户的具体动作 | 证据强度 | 通常能拿到多少 |
| --- | --- | --- | --- |
| 0 级 | 说“挺好的”“有需要” | 不算证据 | 很多 |
| 1 级 · 意愿级 | 主动说了自己的真实困扰与花费 | 及格线 | 5 人里 3～5 人 |
| 2 级 · 关注级 | 留下联系方式 / 加入等待名单 | 中等 | 5 人里 1～3 人 |
| 3 级 · 行动级 | 愿意专门抽出 30 分钟深度试用 | 偏弱（见下） | 5 人里 1～2 人 |
| 4 级 · 承诺级 | 付可退定金、按报价预定、签试用备忘 | 最值钱 | 5 人里 0～1 人 |

:::warning 关于 3 级证据
“愿意花 30 分钟试用”离“愿意付钱”还有很远的距离。它的成本只是一点时间，不需要克服任何金钱心理门槛，很多人在社交场合会顺口答应。真正有说服力的商业信号只有两类：① 对方真的掏了钱（哪怕很小）；② 对方为拿到它付出明显代价（专程跑一趟、专门腾出半天、介绍给别人）。

所以 3 级只用来排除明显不成立的方向（连试用都不愿意，基本可以否掉），不能当作市场存在的证明。如果能拿到 4 级，哪怕只有 1 个人，也比 10 个 3 级更有价值。
:::

这 5 场访谈、3～5 个试用者统计上说明不了问题，且几乎全是便利样本，存在社交礼貌与同质性两类偏差。用法：用它发现方向、淘汰明显不成立的方向；别用它“证明”市场存在或决定投入多少。优先级：便利样本 5 场（本阶段）→ 阶段三真实陌生人 20～50 → 阶段四、五用真实付费动作判定，越靠前越只能定性。

阶段二目标是努力拿 1～2 个 3/4 级证据，不是人人付钱。拿不到正常，但要知道自己停在哪级；若 5 人里 4 人停在 0 级，说明访谈方式有问题，重做访谈比继续做产品划算。

### 6.2 怎么开口要“承诺”（话术脚本）{#ask-script}

大部分人不愿意开口要钱，觉得尴尬。用下面这段脚本，把“要钱”变成“请对方帮个忙”：

```text
（访谈结尾，对方已经聊得起劲时）

我今天是来做研究的，不是来卖东西的。但既然你说到这个问题，
我想跟你确认一件事——

我打算这两周先做一版能用的东西，只做最基础的功能。
如果你愿意的话，可以帮我两个忙之一：

一个是现在留个联系方式，东西做好了我第一个发给你，你帮我用一下
告诉我哪里难用——这会花你大概 30 分钟。

另一个是如果你觉得这东西你肯定要用，可以先付个 20 元定金，
做好了我不额外收你钱，用不上我立刻退给你。

不方便也没关系，你能跟我聊这么久已经帮了大忙了。
```

:::warning 四条不可越过的红线
1. **不可暗示“不付钱就拿不到”**：定金必须可退，且明确告知退款方式与时限；
2. **不可虚构成品已就绪**：说“我打算做一版”，不要说“已经做好了”；
3. **不可收集与用途无关的个人信息**：只要联系方式，不要身份证、单位、收入等；
4. **收款必须可追溯、可退还**：用平台的正规收款方式（能留记录、能原路退回），并留下你自己的退款承诺记录。

一句必须说给对方的原话：“这笔钱随时可以退，你只要跟我说一句就行。”说完之后，把这句话也写进聊天记录里。
:::

预收款、预售、盲订在国内有合规要求；个人阶段最易踩的坑是收了钱没交付、退款不畅。本阶段只做：小额、可退、用途明确的钱，并当作学习项目，不做实质经营。要做真生意，先了解当地经营主体、税务与消费者权益要求。

### 7.3 做 / 不做的判断标准 {#decision}

| 信号 | 建议 |
| --- | --- |
| 有 ≥ 3 人主动描述真实困扰，且有 ≥ 1 人愿意深度试用 | 做：进入阶段三 |
| 有 ≥ 1 人付了定金或预购 | 强烈支持做：收入引擎已有第一个信号 |
| 只有客套话（“有需求”“挺好的”），没人愿意花时间 | 先不做：回去换人群或换问题 |
| 痛点很真，但没人愿意为它花钱/花时间 | 换变现方式：免费引流 + 别的方式变现 |
| 访谈中发现了一个更痛的相邻问题 | 换方向：这两周最大的收获 |

规划明确“做不做都算过关，学会判断才是目的”，但判断要基于证据：能说出“因看到 X 和 Y 决定做/不做”，而非“感觉还行”。

练习 2

1. 0 级（客套话，不算证据）
2. 2 级（关注级：留下联系方式）
3. 1 级（意愿级：主动描述真实困扰与代价）

## 附录 A：高频追问话术（访谈冷场时用）{#appendix-followup}

| 情况 | 追问句 |
| --- | --- |
| 对方只说“挺麻烦的” | “能想起来上一次具体是什么时候吗？当时发生了什么？” |
| 对方说“就这样吧，习惯了” | “如果这个事下周突然变简单了，你会拿省下的时间做什么？” |
| 对方开始给你建议 | “谢谢，那你自己现在是怎么处理的？” |
| 对方客气地说“挺好的” | “如果换成是你自己花钱，你会买吗？为什么？” |
| 对方说的和前面矛盾 | “我可能理解错了，你前面说 A，刚才说 B，能再说说是哪种情况吗？” |
| 对方答不出价格 | “你现在为类似的事每月大概花多少？” |
