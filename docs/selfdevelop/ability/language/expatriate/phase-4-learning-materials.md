# 阶段四学习材料：场景实战（第 4 个月）

本材料是《[英语进阶学习计划（外派罗马尼亚 · 6 个月）](index.md)》第四阶段的配套学习内容，主题是**场景实战**。前三个月打下的听读与语法基础，本阶段全部**收敛到 18 张场景卡**：每一张卡都是一个「抵达罗马尼亚后马上会用到的真实场景」，目标是让你在 2 分钟连续输出里做到**卡顿点 ≤ 2、句型地道、语法错误可控**。按四周推进：**W1~W2 工作 6 卡 → W3 生活 6 卡 → W4 旅行 6 卡**，每天 1 张卡。

## 一、本阶段学习目标 {#goals}

本阶段月末标准（达标线）如下。计数口径沿袭计划 v3，务必先看懂「怎么数」再练，否则无法自我校验。

| 维度 | 月末达标线 | 计数方法 | 对应本材料章节 |
| --- | --- | --- | --- |
| 口语 | 18 张场景卡全部填写，每卡 2 分钟输出，卡顿点 ≤ 2 | 2 分钟录音，数「停顿 > 2 秒」+「同一词重复修正 2 次以上」的次数 | [二、场景卡学习法](#card-method) |
| 听力 | 场景原声第一遍听懂；场景卡跟读同步率 ≥ 80% | 1 分钟材料分 10 意群，逐群对比漏/错/节奏错位 | [二、跟读同步率](#shadow-sync) |
| 语法 | 每周 1 个语法点绑定场景，录音语法错 ≤ 3 处/次 | 录音复盘，逐句数语法错误处数 | [六、语法绑定场景](#grammar) |
| 词汇 | 新增 300（场景专用词），随卡片逐卡积累 | 每卡 15～20 词，18 卡合计约 300；Anki 自测 | [二、关键词积累](#keywords) |
| 里程碑 | 18 张卡填完，[通关表第 1 版](#pass-table)全勾 | 见[通关表模板](#pass-table) | [八、自检清单](#checklist) |

:::note 本阶段的定位

前三个月你是「在教室里学英语」，这个月你是「在为抵达后第一天彩排」。本阶段**不追求新知识量，追求把旧知识练到脱口而出**。每一张卡练的不是「会不会」，而是「多快、多自然」。请把每一张卡都当成一次「即将真实发生的对话」。

:::

## 二、场景卡学习法 {#card-method}

### 2.1 卡片模板怎么填 {#card-template}

沿用计划 v3 的卡片模板，每张卡照此填写：

```text
【场景 N · 名称】            优先级：P0 / P1
高频句（8～10 条）+ 关键词（10～15 个）+ 2 分钟角色扮演录音
自评：日期 / 卡顿点 / 待改进：
```

填写顺序有讲究：**先抄高频句 → 再补关键词 → 最后录音自评**。不要一上来就背，先确保每句都「知道为什么这么说」（语境），再进录音环节。本章每张卡都给出「核心句型讲解」，那就是你填写「高频句」的底稿。

### 2.2 每天 30 分钟怎么分 {#card-30min}

**前 20 分钟：学句型。** 读当天卡片的高频句，逐句做三件事：①读懂语境（在哪个场景、对谁说）；②看[核心句型讲解](#card-method)里的「为什么这么说」；③跟读原文音 3～5 遍，把语调、重音模仿到位。目标不是背下来，而是「理解 + 能跟读」。

**后 10 分钟：角色扮演录音。** 设定对方角色（客户/邻居/店员/边检官），自己扮演自己，把当天卡片串成一段 2 分钟的输出并录音。录音后用[卡顿点计数](#count-pauses)自评，并数[语法错误](#grammar)处数。

:::tip 角色扮演的关键

不要「背台词」，要「演对话」。给自己设定一个具体情境（例如「周三例会向经理汇报故障进展」），用卡片句型组织语言，但允许临时组织新句子——这正是练「应变」。录音时想象对面真的坐着一个人，语速和语气都要自然。

:::

### 2.3 卡顿点怎么数 {#count-pauses}

**数法**：录 2 分钟输出，数「停顿 > 2 秒」和「同一词重复修正 2 次以上」的次数。正常想词的间隙（< 2 秒）不计，避免过度苛刻。本阶段标准：**每卡 2 分钟输出卡顿点 ≤ 2**。

**示例计数**：

> Hi, I'd like to return this item.（1.5 秒——不计）I bought it,（3 秒——**计 1 点**）um, I, I,（重复修正——**计 1 点**）yesterday. ...

共 2 点，达标。若某卡稳定 > 2 点，把卡顿最频繁的那一句单独拎出来练 10 遍，再整段重录。

### 2.4 跟读同步率怎么数 {#shadow-sync}

听力标准「场景卡跟读同步率 ≥ 80%」用**十意群法**：把 1 分钟场景原声切成 10 个意群，逐群跟读对比，记录漏、错、节奏错位。达标公式：**同步率 = 10 − 出错意群数 ÷ 10**，≥ 80% 即出错意群 ≤ 2 个。

| 意群序号 | 原声内容 | 跟读结果（✓/漏/错/节奏） |
| --- | --- | --- |
| 1 | Could you send someone to fix the heating | ✓ |
| 2 | We have an active alarm on NE123 | 节奏错位 |
| 3 | I'm afraid I can't make it on Friday | ✓ |
| ... | ... | ... |

### 2.5 关键词怎么积累 {#keywords}

每卡 15～20 个场景专用词，随卡片逐卡积累，18 卡合计约 300。每词做 Anki 卡：正面英文，背面「含义 + 一句本场景例句」。关键词已在各卡中以「关键词」小节列出，直接照抄进 Anki 即可。目标：**月底 300 词 Anki 自测正确率 ≥ 90%**。

## 三、工作场景 6 卡 {#scenario-work}

工作场景是最高优先级（外派岗位的核心），W1~W2 两周完成。每卡含「核心句型讲解（为什么这么说）→ 关键词 → 角色扮演脚本 → 录音自评要点」。

### 卡 1 · 入职与团队自我介绍 {#work-card-1}

**核心句型讲解**

| 高频句 | 为什么这么说（语境） |
| --- | --- |
| Hi everyone, I'm [姓名] from China. | 开场：先报名字，再说明来源，破冰自然 |
| I'll be joining the [团队] as a software maintenance engineer. | 说明岗位与职责，用将来时「will be joining」表即将到岗 |
| I've been in this area for about [X] years. | 用现在完成进行时表达「持续至今的工作经验」 |
| My recent focus has been on fault handling and version maintenance. | 用完成时收窄到近期的具体方向，便于对方接话 |
| This is my first time living in Romania. | 主动抛「新人/新环境」，给对方一个关心你的入口 |
| I'm looking forward to working with the local team. | 表达积极意愿，团队协作的礼貌收尾 |
| Please feel free to grab me for a chat. | 口语化邀约，降低对方开口门槛 |

**关键词**：software maintenance / core network / network management / fault handling / ticket / alarm / version maintenance / local team / newcomer / colleague / project / handover

**角色扮演脚本示例**

```text
（对方：本地团队经理 Tom）
Hi everyone, I'm [Li Ming] from China. I'll be joining the NMS
team as a software maintenance engineer.

I've been in this area for about eight years, mostly working on
core network fault handling and version maintenance. My recent
focus has been on alarm handling and patch rollout.

This is my first time living in Romania. I'm really looking forward
to working with the local team and learning from everyone.

Please feel free to grab me for a chat if you have any questions.
Thanks!
```

**录音自评要点**：①介绍是否完整覆盖「名字/岗位/经验/意愿」四要素；②「I've been...」与「I'll be...」的时态是否用对；③卡顿点是否 ≤ 2；④语调是否有起伏（不是平读）。

### 卡 2 · 例会发言与周报 {#work-card-2}

**核心句型讲解**

| 高频句 | 为什么这么说（语境） |
| --- | --- |
| Since last week, I've been working on [任务/问题单]. | 用现在完成进行时强调「从上周持续到现在」的动作 |
| I've finished [成果] — here's a quick update. | 用现在完成时汇报已完成的事，配「quick update」拉近距离 |
| Right now I'm stuck on [问题], and I could use some input. | 主动求助，用「could use some input」礼貌请同事给建议 |
| I'm planning to have it done by [日期]. | 用 be going to 表达明确的计划与截止时间 |
| For next week, I'll focus on [下一步]. | 用 will 表达下一步安排，明确优先级 |
| Does anyone have feedback on this approach? | 主动征集意见，是例会发言的收尾标配 |

**关键词**：update / task / ticket / progress / stuck / deadline / feedback / approach / priority / next step / on track

**角色扮演脚本示例**

```text
（对方：项目例会，5 人）
Since last week, I've been working on ticket 4821 about the
configuration alarm. I've finished the log analysis, and the issue
is reproducible on our side.

Right now I'm stuck on the root cause — I could use some input on
the configuration file. I'm planning to have it done by Friday.

For next week, I'll focus on drafting the rollback plan. Does anyone
have feedback on this approach?
```

**录音自评要点**：①「have been working」与「have finished」的完成时是否区分清楚；②求助句是否用了「could use」而非生硬的「I need」；③汇报结构是否「过去→现在→未来」清晰。

### 卡 3 · 故障处理与变更沟通 {#work-card-3}

**核心句型讲解**

| 高频句 | 为什么这么说（语境） |
| --- | --- |
| We have an active alarm on [网元/设备], severity is [级别]. | 用一般现在时陈述当前事实状态，开门见山 |
| Let me confirm the fault description — could you provide the error log? | 「Let me confirm」缓冲 + 用 could 礼貌索要信息 |
| The issue is reproducible on our side. We've identified the root cause. | 「reproducible」是技术沟通高频词；用完成时报告已定位 |
| We'll provide a workaround first, then schedule a permanent fix. | 用 will 说明处置顺序：先临时规避，再根治 |
| We'd like to apply the patch during the maintenance window on [日期]. | 用 would like 礼貌提出变更申请，明确时间窗 |
| Do we need a rollback plan before the upgrade? | 变更前必问，体现风险管理意识 |
| The change completed successfully. Post-check indicators are normal. | 用过去时报告已完成动作 + 用现在时报告当前状态 |
| I'll escalate this ticket and keep you updated. | 用 will 承诺下一步动作，给对方确定性 |

**关键词**：active alarm / severity / error log / reproducible / root cause / workaround / patch / maintenance window / rollback / escalate / post-check / keep updated

**角色扮演脚本示例**

```text
（对方：本地维护团队同事）
We have an active alarm on NE123, severity is high. Let me confirm
the fault description — could you provide the error log?

The issue is reproducible on our side. We've identified the root
cause. We'll provide a workaround first, then schedule a permanent
fix during the maintenance window on Friday night.

Do we need a rollback plan before the upgrade? If so, I'll prepare
it today. I'll escalate this ticket and keep you updated.
```

**录音自评要点**：①陈述事实用一般现在时、报告已完成用过去时/完成时是否用对；②「could you provide」「would like to」等礼貌请求是否到位；③「first...then...」的处置顺序是否清楚。

### 卡 3 延伸 A · 与本地团队/客户电话 {#work-card-3-phone}

电话沟通比当面更难（无表情、无画面），核心策略是**放慢 + 确认**。

**核心句型讲解**

| 高频句 | 为什么这么说（语境） |
| --- | --- |
| Hi, this is [姓名] from the [团队]. | 电话标准开场：报名字 + 单位，别让对方猜 |
| Could you speak a little more slowly, please? | 电话里听力最难，礼貌请对方放慢是必备句 |
| Sorry, could you say that again? | 没听清时的标准补救句，别硬着头皮猜 |
| Just to confirm, you said [要点], right? | 「Just to confirm」主动复述确认，避免听错 |
| Let me check and call you back. | 不确定时先别乱答，承诺回电更专业 |
| I'll send you an email with the details. | 用邮件兜底书面信息，弥补电话易忘的缺点 |

**关键词**：phone call / confirm / check back / say that again / speak slowly / take a message / call back / details / follow up

**角色扮演脚本示例**

```text
（对方：客户技术支持，语速较快）
Hi, this is [Li Ming] from the NMS team. I'm calling about ticket
4821.

Sorry, could you say that again? ... Just to confirm, you said the
alarm appears after the last patch, right?

Let me check the configuration and call you back within an hour.
I'll also send you an email with the details.
```

**录音自评要点**：①开场是否报了名字和单位；②确认句「Just to confirm...right?」是否熟练；③是否避免了「嗯嗯啊啊」式的敷衍回应，改用明确承诺。

### 卡 3 延伸 B · 英文邮件（周报/请假/请求）{#work-card-3-email}

邮件是书面沟通，要求**结构清晰、礼貌克制**。核心是「开头问候 → 正文要点 → 结尾礼貌语」。

**核心句型讲解**

| 高频句 | 为什么这么说（语境） |
| --- | --- |
| Hi [收件人], / Dear Mr./Ms. [姓], | 熟络用 Hi，正式或首次用 Dear + 称呼 |
| This week I focused on [任务] – status. | 用过去时报告本周已做的事 |
| Next week I plan to [计划]. | 用 plan to 表达下周安排 |
| One thing I'd like your input on: [问题]. | 用 would like 礼貌请求对方意见 |
| I'd like to request leave on [日期]. | 请假请求的标准句式，直接明确 |
| I'll make sure my tasks are covered before I leave. | 请假时给承诺，打消对方顾虑，显得负责 |
| Would it be possible to [请求]? | 请求句的万能礼貌句式 |
| Best regards, [姓名] | 标准落款 |

**关键词**：focused on / plan to / status / request / covered / input / possible / Best regards / attached / please find

**周报邮件模板示例**

```text
Subject: Weekly Report – [Li Ming], [日期]

Hi Tom,

This week I focused on:
1) Ticket 4821 – analysis done, root cause identified
2) Patch 2.3 – post-check indicators normal

Next week I plan to:
- Draft the rollback plan for the upgrade
- Prepare the handover notes for ticket 4821

One thing I'd like your input on: the maintenance window timing
on Friday.

Best regards,
[Li Ming]
```

**录音自评要点**：①主题是否清晰（含姓名+日期）；②正文是否「本周/下周/需反馈」三段清晰；③请假/请求是否用了礼貌句式，是否给了「任务已安排」的承诺。

### 会议万能句（工作场景第 6 卡）{#work-card-3-meeting}

会议不是汇报时也需要「在场感」，以下是四类万能句，任何会议都适用：

| 场景 | 万能句 | 什么时候用 |
| --- | --- | --- |
| 澄清 | Just to clarify, ... | 对方表述不清，或自己需要确认理解 |
| 插话 | Can I jump in here? | 礼貌打断，争取发言机会 |
| 搁置 | Let's circle back on this later. | 话题偏题或时间不够，建议稍后再议 |
| 总结 | To summarize what we agreed: ... | 会议结尾主动总结共识，体现主导力 |

**关键词**：clarify / jump in / circle back / summarize / agree / action item / agenda / follow up

**角色扮演脚本示例**

```text
（对方：跨团队周会）
Just to clarify, the alarm appears only after the last patch, right?
... Can I jump in here? On the rollback plan, I think we should
schedule it for Friday.

Let's circle back on the configuration details later. To summarize
what we agreed: we'll prepare the rollback plan this week, and I'll
confirm the window with the operations team.
```

**录音自评要点**：①四类万能句是否都能脱口而出；②「Can I jump in here?」是否语气礼貌（而非抢话）；③能否在会议结尾用「To summarize」主动收束。

## 四、生活场景 6 卡 {#scenario-life}

生活场景 W3 一周完成，是「带娃安家」的刚需。注意这些场景大量用到[礼貌请求 would/could](#grammar-would) 与[被动语态](#grammar-passive)。

### 卡 4 · 租房安家 {#life-card-4}

**核心句型讲解**

| 高频句 | 为什么这么说（语境） |
| --- | --- |
| I'm looking for a two-bedroom apartment near [学校/区域]. | 用现在进行时表达「正在找」，并给出硬性条件 |
| What's the monthly rent, and what does it include? | 房租 + 包含项目一次问清，别漏 |
| Is heating / water / internet included? | 逐一确认是否含在房租里（东欧冬天暖气重要） |
| How long is the lease, and can we extend it later? | 租期 + 续租灵活性，避免合同到期被动 |
| What's the deposit? Is it refundable? | 押金金额 + 是否可退，防坑关键句 |
| Could I take a look at the contract before signing? | 用 could 礼貌请求先看合同再签 |
| When can we move in? | 搬入时间，安排搬家计划 |

**关键词**：apartment / rent / lease / deposit / refundable / included / contract / move in / neighborhood / landlord / utilities

**角色扮演脚本示例**

```text
（对方：房屋中介）
I'm looking for a two-bedroom apartment near the international
school. What's the monthly rent, and what does it include?

Is heating and internet included? How long is the lease, and can we
extend it later? What's the deposit — is it refundable?

Could I take a look at the contract before signing? And when can we
move in?
```

**录音自评要点**：①是否把「租金/包含项/押金/租期」问全；②请求看合同是否用了「Could I」而非生硬命令；③被动语态场景（如「Is heating included?」）是否自然。

### 卡 5 · 银行开户 {#life-card-5}

**核心句型讲解**

| 高频句 | 为什么这么说（语境） |
| --- | --- |
| I'd like to open a personal account. | 用 would like 礼貌提出需求 |
| What documents do I need to bring? | 提前问清材料清单，避免白跑 |
| I have my passport and proof of address. | 主动报出已备材料，推进流程 |

:::

## 六、语法绑定场景 {#grammar}

每周 1 个语法点，绑定当月场景。每个语法点给出「场景例句讲解」+「常见错误警示」。录音后数语法错误，标准是 **≤ 3 处/次**。

### 语法 1 · 现在完成时 vs 过去时（例会汇报）{#grammar-present-perfect}

**场景例句**

> I've been working on ticket 4821 since last week. （从上周一直做到现在，可能还在做）

> I finished the analysis yesterday. （过去某时做完，时间点明确）

**讲解**：**现在完成时**强调「与现在有联系」——持续至今的动作（用 have been doing）或刚完成的成果（用 have done）；**过去时**强调「过去某个明确时间点发生的事」，常配 yesterday / last week / on Friday 等具体时间。

**常见错误警示**：

- 错：~~I have finished the analysis yesterday.~~（有了 yesterday 这个过去时间点，必须用过去时）
- 对：I finished the analysis yesterday.
- 错：~~I work on this ticket since last week.~~（since 表持续至今，需用完成时）
- 对：I've been working on this ticket since last week.

### 语法 2 · 礼貌请求 would / could（服务场景）{#grammar-would}

**场景例句**

> Could you send someone to fix the heating? （could 表礼貌请求，口语最常用）

> Would it be possible to extend the lease? （would 更正式委婉，用于书面或郑重请求）

**讲解**：**Could you...?** 是口语请求的标准句式，礼貌且自然；**Would it be possible to...?** 更正式委婉，适合邮件、书面或对不熟的人。两者都比直接命令（Fix the heating.）礼貌得多。

**常见错误警示**：

- 错：~~You fix the heating.~~（命令式，太生硬）
- 对：Could you fix the heating?
- 错：~~Would you possible to help?~~（possible 需接 it be）
- 对：Would it be possible to help? / Could you help?

### 语法 3 · 将来计划 be going to / will（预约计划）{#grammar-future}

**场景例句**

> We're going to move in next week. （be going to 表「已计划好、有迹象」的计划）

> I'll send you the email this afternoon. （will 表临时决定或承诺）

**讲解**：**be going to** 强调「已经计划好的安排」或「有迹象要发生」；**will** 强调「此刻的决定」或「承诺/意愿」。预约、计划（搬家、开会）多用 be going to；临时决定、承诺（回电、发邮件）多用 will。

**常见错误警示**：

- 错：~~I will move in next week.~~（事先计划好的搬家用 be going to 更自然，但不算硬错）
- 对：We're going to move in next week.
- 错：~~I'm going to call you back right now.~~（临时决定回电，用 will）
- 对：I'll call you back right now.

### 语法 4 · 被动语态（报修/通知理解）{#grammar-passive}

**场景例句**

> The heating has been fixed. （暖气已被修好——说话人更关心「结果」而非「谁修的」）

> A scheduled upgrade will be run on Friday. （通知里常见，突出「安排」而非施动者）

**讲解**：被动语态（be + 过去分词）在**报修、通知**里特别常见，因为重点在「事件/结果」而不在「谁做的」。理解时要能快速识别「has been done / is done / will be done」结构，这直接关系到你对通知的准确理解。

**常见错误警示**：

- 错：~~The heating has fixed.~~（被动需加 be：has been fixed）
- 对：The heating has been fixed.
- 错：~~It is fix by the technician.~~（过去分词 + by 表施动者：fixed）
- 对：It is fixed by the technician.

### 语法 5 · 委婉否定 I'm afraid（拒绝/请假）{#grammar-afraid}

**场景例句**

> I'm afraid I can't make it on Friday. （委婉拒绝，「我恐怕周五来不了」）

> I'm afraid we're fully booked for tonight. （服务员婉拒，比直接 No 礼貌）

**讲解**：**I'm afraid + 否定**是英语委婉否定/拒绝的经典句式，用「恐怕」弱化生硬感。拒绝请假、表示无法赴约、店员婉拒时都用它，比直接「I can't」或「No」礼貌得多。注意 I'm afraid 在此是「恐怕」之意，**不是**「害怕」。

**常见错误警示**：

- 错：~~I'm afraid I can't make it.~~（其实是正确的，但注意别把 afraid 理解成害怕）
- 错：直接说 ~~No, I can't.~~（太生硬，改用 I'm afraid 软化）
- 对：I'm afraid I can't make it on Friday.
- 注意：I'm afraid + 否定表委婉，I'm afraid of + 名词表「害怕」——勿混淆。

### 语法 6 · 第一条件句 if...will（建议/预案）{#grammar-conditional}

**场景例句**

> If it's raining, we'll take a taxi. （若下雨，我们就打车——真实可行的预案）

> If you need a rollback plan, I'll prepare it. （如果需要回退方案，我就准备——条件建议）

**讲解**：**第一条件句** = **If + 现在时，主句 + will**。用于谈论「很可能发生的条件 + 相应结果」，是建议、预案、约定的核心结构。注意 if 从句用**现在时**（不是 will），主句才用 will。

**常见错误警示**：

- 错：~~If it will rain, we'll take a taxi.~~（if 从句用现在时，不用 will）
- 对：If it rains, we'll take a taxi.
- 错：~~If you need, I will will prepare.~~（冗余，删去重复的 will）
- 对：If you need a plan, I'll prepare it.

### 参考答案与解析 {#answer-key}

**练习 1**：

1. Could（Could you...? 礼貌请求）
2. been（I've been working = 现在完成进行时，持续至今）
3. afraid（I'm afraid I can't = 委婉否定）
4. Could（Could I...? 礼貌请求许可）
5. rains（if 从句用现在时，不用 will）
6. going（be going to = 已计划好的安排）

**练习 2**（示例·卡 8）：参考[卡 8 角色扮演脚本](#life-card-8)。核心要求自检：①有开场问候（Good morning, Ms. Ana...）；②过敏说明精确（...has a food allergy to peanuts, please make sure lunch doesn't include them）；③至少 1 句 could/would（Could we arrange...）；④至少 1 句被动或完成时。

**练习 3**：

1. have finished → finished（有 yesterday 时间点，用过去时）
2. We're going to → We'll（临时决定回电用 will）
3. has fixed → has been fixed（被动语态需加 been）
4. If it will rain → If it rains（if 从句用现在时）
5. I'm afraid of I can't → I'm afraid I can't（I'm afraid + 从句表「恐怕」，不加 of）

**练习 4**：自测。卡顿点 ≤ 2 为达标；计法见[二、卡顿点怎么数](#count-pauses)。

**练习 5**：

1. A（现在完成进行时强调持续至今）
2. B（What do you recommend? 是地道问法）
3. B（I'm afraid = 恐怕，非害怕）
4. B（has been fixed 是被动语态）
5. A（How long are you staying? 用现在进行时提问，答也用进行时）
6. 错（Could 开头是礼貌请求）
7. 对（紧急场景三要素：谁 + 什么事 + 在哪）
8. 错（过敏信息必须精确、不容误解）
9. 场景任务：卡顿点 ≤ 2、语法错 ≤ 3 达标。
