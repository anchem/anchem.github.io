# 阶段三学习材料：口语输出（第 3 个月）

本材料是《[英语进阶学习计划（外派罗马尼亚 · 6 个月）](index.md)》第三阶段的配套学习内容，按四周推进：**第一周影子跟读过渡 → 第二周复述训练与首次外部反馈 → 第三周 PREP 观点表达 → 第四周录音复盘方法论**。阶段主题是**口语输出**，前两个月（语音节奏、精听）打的是「耳朵」与「节奏」的地基，这个月把积累**真正说出口**。

:::note 本阶段的定位

第三阶段**不追求「说得完美」，追求「开口有章法」**：①把「跟读」升级成「影子跟读」，让嘴跟上真实语速；②用「复述」把听到的内容用自己的话讲出来；③用「PREP」框架让即兴表达有结构、不卡壳；④用「录音自评」把错误找出来并改掉。这四件是后面三个月所有场景实战的**输出能力地基**。

:::

## 二、第一周：影子跟读过渡 {#shadowing}

### 2.1 从「跟读」到「影子跟读」{#shadowing-transition}

**核心概念**：跟读（repeat）是先听一句、暂停、再模仿；**影子跟读（shadowing）是不暂停、不重来，像影子一样跟在原声后面半拍说出来**。

| 对比项 | 跟读 | 影子跟读 |
| --- | --- | --- |
| 停顿 | 每句暂停 | 不暂停，连续进行 |
| 滞后 | 无滞后 | 滞后 0.5～1 秒（延迟跟随） |
| 文本 | 可看稿 | **不看文本**，凭听 |
| 训练目的 | 模仿单句语音 | 训练节奏、意群切分、短时记忆、输出流畅度 |
| 难度 | 低 | 高 |

**过渡方法（三步走）**：

1. **第一步（第 1～2 天）**：先正常跟读 2 遍，熟悉内容与语音，再进入影子跟读。
2. **第二步（第 3～5 天）**：正式影子跟读，滞后 0.5～1 秒、不看文本。跟不上没关系，**保持节奏不断**最重要——宁可含糊带过，也不要停下来重来。
3. **第三步（第 6～7 天）**：录音自评，用同步率法（见 2.2）数意群同步情况。

:::tip 滞后感怎么找

影子跟读的「滞后 0.5～1 秒」指的是：你开始说某个意群时，原声大概已经把这个意群读完一半。你是在「跟着复述」，不是在「和原声同时抢着说」。刚开始可以故意晚半拍，练熟了自然就会找到合适的滞后。

:::

### 2.2 同步率怎么数（示例）{#sync-rate}

**数法**：取 1 分钟材料，把它切分成 **10 个意群**，逐群对比你与原声——每个意群只要出现「漏词」「错词」「节奏错位」中的任意一种，就计这个意群**不同步**。

> 同步率 = 同步的意群数 ÷ 10 × 100%

**示例材料**（1 分钟技术类播客片段，切为 10 个意群）：

```text
① When we deploy a new software version /  ② the first thing we check /  ③ is the monitoring dashboard. /  ④ If any alarm shows up /  ⑤ with a severity above a warning, /  ⑥ we open a ticket immediately /  ⑦ and start a diagnosis. /  ⑧ The root cause is usually found /  ⑨ within a few hours. /  ⑩ Then we apply a fix and verify the result.
```

**学生影子录音对比示例**：

| 意群 | 原声 | 学生影子 | 判定 |
| --- | --- | --- | --- |
| ① | When we deploy a new software version | When we **deliver** a new software version | 错词（错）→ 不同步 |
| ② | the first thing we check | the first thing we check | 同步 |
| ③ | is the monitoring dashboard | is the monitoring dashboard | 同步 |
| ④ | If any alarm shows up | If any alarm show up（漏了 s） | 错词 → 不同步 |
| ⑤ | with a severity above a warning | with a severity above a warning | 同步 |
| ⑥ | we open a ticket immediately | we open a ticket immediately | 同步 |
| ⑦ | and start a diagnosis | and start a diagnosis | 同步 |
| ⑧ | The root cause is usually found | The root cause is usually found | 同步 |
| ⑨ | within a few hours | within a few hours | 同步 |
| ⑩ | Then we apply a fix and verify the result | Then we apply a fix and verify the result | 同步 |

同步 8 个意群，同步率 = 8 ÷ 10 = 80%，**达标（≥ 80%）**。注意：第②④的「错词」哪怕只是单复数（show up 漏 s）也算该意群不同步——**同步率衡量的是「整体跟上没跟上」，不是「大概意思对没对」。**

### 2.3 意群怎么切分 {#chunking}

切分意群是影子跟读的基础。意群（chunk）= 一个语法或语义完整的小单位，通常是一个短语或一个分句。

| 切分规则 | 例子（/ 处为停顿） |
| --- | --- |
| 介词短语自成一组 | We met / in the meeting room / yesterday. |
| 从句自成一组 | If the alarm is high / we escalate it. |
| 并列成分分开 | We checked the logs / and the configuration. |
| 主谓宾完整句可成一组 | The system recovered / after the reboot. |

:::warning 常见误区

**影子跟读不是「默读」也不是「背稿」**。默读不练嘴，背稿不练「跟」。影子跟读必须**出声**，且**跟着原声的节奏**走——你的目标是「贴着原声」，不是「抢在原声前面」把整句背出来。

:::

### 2.5 口语动词短语与衔接词启动 {#shadow-vocab}

本月词汇目标是**新增 300**，其中口语板块主攻两类：**口语动词短语（phrasal verbs）** 和 **衔接词（linkers）**。第一周先启动下面 20 个高频口语动词短语：

| 短语 | 含义 | 工作例句 |
| --- | --- | --- |
| look into | 调查、排查 | I'll look into the alarm right away. |
| figure out | 弄清楚 | We need to figure out why it crashed. |
| run into | 遇到（问题） | We ran into an issue during the upgrade. |
| sort out | 解决、理清 | Let's sort out the ticket order first. |
| carry out | 执行 | We carried out the maintenance as planned. |
| bring up | 提出（话题） | I'll bring this up in the daily meeting. |
| catch up | 赶上进度 / 叙旧 | Let me catch up on the ticket status. |
| put off | 推迟 | We put off the release by one day. |
| go through | 过一遍、审阅 | Let's go through the checklist. |
| set up | 建立、安排 | We set up a monitoring alert for it. |
| come up with | 想出（方案） | We came up with a workaround. |
| check in | 报到、确认 | I'll check in with the team later. |
| turn out | 结果是 | It turned out to be a config issue. |
| deal with | 处理 | I'll deal with the high-severity fault first. |
| give up | 放弃 | We won't give up on the diagnosis. |
| point out | 指出 | She pointed out a mistake in the report. |
| take over | 接手 | I'll take over the ticket from the night shift. |
| hand over | 交接 | I handed over the notes before leaving. |
| keep up with | 跟上 | It's hard to keep up with the log volume. |
| break down | 出故障 / 分解 | The element broke down at 2 a.m. |

**记忆法**：把每个短语做成 Anki 卡——正面英文短语，背面「含义 + 一句工作场景例句」。动词短语的重点是**记搭配**（run INTO、look INTO、deal WITH），介词错了意思就偏了。

## 三、第二周：复述训练与首次外部反馈 {#retell}

### 3.1 听后复述框架 {#retell-framework}

**核心概念**：复述（retell）不是逐句背诵，而是**用自己的话把听过的内容讲出来**。它是「听力 → 输出」的关键桥梁：证明你真的听懂了，而不是只是跟读出来了。

**听后复述五要素框架**（时间 / 地点 / 人物 / 发生了什么 / 结果）：

| 要素 | 要回答的问题 | 示例（例会通报） |
| --- | --- | --- |
| 时间 When | 什么时候发生 | Last night around 11 p.m. |
| 地点 Where | 发生在哪个系统/网元 | on NE123, the core network element |
| 人物 Who | 涉及谁/哪个团队 | my team and the on-call engineer |
| 发生了什么 What | 核心事件是什么 | a high-severity alarm went off |
| 结果 How it ended | 最后怎么解决 | we applied a workaround and it's stable now |

**复述三步流程**：

1. **听**：完整听一遍材料，抓住五要素，允许做简单笔记（时间/名词/数字）。
2. **说**：不看笔记，用自己的话把五要素串成 3～4 句话讲出来。**用简单句，不追求原词。**
3. **对**：对比原材料的要点，看有没有漏掉关键信息；再重听一遍补漏。

**示例**（复述一段 1 分钟的例会汇报）：

> 原声大意：昨晚 11 点 NE123 网元出现高优先级告警，值班工程师排查后确认是配置错误，采用临时规避方案后系统恢复稳定，永久补丁将在下次维护窗口部署。

> 学生复述：A high-severity alarm went off on NE123 last night around 11. The on-call engineer found it was caused by a configuration error. We applied a temporary workaround and the system is stable now. The permanent fix will be deployed in the next maintenance window.

复述时**用你自己的话**，不必复现原声的表达；只要五要素齐全、逻辑通顺即可。

### 3.2 复述训练的选材与频率 {#retell-materials}

| 材料类型 | 时长 | 用途 | 频率 |
| --- | --- | --- | --- |
| 技术播客片段 | 1 分钟 | 复述技术要点 | 每天 1 段 |
| 会议/汇报录音 | 1～2 分钟 | 复述工作场景信息 | 每周 2 段 |
| 生活类短视频 | 1 分钟 | 复述生活话题 | 每天 1 段 |

:::tip 复述和听写的关系

前两月你练的「精听五步法」是把内容**写下来**，复述是把内容**说出来**。写下来检验「听清了没有」，说出来检验「能讲明白没有」——两者配合，听力才算真正内化。

:::

### 3.3 首次外部反馈（必做）{#first-feedback}

**核心概念**：自评容易「自我感觉良好」，需要**真人反馈**来校准。从第 2 周起，**每 2 周 1 次真人反馈，必做**——平台用 italki 或 Cambly，约 ¥100～150/次。

**反馈流程**：

1. **课前准备**：选好材料（1 段影子录音 + 1 段话题演讲），明确「这次想解决什么问题」（比如「我的时态总错」或「我说话卡顿太多」）。
2. **课中呈现**：给外教放你的录音，或直接对话；请对方按[反馈记录表](#feedback-log)的维度给评价。
3. **课后记录**：当天就把反馈填进[反馈记录表](#feedback-log)，落实改进动作。

**反馈记录表怎么用**（模板见[附录](#feedback-log)）：重点是「改进动作」和「下次复查」两列——**反馈不落到动作就等于白听**。比如外教说「你过去式总用成原形」，你的改进动作就是「每天复述时专门检查 5 处过去式」，下次复查时请外教再听 3 句过去式。

:::important 为什么「必做」

真人反馈是阶段三**硬性里程碑**（至少 2 次），不是可选加分项。它解决的是自评失真的问题——你录音时以为「还不错」，但真实对话场景下对方可能根本听不懂。第 2 周和第 4 周各做 1 次，正好覆盖本月两次。

:::

## 四、第三周：PREP 观点表达 {#prep}

### 4.1 PREP 框架 {#prep-framework}

**核心概念**：PREP 是即兴发言的四步结构，让任何话题都能「有观点、有理由、有例子、有收尾」：

| 步骤 | 英文 | 中文 | 作用 | 时间占比 |
| --- | --- | --- | --- | --- |
| P | Point | 观点 | 开门见山亮明立场 | 10% |
| R | Reason | 理由 | 给 1～2 个支撑理由 | 30% |
| E | Example | 例子 | 用具体案例或数据证明 | 40% |
| P | Point | 重申观点 | 收尾回扣观点 | 20% |

**示例**（话题：远程办公好不好？）：

```text
P（观点）：In my opinion, remote work is a good idea for most software teams.

R（理由）：Because it saves commuting time and lets people focus on deep work.

E（例子）：Last year our team worked from home for three months, and we finished more tickets with fewer interruptions. The only downside was that communication took more effort.

P（重申）：So overall, I think remote work helps productivity as long as the team keeps clear communication.
```

### 4.2 观点库话题清单 {#topic-bank}

本月 PREP 训练围绕四类观点库话题，覆盖你未来的工作与生活场景：

| 类别 | 话题示例 |
| --- | --- |
| 工作 Work | ① 为什么软件维护要重视文档；② 问题单处理中最难的是什么；③ 升级前要不要做回退演练 |
| 家庭 Family | ④ 我如何看待父母参与育儿；⑤ 周末家庭活动怎么安排 |
| 育儿 Parenting | ⑥ 孩子学外语越早越好吗；⑦ 国际学校 vs 本地学校怎么选 |
| 赴罗生活 Life in Romania | ⑧ 我期待在罗马尼亚体验什么；⑨ 到一个新国家最需要准备什么；⑩ 我如何帮助女儿适应新学校 |

**观点库怎么用**：每天从观点库抽 1 个话题，先口头用 PREP 讲 3 分钟，再录音。观点库不是用来背答案，是用来**逼自己在「没准备」的情况下也能讲出结构**——即兴表达练的就是这个。

### 4.3 衔接词清单 {#connectors}

衔接词是让表达连贯的「路标」。PREP 的每一步之间用衔接词过渡，能明显减少卡顿和「嗯/啊」。

| 功能 | 衔接词 | 例句 |
| --- | --- | --- |
| 亮观点 | In my opinion / I believe / From my perspective | In my opinion, documentation is crucial. |
| 给理由 | because / since / the reason is | The reason is it saves us time later. |
| 举例子 | for example / for instance / such as | For example, we had a P1 alarm last week. |
| 并列补充 | moreover / also / in addition | Moreover, it reduces miscommunication. |
| 转折 | however / but / on the other hand | However, it takes extra effort. |
| 让步 | although / even though | Although it takes time, it's worth it. |
| 因果 | therefore / so / as a result | Therefore, we decided to do a rollback. |
| 顺序 | first / then / finally | First we diagnose, then we fix. |
| 收尾重申 | in short / overall / to sum up | In short, I think it's worth doing. |
| 争取时间 | let me think / well / actually | Let me think... I'd say yes. |

**争取时间的话术**：即兴发言时卡住很正常。与其干愣着（停顿 > 2 秒会计入卡顿点），不如用「Let me think for a second」「Actually, that's a good question」「Let me put it this way」争取 1～2 秒组织思路——**既不卡顿，又显得自然**。

## 五、第四周：录音复盘方法论 {#review}

### 5.1 录音自评四问 {#four-questions}

**核心概念**：录音自评是「没有外教时」最有效的纠错手段。录完一段输出后，用**四问**系统复盘，把模糊的「感觉还行」变成明确的改进点。

| 问题 | 具体检查 | 例子 |
| --- | --- | --- |
| ① 卡顿点在哪 | 停顿 > 2 秒、重复修正发生在哪 | 「…and we, and we (重复) looked into…」 |
| ② 语法错了几处 | 时态、单复数、介词 | 「Yesterday we look (应为 looked) at the log」 |
| ③ 词汇是否地道 | 是否用了中式的直译 | 「make a call to the network」→「call the network」 |
| ④ 节奏是否自然 | 重音、意群停顿、是否蹦豆 | 全句一字一顿 → 缺意群停顿 |

**四问落地**：每段录音复盘时，把四问的结果写进[反馈记录表](#feedback-log)的备注或自评栏，形成「问题 → 动作」闭环。

### 5.2 常见口语错误清单 {#common-errors}

结合你的工作场景，下面是 B2 学习者最常踩的 5 类口语错误。每周复盘时对着清单自查：

| 错误类型 | 常见错误 | 正确说法 | 场景 |
| --- | --- | --- | --- |
| 时态 | Yesterday we find a bug | Yesterday we **found** a bug | 汇报历史问题 |
| 时态 | I worked here since 2020 | I **have worked** here since 2020 | 讲述经历 |
| 单复数 | There are many alarm | There are many **alarms** | 描述告警 |
| 单复数 | The information are correct | The information **is** correct | 说明数据 |
| 介词 | I will discuss about the issue | I will discuss **the issue** | 例会发言 |
| 介词 | We depend of the dashboard | We depend **on** the dashboard | 说明依赖 |
| 中式直译 | open a meeting | **have / hold** a meeting | 会议安排 |
| 中式直译 | give an example to explain | **give an example** of ... | 解释说明 |

:::warning 改错闭环（最重要）

改错不是「知道了就行」，要形成闭环：**① 录一段 → ② 用四问找错 → ③ 把最高频的错误列成 3 条 → ④ 下一段录音前专门练这 3 条 → ⑤ 复查这 3 条是否还犯。** 每两周循环一次，错误会肉眼可见地减少。

:::

| --- | --- | --- |
| 周一 | 录音自评四问：复盘本周影子录音 1 段 | 四问结果填表 |
| 周二 | 录音自评四问：复盘话题演讲 1 段 | 四问结果填表 |

| 周日 | 休息（仅泛听）+ 月度复盘 | 复盘四问填完 |

### 5.4 月末标准怎么测 {#month-end-check}

**影子跟读同步率**：取 1 分钟材料，切 10 意群，逐群对比漏/错/节奏错位，同步 ≥ 8 个即达标（≥ 80%）。方法见[2.2 同步率怎么数](#sync-rate)。

**3 分钟 PREP 话题**：抽 1 个观点库话题，用 PREP 讲 3 分钟并录音。数「停顿 > 2 秒」+「重复修正」次数，**卡顿点 ≤ 4 达标**。计数示例（沿用卡顿点法）：

> I think documentation is important.（2.5 秒——**计 1 点**）because, because（重复修正——**计 1 点**）it saves us a lot of time. ...

共 2 点，达标。注意：正常想词间隙（< 2 秒）不计入。

## 六、配套练习与自测题 {#exercises}

### 练习 1：影子跟读同步率计数 {#exercise-1}

取下面 10 意群材料做一次影子跟读并录音，然后逐群对比，判断每个意群是否同步，计算同步率。

```text
① We received a new trouble ticket this morning. /  ② The severity was high, /  ③ so the team started working on it right away. /  ④ We looked at the logs /  ⑤ and found the root cause. /  ⑥ It was a configuration error /  ⑦ on the core network element. /  ⑧ We applied a temporary workaround /  ⑨ and the network is stable now. /  ⑩ A permanent patch will go live next week.
```

- 同步的意群数：____ / 10
- 同步率 = ____%（≥ 80% 达标）

### 参考答案与解析 {#answer-key}

**练习 1**：以你的实际录音为准。10 意群中同步 ≥ 8 个即达标（≥ 80%）。示例对照法见[2.2 同步率怎么数](#sync-rate)——只要某个意群出现漏词、错词或节奏错位中的任意一种，就判该意群不同步。

**练习 2**（示例答案）：

| 要素 | 复述示例 |
| --- | --- |
| 时间 When | last night around 9 p.m. |
| 地点 Where | on NE45 / the monitoring system |
| 人物 Who | the on-call engineer |
| 发生了什么 What | high CPU usage, a log file filled the disk |
| 结果 How it ended | cleared the log, added rotation rule, back to normal |

**练习 3**（示例提纲，以话题 1「文档重要性」为例）：

```text
P（观点）：Documentation is essential for software maintenance.
R（理由）：Because it saves time and reduces mistakes when handing over work.
E（例子）：Last week I found a config issue; the ticket notes helped me fix it in 20 minutes.
P（重申）：So I believe keeping good documentation is worth the effort.
```

**练习 4**：

1. B（不暂停、连续、滞后 0.5～1 秒跟读）
2. B（0.5～1 秒）
3. B（漏一个 s 属于漏/错词，该意群判不同步）
4. B（五要素是时间/地点/人物/发生了什么/结果，不含价格）
5. B（E = Example）
6. B（2 秒）
7. B（第 2 周起每 2 周 1 次，必做）
8. 错（影子跟读不看文本，凭听跟随）
9. 对（争取时间话术是合理技巧）
10. 错（四问涵盖卡顿、语法、词汇、节奏四方面）
11. 改错：
    - a. find → **found**（时态）
    - b. ticket → **tickets**（单复数）
    - c. depend of → depend **on**（介词）
    - d. worked → **have worked**（时态）
