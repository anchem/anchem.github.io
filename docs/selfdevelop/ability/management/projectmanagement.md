# 项目管理

项目管理解决的问题是：**在一件事有截止期、有资源上限、还要有明确结果的前提下，把它交付出来**。它不是管理者的专属技能，一个人给自己做一件事，同样需要它。

## 概念

### 动机

- 大多数“做不完”不是能力问题，是从来没有定义过什么叫“做完了”。
- 一件事只要同时具备三个特征，就该按项目管理来做：**有截止期、有别人在用、做完要能被验收。**
- 个人项目和团队项目最大的区别不在规模，在于你有没有权力要求别人配合。这个区别决定了方法要减掉什么。

### 范围

- 项目管理解决的问题是：**怎么把一件有约束的事交付出去。**
- 它不解决的问题：这件事**要不要**做，那是[目标管理](./targetmanagement.md)的范围；做这件事的精力从哪来，那是[精力管理](./energymanagement.md)的范围。

### 三重约束

任何项目都同时受三样东西约束，动一样必然牵动另一样：

| 约束 | 一句话 | 动它的代价 |
| --- | --- | --- |
| 范围 | 要做成什么样 | 范围一大，时间和成本立刻绷紧 |
| 时间 | 什么时候要 | 时间压缩，范围或质量必然让位 |
| 成本 | 投入多少人力物力 | 成本砍下去，交付的不确定性上升 |

质量不是第四个约束，它是前三者平衡的结果。**谈“既要又要还要”时，缺的从来不是决心，是取舍。**

## 原则

### 原则一：先定义“完成”，再动手

开工前必须能用一句话说清“什么情况算做完，什么情况算没做完”。说不清的，都不是项目，是愿望。验收标准应当写在最前面，因为它是唯一能在事后判断你到底有没有交付的东西。

### 原则二：砍范围，不砍质量

进度落后时的第一反应通常是加班，第二反应是降低质量。正确的第一反应是**砍范围**：把“必须做”和“最好有”分开，砍掉后者。降质量会让交付物失去被使用的价值，等于全部白做。

### 原则三：风险前移

最贵的风险是临收尾才暴露的那个。凡是不确定的事，尽量往前面挪：先做最没把握的部分，先找最难的那个人确认需求，先跑通最短的那条链路。**先做难的，后做顺的**，是个人项目管理里性价比最高的一条。

### 原则四：干系人比流程重要

再规范的流程，也救不了一个从头到尾没人验收的项目。开工前就想清楚：谁会用它的结果、谁会因为它的延迟受影响、谁有权力说“不行”。三个人以内，也要点得出名字。

### 原则五：计划是拿来改的，不是拿来遵守的

计划的作用不是预测未来，是让偏差**可见**。没有计划，你连自己偏了多少都不知道；有了计划却不肯改，就会把调整成本全部推给最后一周。

## 方法

### 第一步：写清交付物与验收标准

一句话说清交什么、交给谁、什么算不合格。参照[决策质量的六个要素](../decisionmaking/decisionquality.md)里对“问题定义”的要求：定义错了，后面每一步都在正确地做错事。

### 第二步：拆到能被估算为止

拆解的标准不是层级漂亮，而是**每一块的耗时你能估到半天以内**。估不出半天的，说明还没拆到底。拆解的过程本身就会暴露你其实不懂哪一块。

### 第三步：排出唯一的最短路径

标出哪几步必须在别人之前完成，把它们串成一条线。其余的都是可以并行或后置的。个人项目里最怕的不是任务多，是顺序错，顺序一错，一半工作在等另一半。

### 第四步：用看得见的方式盯进度

进度必须写在能被自己看见的地方，并且规定一个固定的复查节奏。每个节点的检查只问三件事：**做完了什么、卡在哪里、下一步是什么。** 三条答不出，等于没进度。

### 第五步：收尾与复盘

交付不是终点，复盘才是。只回答三个问题：实际和计划差在哪、差在哪个判断上、下一次要改哪一条。写在纸上的复盘才算数，脑子里过的很快会消失。

```txt
启动 -> 规划 -> 执行 -> 监控 -> 收尾
  ^                              |
  |______ 复盘结论回流到下一次____|
```

## 习惯

- 开工前先写下三条“不做什么”，比写下要做什么更能省事。
- 每次交付前留出一段只用来收尾的时间，收尾从来不是顺手就能完成的。
- 每周固定一次“要不要砍范围”的复查，不要等到最后一周才承认做不完。
- 借[AI 协作方法论](../ai/ai-collaboration-methodology.md)里的做法，把可逆的事交给工具先试，把不可逆的交付留在自己手里。

## 与相邻能力的关系

- 与[目标管理](./targetmanagement.md)：目标决定做哪个项目，项目决定目标怎么落地。目标管理关心方向对不对，项目管理关心这一步到没到。
- 与[精力管理](./energymanagement.md)：项目排期要按精力节奏来，不按日历格子来。
- 与[知识管理](./knowledgemanagement.md)：项目卡住的地方，就是知识体系缺的那块。
- 与[项目式学习](../../cognition/learning/projectbasedlearning.md)：同一套动作，用来学东西时它叫项目式学习，用来交付时它叫项目管理。
