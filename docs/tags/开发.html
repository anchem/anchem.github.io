API 设计

API 是系统的对外契约。它的生命周期远长于实现，一旦发布就难以修改——因此设计时应把「未来如何演进」作为首要约束。

HTTP

HTTP 是应用层最广泛使用的协议：请求 - 响应模型，无状态，以文本语义描述资源操作。

ICT 理论基础

这里收录支撑软件开发的基础原理。它们很少被直接调用，却决定了技术判断力的上限。

Java

Java 是服务端应用最广泛的语言之一：强类型、跨平台、生态成熟，且提供了完整的并发与内存管理基础设施。它的工程实践高度依赖对运行时机制的理解。

Linux

Linux 是服务端事实上的标准运行环境。理解它的几个核心机制，是排查线上问题的基本功。

Linux 安全

Linux 安全的核心是权限模型 + 隔离机制 + 审计能力三者的组合。

TCP/IP

TCP/IP 是互联网的通信基础：IP 负责把数据包送到目标地址，TCP 在此之上提供可靠、有序的字节流。

一致性

这里的一致性指多副本之间的数据一致，与数据库事务中的 ACID 一致性不是同一个概念。

事务

事务把多个操作捆绑成一个不可分割的逻辑单元，是并发环境下保证数据正确的核心机制。

云原生

云原生不是一组具体技术，而是假设环境不可靠、变化频繁而设计应用的一套方法。

云计算

云计算的本质是把计算资源变成可按需取用的服务，让组织从「拥有基础设施」转变为「消费基础设施」。

人工智能

人工智能在本站语境下不是研究课题，而是一种需要被正确集成与约束的系统组件。工程师需要理解它能做什么、不能做什么、成本在哪里。

代码坏味道

坏味道是结构问题的信号，不是错误。它提示「这里可能值得调整」，但是否重构仍需结合成本与收益判断。

代码审查

代码审查同时实现两个目标：发现缺陷与传播知识。后者常被忽略，却对团队长期能力影响更大。

共识

共识是让多个节点对某个值达成一致的算法。它是分布式系统中最基础也最困难的问题之一：在节点可能崩溃、网络可能分区的条件下，仍要保证一致性。

关系模型

关系数据库以表为基本单位，用集合论与一阶逻辑作为理论基础，通过 SQL 声明式地表达查询。

内存管理

内存管理提供了虚拟内存这一抽象：每个进程都以为自己独占一片连续地址空间，而实际物理内存由内核统一调度。

分布式及并行开发

分布式的价值是突破单机上限：更高的吞吐、更大的容量、更强的容错。代价是引入了单机编程中不存在的根本难题。

创建型模式

创建型模式处理对象如何被创建，目标是把「创建什么」与「怎么创建」解耦。

单元测试

单元测试验证最小的可测试单元（通常是一个函数或类）的行为。它的价值在于快速反馈与精确定位。

复杂度分析

复杂度是衡量算法代价的共同语言，它让方案比较在写代码之前就能进行。

大数据

大数据的核心问题是：当数据量或写入速率超出单机能力时，如何组织计算与存储。它不是一个技术栈，而是一组权衡。

大语言模型

大语言模型（LLM）以自回归生成的方式工作：根据已有文本预测下一个词元，逐字生成完整回答。理解这一点，就能推出它的大部分能力边界。

威胁建模

威胁建模是一个结构化的问题：这个系统会被怎么攻击，我们如何应对。

存储引擎

存储引擎决定数据在磁盘上如何组织、如何被读取与写入。同一套 SQL 在不同引擎上的性能特性可能完全不同。

安全基础

安全基础提供判断安全方案是否成立所需的密码学常识与漏洞类别认知。

安全编码

安全编码把安全设计落实为具体的代码约束。它的核心是在正确的边界处理正确的输入。

安全设计

安全设计在动手写代码之前识别并消解威胁。设计阶段消除一个威胁的成本，远低于上线后修补。

容器技术

容器把应用及其依赖环境打包成一个整体，解决了「本地能跑、换台机器就报错」的根本问题。它是云原生交付方式的基础。

容器编排

编排系统管理多节点上的大量容器：调度、扩缩、升级、自愈与网络。它的核心思想是声明式收敛。

容器运行时

运行时负责创建并管理容器的生命周期：准备文件系统、建立隔离、限制资源、启动进程、回收资源。

容器镜像

镜像是一个只读的、分层的、内容可寻址的文件系统快照，也是容器运行时的起点。

密码学应用基础

工程中使用密码学的目标不是「发明方案」，而是正确地使用成熟原语。

常见漏洞类别

安全漏洞的成因高度集中。理解这几类根因，比记住漏洞清单更有价值。

并发与并行

并发是同时处理多个任务的能力，并行是同时执行多个任务。前者是结构问题，后者是资源问题。

并发编程

Java 的并发能力建立在内存模型之上。不理解内存模型，同步代码就只能是「照着抄」。

开发：怎么做

开发把需求变成真实可运行的系统。它回答的是：用什么原理支撑、用什么结构承载、用什么手段实现与验证。

开发方法论

方法论是组织工作的框架。它的价值不在于被完整执行，而在于提供一套共同语言，让团队能讨论和调整自己的过程。

开发生命周期

生命周期描述软件从构思到退役的完整过程。没有一种模型是通用的，选择取决于需求变化的频率与交付风险。

开发者测试

开发者测试指由代码作者编写并长期维护的自动化测试。它与独立测试团队的工作互补：前者保证实现正确与可持续修改，后者关注整体质量与用户视角。

批处理

批处理对一批已经落地的数据做全量或增量计算，特点是高吞吐、可重算、延迟较高。

持续集成与交付

持续集成（CI）让每次变更都自动验证；持续交付（CD）让每次通过验证的变更都能自动部署。二者共同把发布从事件变成常态。

操作系统

操作系统是程序真实运行的环境。很多「莫名其妙」的问题——进程被杀、内存涨、文件描述符耗尽、延迟抖动——答案都在这一层。

数学基础

数学在软件开发中的作用不是「算出答案」，而是提供精确描述问题的语言。当一个问题能被数学地表述，它的难度、边界和解法空间往往同时变得清晰。

数据库及存储

数据库解决的是数据的持久化、并发访问与高效检索。它的设计决策比其他环节更难撤回——表结构一旦承载数据，改动成本就随数据量增长。

数据结构

数据结构是数据的组织形状，它决定了哪些操作便宜、哪些操作昂贵。

文件系统

文件系统把块设备抽象成目录与文件，并为上层提供统一的读写接口。理解它的 IO 特性，是排查性能问题的必要前提。

文档

文档的目的是降低理解成本。判断一份文档是否有价值，只需问一句：它让谁少花了多少时间。

服务模型

服务模型的区别在于责任边界：谁管理什么。选择模型就是选择把哪部分复杂度留给自己。

机器学习基础

机器学习用数据拟合规律，替代人工编写规则。它的适用前提是：规律存在、数据可获取、且允许一定错误率。

架构风格

架构风格是组织组件的常见形态。选择风格就是选择把复杂度放在哪里。

汇编与机器模型

汇编是机器指令的可读形式。理解它不是为了写汇编，而是为了理解程序的真实执行成本。

汇编及编译原理

这一学科回答：我写的代码最终变成了什么。它决定了性能分析的下限与语言语义的边界。

流处理

流处理对持续到达的数据做增量计算，核心挑战不是吞吐，而是时间与状态的语义。

测试替身

测试替身（test double）用来替代真实依赖，使测试能够隔离、快速、可重复地运行。

测试防护网

重构的定义是「不改变外在行为」。要在修改结构的同时确认行为未变，唯一可行的办法是自动化测试。

测试驱动开发

测试驱动开发（TDD）的核心主张是：先写测试，再写实现。它的主要收益不在测试本身，而在它迫使设计在编码前被想清楚。

演进式架构

演进式架构的核心主张是：不要试图一次设计到位，而是把「支持变化」这件事本身设计进去。

版本管理

版本管理是所有协作的基础设施：它记录谁在什么时候因为什么改了什么。它不只是工具，还是团队协作方式的直接体现。

离散数学

离散数学研究离散结构：集合、关系、图、逻辑、组合。计算机处理的正是离散对象，因此它是计算理论的地基。

算法与数据结构

这一学科回答三个问题：数据怎么组织、问题怎么求解、代价怎么衡量。三者是一个整体——脱离代价谈算法没有意义。

算法范式

范式是求解问题的思路模板。识别出问题属于哪种范式，往往直接给出可行方向。

系统分析与设计

系统分析与设计是从问题域走向解空间的过程：先弄清系统要做什么，再决定它由什么构成。

线性代数与概率统计

这两块是数据与不确定性的语言，在人工智能、性能建模与实验分析中不可替代。

结构型模式

结构型模式处理对象如何组合成更大的结构，核心手段是「在调用链中间插入一层」。

编程语言

语言是表达设计的工具。语言提供的抽象能力，直接决定了什么样的设计能够被自然地表达。

编译构建

构建把源码转换为可交付的产物。它看似只是工具链问题，实则直接影响交付的一致性与可复现性。

编译过程

编译把源码翻译为目标代码，其价值是把问题逐步转换到更容易分析与优化的形态。

网络安全

网络安全要解决的是：在不可信的信道上建立可信的通信。默认假设应当是——所有经过网络的数据都可能被窃听、篡改或重放。

行为型模式

行为型模式处理对象之间的职责分配与通信方式，是数量最多、使用最广的一类。

计算机网络

网络的本质是在不可靠的介质上构建可靠的通信。这个前提决定了几乎所有的网络现象：重传、超时、乱序、延迟抖动。

设计原则

设计原则是对「什么样的结构更容易修改」的经验总结。它们不是定律，而是权衡的提示。

设计模式

设计模式是针对重复出现的设计问题的命名方案。它的首要价值不是提供代码模板，而是提供共同词汇——说「这里用策略模式」比描述三遍结构要快得多。

调试技术

调试是从现象回溯到原因的过程。它的效率差异极大：有人几分钟定位，有人几天无果，区别在于方法而非运气。

质量保障

质量保障（QA）关注的是质量如何被系统性地保证，而不仅是「测出多少缺陷」。

质量属性

质量属性是架构设计的输入与验收标准。没有明确的质量属性，架构讨论就只能停留在「看起来是否优雅」这种无法判定的层面。

软件安全

安全与其他质量属性最大的区别是：存在主动的、会持续尝试的对手。因此安全不能被当作上线前的加固环节，而必须贯穿架构、设计与实现。

软件实现

实现是设计落地的过程。它不只是「把逻辑写成代码」，还包括让代码在团队中可持续演进：可构建、可审查、可重构。

软件工程

软件工程要解决的是规模问题：当参与者从一人变成多人、寿命从一周变成数年，靠个人技艺无法维持质量。工程化管理的是过程与协作。

软件开发

软件开发把原理转化为可运行、可维护的系统。这里的六个模块构成一条从约束到细节的链条。

软件架构

架构是难以撤回的设计决策。它决定了系统的骨架：由哪些部分组成、边界划在哪里、各部分如何交互。架构的目标不是「正确」，而是在给定的质量属性约束下做出可接受的取舍。

软件设计

设计关注模块内部的结构：如何组织代码、如何划分职责、如何定义接口。它的目标是让代码在持续修改中保持可控。

软件验证

验证回答一个问题：我们凭什么相信这个系统是对的。没有验证的交付，本质上是在把风险转嫁给用户。

进程与线程

进程是资源分配与隔离的单位，线程是调度的单位。区分这两件事，是理解并发问题的起点。

配置管理

配置管理保证同一份构建产物可以在不同环境中以不同参数运行，同时保证敏感信息不泄露。

重构

简单说，重构就是在不改变代码外在行为的前提下，对代码进行修改，以改进程序的内部结构，比如获得更好的可读性、可维护性、可扩展性等。

重构工具

工具能显著降低重构的成本与风险。用工具做机械性改动，把人的精力留给判断性工作。

重构手法

重构手法是小步、可验证、行为不变的结构调整。掌握手法比掌握坏味道更重要——识别问题只是第一步，能安全地改才是关键。

集合框架

集合是日常使用频率最高的部分。选错集合带来的性能影响，往往比算法选择更大。

非关系型数据库

NoSQL 不是一个技术，而是一组针对特定数据模型与规模需求的选择。它的价值在于用放弃某些能力，换取另一些能力。

面向对象分析与设计

面向对象的核心是用对象封装状态与行为，并通过多态让变化点可替换。它的价值在于管理复杂度，代价是抽象不当时产生的间接性。

领域驱动设计

领域驱动设计（DDD）主张用业务领域的结构决定软件的结构。它的核心价值不是模式集合，而是建立业务与技术共用的统一语言。
